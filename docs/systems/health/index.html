Health

The server is the single source of truth for every player's health value. HealthManager maintains an internal record, drives regen on RunService.Heartbeat, mirrors values to the Roblox Humanoid, and broadcasts to the owning client via HealthStateSync. The client forwards that packet to a signal consumed by the HUD.

Data flow​

Server (HealthManager)                     Client (HealthController)
──────────────────────────────────────────────────────────────────────
PlayerAdded → create HealthRecord{
  Health = MaxHealth,
  LastDamageTime = 0,
  LastSyncTime = 0,
  LastSyncedHealth = MaxHealth
}

CharacterAdded → reset Health to MaxHealth
  humanoid.MaxHealth = HealthConfig.MaxHealth
  humanoid.Health = record.Health
  ──── HealthStateSync:FireClient(player, health) ──────►
                                                         Packets.HealthStateSync
                                                         .OnClientEvent →
                                                         Signals.OnHealthValueChanged
                                                         :Fire(health)
                                                           │
                                                           ▼
                                                         HealthStaminaGuiController
                                                         (drives health bar)

RunService.Heartbeat (server):
  if regen eligible (alive, not full, past RegenDelay):
    record.Health += HealthRegen * dt
    humanoid.Health = record.Health
    if periodicSync (0.1 s) or full:
      ──── HealthStateSync:FireClient ─────────────────►

HealthManager.ApplyDamage:
  validate AttackType / AOEVariant
  clamp amount to [0, MaxHealth]
  amount *= (1 - clamp(ArmorBaseReduction * (1 + ArmorEfficiency), 0, 0.75))   -- crafted armor x Armor perk
  record.Health -= amount
  record.LastDamageTime = os.clock()
  humanoid.Health = record.Health
  ──── HealthStateSync:FireClient ─────────────────────►

HealthManager.HealPlayer:
  record.Health = min(MaxHealth, record.Health + amount)
  humanoid.Health = record.Health
  ──── HealthStateSync:FireClient ─────────────────────►

Client / Server / Shared​

Client (HealthController.client.luau) Minimal bridge: listens to Packets.HealthStateSync.OnClientEvent and re-fires Signals.OnHealthValueChanged with the received health value. It owns no state. HealthStaminaGuiController (not part of this system) consumes OnHealthValueChanged to animate the HUD bar.

Server (HealthManager.luau) Bootstrapped by HealthSystemLoader.server.luau via HealthManager.Initialize(). Maintains a HealthRecord per player (Health, LastDamageTime, LastSyncTime, LastSyncedHealth). The regen heartbeat is capped at MAX_HEALTH_STEP_DT = 0.1 seconds per step to prevent delta-time spikes from applying burst healing. Syncs are batched: regen fires HealthStateSync at most every HEALTH_SYNC_INTERVAL = 0.1 seconds, or immediately when health reaches full. On PlayerRemoving the record is deleted; no stale data persists across sessions.

Shared (HealthConfig.luau) Three fields read by both HealthManager (server logic) and indirectly by HealthController/GUI (via the synced value): MaxHealth, HealthRegen, RegenDelay. RegenEnabled is a kill-switch for the entire regen loop.

Key files​

  • src/StarterPlayer/StarterPlayerScripts/HealthController.client.luau — HealthStateSync → OnHealthValueChanged bridge
  • src/ServerStorage/SharedModules/HealthManager.luau — authoritative health record, regen heartbeat, ApplyDamage, HealPlayer, HealthStateSync dispatch
  • src/ReplicatedStorage/SharedModules/Configs/HealthConfig.luau — MaxHealth, regen rate/delay, regen kill-switch

Config knobs​

FieldDefaultEffect

Gotchas​

Non-CombatService damage bypasses HealthManager

HealthManager.ApplyDamage is now called by CombatService (which WeaponServer and NpcCollisionService route through). However, any damage source that writes directly to Humanoid.Health — such as default Roblox fall damage or unrouted hazards — will bypass HealthManager's internal record, causing the HUD to show a stale value and skipping armor mitigation. Before shipping such a source, either disable it or listen to Humanoid.HealthChanged and reconcile the record (see audit note H3 in the source).

One-way mirror: HealthManager writes record.Health → humanoid.Health but never reads back from the Humanoid. Any external write to humanoid.Health is invisible to the manager until a HealthStateSync event corrects the client. Keep all health mutations going through HealthManager.ApplyDamage or HealthManager.HealPlayer.

Armor mitigation: applyDamageInternal combines crafted armor with the Armor perk as the final scale on amount before health is subtracted. It reads ArmorState/<UserId>.ArmorBaseReduction (written by ArmorManager from the player's tier) and PerkBuffs/<UserId>.ArmorEfficiency (the Armor perk), computing reduction = clamp(ArmorBaseReduction * (1 + ArmorEfficiency), 0, ArmorConfig.MaxReductionCap). Both are read per hit, so crafting a tier or allocating/respeccing the perk takes effect on the next damage event; with no armor the perk does nothing. Coverage is bounded by the chokepoint — damage that bypasses HealthManager.ApplyDamage also bypasses armor. See Perks for the cap rationale and the attacker-bonus-then-armor multiplication order.

Character respawn resets health: CharacterAdded unconditionally resets record.Health to MaxHealth. If a partial-health respawn mechanic is ever needed, this reset must be conditional.

Sync rate: HealthStateSync is sent at most every 0.1 seconds during regen. For combat situations where granular damage feedback matters, callers to ApplyDamage should be aware that each call forces an immediate sync — avoid calling it in tight per-frame loops.
