Junk

The junk system spawns debris that floats past the train for players to collect with the GrabHook. The server owns spawning, weighted selection, and collection validation; the client renders junk with pooled instances and drives the movement simulation locally using a shared speed value.

Data flow​

JunkService (server) — spawn loop
  • selectRandomJunk() — weighted tier + pity type selection
  • assigns id (U16), records SpawnOdometer + SpawnPos
  • SpawnJunk:Fire(id, modelName, startPos) ──────────────────────────► JunkController (client)
                                                                          • pools[poolName]:RetrieveObject(startPos)
                                                                          • adds to activeJunks + junkMap

SetJunkSpeed:Fire(targetSpeed) ─────────────────────────────────────► JunkController (client)
  (on train state change or player join)                                 • first receipt: snap currentSpeed
                                                                          • subsequent: start smoothstep ramp

  ┌── Shared speed ramp (same smoothstep on both sides) ──────────────────────────────┐
  │  JunkService Heartbeat: junkOdometer += currentSpeed * dt                         │
  │  JunkController PreSimulation: advance each junk's DistanceTraveled               │
  │  Despawn when (junkOdometer - SpawnOdometer) > DESPAWN_DISTANCE (server)          │
  │           when DistanceTraveled > DESPAWN_DISTANCE (client)                       │
  └───────────────────────────────────────────────────────────────────────────────────┘

Player fires GrabHook → Signals.TryClaimJunk:Fire(id, hitPos)
  • JunkController → Packets.ReqJunkClaim:Fire(id, hitPos) ──────────► JunkService
                                                                          • proximity check vs junkOdometer
                                                                          • cooldown check
                                                                          • reserves junk for player
                                                                          • BeginJunkRetract:Fire(id, hitPos, retractTime, player)
  ◄── BeginJunkRetract ───────────────────────────────────────────────
  • remove from activeJunks; move to retractingJunks
  • if localPlayer: GrabHookVisuals.AnimateProjectile drives movement
  • if other player: observer lerp on RenderStepped

Player fires Signals.TryFinalizeJunk:Fire(id)
  • JunkController → Packets.ReqJunkFinalize:Fire(id) ───────────────► JunkService
                                                                          • verifies reservation + timeout
                                                                          • marks Collected, awards Tool to Backpack
                                                                          • JunkCollected:Fire(id, player) → all clients
  ◄── JunkCollected ──────────────────────────────────────────────────
  • pool:InsertObject (returns model)

Client / Server / Shared​

Client (JunkController.client.luau)

  • Builds per-model GenericPoolInstance pools at startup, one per model name found in JunkAssets, with initial size 5, max 60, expand by 10.
  • On SpawnJunk: checks MAX_CLIENT_JUNKS = 250 cap, retrieves model from pool, sets Transparency = 0, parents to workspace/JunksVisuals, records in activeJunks and junkMap.
  • PreSimulation loop: advances the smoothstep speed ramp, moves each active junk by currentSpeed * dt along MOVE_DIRECTION, applies per-junk random rotation, increments DistanceTraveled. Despawns via RemoveJunkLocal when DistanceTraveled > DESPAWN_DISTANCE.
  • On BeginJunkRetract: removes the junk from simulation, moves it to retractingJunks. The local player's animation is driven by GrabHookVisuals.AnimateProjectile; other players see an observer lerp on RenderStepped. An 8-second safety-net timeout returns the model to the pool if JunkCollected never arrives.
  • On JunkCollected: cleans up rope attachments and beams on the model, returns it to the pool.
  • Bridges claim/finalize signals from GrabHook.client to Packets.ReqJunkClaim / Packets.ReqJunkFinalize via Signals.TryClaimJunk and Signals.TryFinalizeJunk.
  • Exposes GetJunkIdFromPart(part) via BindableCore so GrabHook.client can resolve a junk ID from a raycast hit part.

Server (JunkService.server.luau)

  • Weighted tier selection: each tier's weight is multiplied by GlobalModifiers.TierMultipliers[tier]; a random number selects the tier by accumulated weight.
  • Type selection with pity: if spawnsSinceLastEnergy >= ENERGY_PITY_THRESHOLD (8), an Energy type junk is forced; otherwise weighted by SpawnChance * TypeMultiplier. The pity counter resets on every Energy spawn.
  • Records SpawnOdometer (value of junkOdometer at spawn time) and SpawnPos for each active junk. The junk's current world position is reconstructed on claim as SpawnPos + MOVE_DIRECTION * (junkOdometer - SpawnOdometer).
  • Distance-based despawn on Heartbeat: removes any junk where (junkOdometer - SpawnOdometer) > DESPAWN_DISTANCE. This mirrors the client-side DistanceTraveled check.
  • Claim validation (ReqJunkClaim): reconstructs junk world position, checks distance against GrabHookConfig.Physics.MaxDistance + 15 studs (latency slack), enforces per-player cooldown, reserves junk, computes retract time, and fires BeginJunkRetract to all clients.
  • Finalize validation (ReqJunkFinalize): checks reservation ownership and 5-second timeout, marks collected, fires JunkCollected to all clients, and gives the tool to the player's Backpack.
  • SetTrainState(isMoving) and SetTrainStarted(started) are wired to Signals.SetTrainState and Signals.SetTrainStarted for external control.
  • Junk counter wraps at 65535 (U16 boundary) to keep IDs compact in the SpawnJunk packet.

Shared (SpawnHelper.luau)

  • SpawnHelper:Init() caches all BasePart children of workspace/SpawnVolumes weighted by volume.
  • SpawnHelper.GetRandomPoint() picks a random world position inside one of the spawn volumes using volume-weighted selection.

Key files​

  • src/StarterPlayer/StarterPlayerScripts/JunkController.client.luau — client rendering: pool management, movement loop, retract animation, collection cleanup
  • src/ServerScriptService/JunkService.server.luau — server authority: weighted spawn loop, pity system, odometer, claim/finalize handshake
  • src/ReplicatedStorage/SharedModules/SpawnHelper.luau — volume-weighted random spawn position helper
  • src/ReplicatedStorage/SharedModules/GenericPoolInstance.luau — instance pool used for junk visuals (vendored; RetrieveObject / InsertObject)
  • src/ReplicatedStorage/SharedModules/Configs/JunkConfig.luau — all tuning: spawn rates, speeds, tier weights, type chances, despawn distance

Config knobs​

FieldDefaultEffect
MAX_SERVER_JUNKS200Hard cap on server-side active junk entries
MAX_CLIENT_JUNKS250Client silently drops SpawnJunk events beyond this count
MOVE_DIRECTIONVector3.new(1,0,0)World direction all junk travels
DESPAWN_DISTANCE700 studsOdometer delta at which junk is removed (both sides)
DEFAULT_SPAWN_RATE0.5 sSeconds between junk spawns when train is moving
STOPPED_SPAWN_RATE1.5 sSeconds between spawns when train is stopped
DEFAULT_JUNK_SPEED10 studs/sJunk movement speed when train is moving
STOPPED_JUNK_SPEED5 studs/sJunk movement speed when train is stopped
SPEED_RAMP_DURATION1.5 sSmoothstep ramp time on speed change
ENERGY_PITY_THRESHOLD8Non-energy spawns before Energy is guaranteed
BaseModifiers.GlobalSpawnRateMult1.0Global spawn rate multiplier (runtime-adjustable)

Tiers[n].Types[t].SpawnChancevariesRelative spawn chance for each type within a tier

Gotchas​

Both sides integrate the same ramp — keep them in sync

The server (junkOdometer) and client (DistanceTraveled) both use the identical smoothstep ramp over SPEED_RAMP_DURATION. If you change the ramp formula in one place, change it in the other. Drift causes the server's proximity check to reject valid claims.

Reservation timeout is 5 seconds

If a client claims junk but never finalizes (e.g. disconnects mid-retract), the reservation expires after 5 seconds (RESERVATION_TIMEOUT). Another player can then claim the same junk. The client has an 8-second safety net (RETRACT_RECLAIM_TIMEOUT) that returns the model to the pool if JunkCollected never arrives — this value must exceed RESERVATION_TIMEOUT plus round-trip time.

  • Pool cleanup is mandatory. Every path that removes a junk from activeJunks or retractingJunks must call CleanupJunkModel then pool:InsertObject. Skipping cleanup leaks HookAttachment or Beam instances on the model, which will appear on the next retrieval.
  • workspace/JunksVisuals folder must exist. JunkController uses WaitForChild to find it; the folder should be created in the place file or by a server startup script.
  • Junk ID wraps at 65535. This is intentional for the NumberU16 wire type in SpawnJunk. Long-running servers are safe because entries are removed before the counter can collide.
  • Tier 5 weight is 0. Items in Tier 5 will never spawn under default config. Set the weight above 0 to enable them.
  • SpawnHelper:Init() must be called before the spawn loop. JunkService calls it at startup; if no SpawnVolumes parts exist in workspace, GetRandomPoint will always return nil and no junk will spawn.
