Sound

A layered client audio system built around a single facade module. All game audio — one-shot SFX, positional SFX, looped sounds, background music, and ambience beds — flows through SoundManager. No other script creates Sound instances directly.

Data flow​

Client code calls SoundManager.PlaySFX / PlaySFXAt / PlayLooped / PlayMusic / SetAmbience
  └─> SoundManager facade delegates to the appropriate submodule
        ├─ SFX.Play        -> creates transient Sound in SoundService (2D one-shot)
        ├─ SFX.PlayAt      -> Pool.Acquire(position) -> pooled part+Sound in workspace
        │     (Replicate=true) -> Packets.ReplicateSoundAtLocation:Fire -> server relay
        ├─ SFX.PlayLooped  -> long-lived Sound in SoundService + LoopHandle returned
        ├─ Music.Play      -> playlist shuffle with crossfade (MotionMaster volume fades)
        └─ Ambience.Set    -> 2D bed Sounds in SoundService (MotionMaster fade in/out)

Packets.ReplicateSoundAtLocation (client -> server -> other clients)
  └─> ReplicatedSoundService validates against ALLOWED_SOUND_IDS allowlist
        └─> FireClient to all players except sender
              └─> SFX.ConnectReplication handler -> Pool.Acquire positional playback

SoundGroup bus hierarchy (Groups submodule):
  SoundService
    └─ Master SoundGroup
          ├─ SFX SoundGroup
          ├─ BGM SoundGroup
          └─ Ambience SoundGroup

Client / Server / Shared​

Client — SoundManager (facade + submodules)

SoundController.client.luau calls SoundManager.Init() once at startup. Init creates the SoundGroup bus hierarchy (via Groups.Ensure), warms the positional sound pool (via Pool.Ensure and per-asset pre-warm), connects the replication receiver (SFX.ConnectReplication), preloads all configured asset IDs via ContentProvider:PreloadAsync, and autostarts any ambience beds listed in SoundConfig.Ambience.Autostart.

After Init, any client script or tool may require(SharedModules.SoundManager) and call the facade. The submodules (Groups, Pool, SFX, Music, Ambience) are internal and should not be required directly.

Server — ReplicatedSoundService.server.luau

Listens on Packets.ReplicateSoundAtLocation.OnServerEvent. The server does not play audio itself — it acts only as a validated relay:

  1. Per-player rate limit (MIN_INTERVAL = 0.05 s) rejects bursts.
  2. Payload shape is validated (data.SoundConfig.Id must be a string).
  3. The sound ID must be in ALLOWED_SOUND_IDS, which is built at startup from SoundConfig.GetReplicatedIds() — any SFX entry with Replicate = true is automatically included.
  4. Passes the original payload to all other connected players via FireClient.

Key files​

  • src/ReplicatedStorage/SharedModules/SoundManager/init.luau — public facade; the only module other scripts should require
  • src/ReplicatedStorage/SharedModules/SoundManager/Groups.luau — creates and manages the Master → SFX / BGM / Ambience SoundGroup hierarchy under SoundService
  • src/ReplicatedStorage/SharedModules/SoundManager/Pool.luau — per-asset pool of BasePart + Sound pairs used by PlaySFXAt for positional audio
  • src/ReplicatedStorage/SharedModules/SoundManager/SFX.luau — Play (2D), PlayAt (positional pooled), PlayLooped (looped handle), and replication receiver
  • src/ReplicatedStorage/SharedModules/SoundManager/Music.luau — playlist manager with shuffle, gap, and crossfade
  • src/ReplicatedStorage/SharedModules/SoundManager/Ambience.luau — global 2D ambience bed management with MotionMaster fade
  • src/StarterPlayer/StarterPlayerScripts/SoundController.client.luau — thin bootstrap; calls SoundManager.Init() once
  • src/ServerScriptService/ReplicatedSoundService.server.luau — server relay with allowlist and rate-limit validation
  • src/ReplicatedStorage/SharedModules/Configs/SoundConfig.luau — single source of truth for all asset IDs, volumes, pitch ranges, pool sizes, bus volumes, playlists, and ambience beds

Config knobs​

Everything audio lives in src/ReplicatedStorage/SharedModules/Configs/SoundConfig.luau.

Bus volumes (SoundConfig.GroupVolumes):

BusDefault
Master1.0
SFX1.0
BGM0.6
Ambience0.5

Per-SFX definition fields (SoundConfig.Sfx):

FieldDescription
IdRoblox asset ID string; empty string disables the entry
VolumeDefault playback volume (0–1)
PitchFixed pitch multiplier
PitchRangeTwo-element array {min, max}; randomises pitch per play
GroupBus name ("SFX", "BGM", "Ambience"); defaults to "SFX"
Replicatetrue to include in the server relay allowlist
DebounceMinimum seconds between plays of this entry (anti-spam)
PoolInitialPre-allocated pool slots warmed at Init (positional only)
PoolMaxHard cap on the per-asset pool size (positional only)

Adding a new replicable SFX: add the entry to SoundConfig.Sfx with Replicate = true. SoundConfig.GetReplicatedIds() and ReplicatedSoundService pick it up automatically on next server start — no changes needed in the server script.

Gotchas​

Never create ad-hoc Sound instances

All Sound creation must go through SoundManager. Creating Sound instances by hand bypasses the bus groups (so volume controls have no effect), skips the positional pool (causing memory churn), and may produce sounds that persist across character reloads without a cleanup path.

  • SoundManager.Init() must be called before any Play* call. It is called once by SoundController.client.luau; do not call it again from other scripts.
  • PlaySFXAt is positional — it parents a pooled BasePart at the given Vector3 in the workspace. The pool releases the part after sound.TimeLength + 0.05 seconds. Do not hold references to the part or sound after the call.
  • PlayLooped returns a LoopHandle. The caller is responsible for calling handle:Stop() or handle:Destroy() when the sound is no longer needed. Abandoning a handle leaks a live Sound instance under SoundService.
  • A sound entry with Replicate = true and an empty Id string ("") is excluded from the allowlist automatically by GetReplicatedIds(). The pool warm step also skips empty IDs. Fill in the asset ID when the sound is ready — no further config changes are required.
  • The BGM and Ambience buses default to volumes below 1.0. SFX entries authored at Volume = 0.5 will be audibly louder than music at the same numeric volume because the bus multipliers differ.
