Systems

📄️Placement

The placement system lets players preview and place items in designated build areas, using a shared validation module that runs identically on the client (preview) and server (authority).

📄️Stamina & Sprint

Sprint is client-predicted for responsive feel and server-authoritative for integrity. The server runs the canonical stamina simulation and pushes syncs at up to 10 Hz; the client uses each sync to gate visual and audio effects.

📄️Junk

The junk system spawns debris that floats past the train for players to collect with the GrabHook. The server owns spawning, weighted selection, and collection validation; the client renders junk with pooled instances and drives the movement simulation locally using a shared speed value.

📄️GrabHook

The GrabHook is a player tool that fires a tethered hook to collect floating junk. The client owns all raycasting and rope visuals; the server validates the claim and awards the item.

📄️Shredder

Players hold a ProximityPrompt on a placed Workbench to convert non-Energy junk Tools into crafting material Tools via a two-step server handshake; ejected materials land in the world with a bezier arc and hover until picked up or auto-collected.

📄️Health

The server is the single source of truth for every player's health value. HealthManager maintains an internal record, drives regen on RunService.Heartbeat, mirrors values to the Roblox Humanoid, and broadcasts to the owning client via HealthStateSync. The client forwards that packet to a signal consumed by the HUD.

📄️Train Fuel

A single global fuel value (0–100) governs the train's state for all players. The server computes fuel algebraically from the last event rather than polling each frame; every state transition snapshots the current fuel, switches the drain rate, and schedules the next deterministic transition via a nonce-guarded task.delay. Clients receive a snapshot and predict the bar locally.

📄️Proximity Pickup

Dropped craft-material Tools and shredder-ejected material handles register with a server pickup system; any player who walks into the detection sphere claims the item. Unclaimed items auto-collect to the owner after a configurable delay. The client plays a hover/spin effect on unclaimed items and a float-to-hand animation on claim.

📄️Train Shield

A single global shield pool governs the train's structural integrity for all players. Unlike fuel, the shield has no continuous drain — it is event-driven: damage events deplete it, and players restore it by feeding Energy tools into a ShieldConsole. Depleting the shield to 0 is no longer a game over — once the shield is down, further attacks bleed through to fuel (see ApplyDamage / fuel bleed-through below). The server is the sole authority; clients receive snapshots and update the diegetic shield monitor.

📄️Enemy Spawner

A generic, server-authoritative combatant spawner for the pirate-encounter and outpost gameplay loops. Given a named spawn group and a wave request, EnemySpawner selects attachment-authored spawn points with cumulative-inverse weighting, jitters each position within a configurable disc, validates the candidate through SpawnVerification (ground snap, wall/headroom clearance, enemy spacing), clones the archetype Model from ServerStorage.EnemyAssets, and returns a WaveHandle that fires OnCleared once the last enemy dies. The server is the sole authority; spawned Models replicate to clients natively via Roblox replication — no packets are required. The spawner owns only the act of spawning: it does not own when spawning happens, does not implement AI or pathfinding, does not manage the cutscene or boarding state machine, and does not model outpost-stop trigger detection. Orchestrators call SpawnWave and react to WaveHandle.OnCleared.

📄️Placeable Actions (Stash / Move)

Stash returns a placed item to the player's Backpack; Move does the same and immediately auto-equips it. Both actions are triggered by invisible ImageButtons inside the placeable's own GUI and validated server-side before any item is transferred.

📄️Camera

A fully script-owned third-person camera. CameraController sets Camera.CameraType = Enum.CameraType.Scriptable and computes Camera.CFrame every frame from yaw/pitch/distance state, rather than decorating Roblox's default Custom camera. Mouse-look, scroll zoom, wall occlusion, and character-facing are all one render step in one script; a small stateless module (CameraRig) does the CFrame math.

📄️Sound

A layered client audio system built around a single facade module. All game audio — one-shot SFX, positional SFX, looped sounds, background music, and ambience beds — flows through SoundManager. No other script creates Sound instances directly.

📄️Notifications

A client-side toast stack driven entirely by signals. Any controller or system fires a single signal to show a notification; NotificationManager is the sole subscriber and handles all layout, animation, audio, and cleanup.

📄️Tech Tree

A cooperative, server-wide, session-only (no DataStore) tech tree lets players pool crafted materials (Wood/Metal) into research nodes at one fixed bench. Eligibility is always-open: any node whose prerequisite is unlocked and which is not yet unlocked accepts submissions. A node auto-unlocks the instant its full cost is met. Because refunds go to a shared ground pile, there is no per-player contribution tracking — one shared pool per node.

📄️Weapons

Client-predicts / server-authoritative combat with a shared validator (WeaponValidation). All damage is applied server-side; client hit claims are never trusted. Weapons are Roblox Tools equipped from the Backpack; the server infers the weapon from the equipped Tool, so fire packets carry only origin/direction — never a claimed target.

📄️Perks

A level-driven permanent progression system that lets players spend points on persistent buffs backed by ProfileStore. Two independent point pools — Personal (buffs the owner only) and Party (buffs are resolved as the server-max of all players) — each grow by exactly 1 point per XP level. Points are derived, never stored; only PerkLevels (a { [perkId]: number } map) persists. Respecs are free.

📄️Workbench Crafting

A placed Workbench station lets players craft weapons, armor, and placeables from config-defined recipes in a single server-authoritative round-trip. Crafting is instant (no hold duration) and per-player. The station is placed in the world by the existing placement system and interacted with through a ProximityPrompt; Stash/Move of the Workbench itself is handled by the existing PlaceableActions system.

📄️Events Orchestrator

A server-authoritative scheduler that decides when in-game events fire, which event fires, and enforces a configurable gap between events. It drives a virtual odometer (distance the train has traveled, accumulated only while running) and one independent state machine per channel. Each channel rolls a weighted table at a configurable distance cadence; the roll can come up empty (a Nothing entry), with a pity guard that forces a real event after enough empty rolls in a row. Events plug in as handler modules implementing a shared EventHandler interface — the orchestrator never touches networking; each handler owns its own client communication.
