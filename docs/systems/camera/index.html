Camera

A single client camera that switches between locked third-person and aim (shoulder) mode, controlled by two orthogonal boolean flags. A MotionMaster spring eases humanoid.CameraOffset between the two modes; a second controller handles raycast occlusion and per-mode zoom clamping.

Data flow​

External signal fires Signals.RequestShootingCamera(true/false)
  └─> CameraController sets aimMode, calls applyState()
        ├─ offsetSpring:SetTarget(ShootingOffset or ThirdPersonOffset)
        ├─ humanoid.AutoRotate = false (aim) / false (locked 3P) / true (free)
        ├─ MouseBehavior = LockCenter (aim/locked) or Default (free)
        ├─ reticleImage.Visible = aimMode
        └─> Signals.OnShootingCameraToggled:Fire(aimMode)
              └─> CameraBoomController switches max-zoom ceiling

LeftAlt key pressed (non-aim only)
  └─> freeLookMode toggles -> applyState()

RunService RenderStep "CameraUpdate" (Priority = Camera + 1)
  ├─ aim   : lerp HRP.CFrame to face camera yaw
  └─> locked 3P: lerp HRP.CFrame to face movement direction

RunService RenderStep "CameraBoom" (Priority = Camera)
  ├─ raycast from camera.Focus toward camera.CFrame.Position
  ├─ clamp hit distance by BoomBuffer
  └─> player.CameraMaxZoomDistance = smoothed clamped distance

Client / Server / Shared​

The camera system is client-only — there is no server component.

CameraController.client.luau

Owns the two state booleans:

  • aimMode — set exclusively via Signals.RequestShootingCamera. No player keybind activates aim directly; only tools (GrabHook on equip) and systems (PlacementClient on build-mode entry) fire this signal.
  • freeLookMode — toggled by LeftAlt; inert while aimMode is true. Aim always wins: when aimMode is true, LeftAlt presses are silently consumed.

On every character load a new MotionMaster.Spring is created bound to humanoid.CameraOffset (destroyed on CharacterRemoving). The spring's Omega and Zeta come from CameraConfig. The render step runs at Camera + 1 priority so it executes after CameraBoom.

CameraBoomController.client.luau

Raycasts from camera.Focus toward camera.CFrame.Position every frame, excluding the local character. If the ray hits geometry, player.CameraMaxZoomDistance is set to hitDistance - BoomBuffer, clamped to [CameraMinZoomDistance, maxForMode]. The result is lerp-smoothed by BoomSmoothingSpeed * dt. The ceiling for maxForMode switches between ShootingCameraMaxZoomDistance (aim) and ThirdPersonCameraMaxZoomDistance (third-person) when Signals.OnShootingCameraToggled fires.

Key files​

  • src/StarterPlayer/StarterPlayerScripts/CameraController.client.luau — state machine, offset spring, render step, signal wiring
  • src/StarterPlayer/StarterPlayerScripts/CameraBoomController.client.luau — raycast occlusion + per-mode zoom clamp
  • src/ReplicatedStorage/SharedModules/Configs/CameraConfig.luau — all camera tuning constants
  • src/ReplicatedStorage/SharedModules/Signals/init.luau — RequestShootingCamera, OnShootingCameraToggled, RequestMouseIcon

Gotchas​

Aim mode is signal-only

There is no keybind that activates aimMode directly. Only external systems fire Signals.RequestShootingCamera. If a new tool or system needs to enter aim mode it must fire this signal — do not read or write the aimMode local directly.

  • Do not use TweenService to animate CameraOffset. The offset spring is a MotionMaster.Spring driver; bypassing it will produce conflicting states and the spring will override any TweenService tween on the next frame.
  • The CameraBoom render step runs at Camera priority, one tick before CameraUpdate at Camera + 1. Do not change these priorities — ordering matters for the zoom clamp to see the correct camera position before HRP rotation is applied.
  • The offset spring is re-created on every CharacterAdded and destroyed on CharacterRemoving. Holding a reference to an old spring past the character death will produce a dangling driver pointing at a destroyed Humanoid.
  • freeLookMode re-enables humanoid.AutoRotate and unlocks the mouse. Any system that expects AutoRotate = false (e.g. shift-lock integrations) should listen to OnShootingCameraToggled rather than polling AutoRotate.
