Camera

A fully script-owned third-person camera. CameraController sets Camera.CameraType = Enum.CameraType.Scriptable and computes Camera.CFrame every frame from yaw/pitch/distance state, rather than decorating Roblox's default Custom camera. Mouse-look, scroll zoom, wall occlusion, and character-facing are all one render step in one script; a small stateless module (CameraRig) does the CFrame math.

Data flow​

UserInputService:GetMouseDelta() (every RenderStep, when look is active)
  └─> yaw  -= delta.X * CameraConfig.MouseLookBaseSpeed * sensitivity
      pitch -= delta.Y * CameraConfig.MouseLookBaseSpeed * sensitivity
      pitch = CameraRig.ClampPitch(pitch, MinPitch, MaxPitch)
        (sensitivity comes from SettingsClient.Get("CameraSensitivity"),
         live-updated via Signals.OnSettingChanged)

Scroll wheel (UserInputService.InputChanged, MouseWheel)
  └─> targetDistance = clamp(targetDistance + step, CameraMinZoomDistance, maxDistanceForMode())

RunService RenderStep "Camera" (Priority = Camera)
  ├─ if buildModeActive: return (PlacementCameraController owns the camera)
  ├─ reassert camera.CameraType = Scriptable if something else changed it
  ├─ occlusion raycast from the offset focus toward the desired camera position
  │    └─> renderDistance smoothed toward occludedDistance (BoomSmoothingSpeed * dt)
  ├─ CameraRig.Compose(subject.Position, offsetHolder.Value, yaw, pitch, renderDistance, lookOffset)
  │    └─> camera.CFrame, camera.Focus
  └─ HRP facing: lerp toward camera yaw (aim) or move direction (locked/free-look)

External signal fires Signals.RequestShootingCamera(true/false)
  └─> CameraController sets aimMode, calls applyState()
        ├─ offsetSpring:SetTarget(ShootingOffset or ThirdPersonOffset)
        ├─ angleSpring:SetTarget(ShootingLookAngle or ThirdPersonLookAngle)
        ├─ MouseBehavior = LockCenter + cursor hidden (aim / locked 3P)
        │               or Default + cursor shown (free-look OR GUI cursor request)
        ├─ reticleImage.Visible = aimMode
        └─> Signals.OnShootingCameraToggled:Fire(aimMode)

LeftAlt key pressed (ContextActionService, non-aim only)
  └─> freeLookMode toggles -> applyState()
        (while freeLookMode is true, mouse-look only runs while RMB is held)

Signals.RequestMouseIcon(visible)
  └─> guiRequestsMouse = visible -> applyState()
        (frees/hides the cursor and suspends look independent of free-look)

Signals.OnBuildModeChanged(isActive)
  └─> buildModeActive = isActive
        (render step becomes a full no-op while true; reclaims Scriptable on resume)

Client / Server / Shared​

The camera system is client-only — there is no server component.

CameraController.client.luau

Owns all camera state and the render step. Two orthogonal booleans select the mode (aim wins over free-look):

  • aimMode — set exclusively via Signals.RequestShootingCamera. No player keybind activates aim directly; only tools (GrabHook on equip), weapons (WeaponController on weapon equip/unequip), and systems (PlacementClient on build-mode entry) fire this signal.
  • freeLookMode — toggled by LeftAlt via ContextActionService:BindAction("ToggleCameraMode", ...); inert while aimMode is true (the action sinks the input but silently no-ops).

Two more flags participate in lookActive()/applyState() without being a "mode" of their own:

  • guiRequestsMouse — set by Signals.RequestMouseIcon; frees and shows the cursor and suspends mouse-look, independent of freeLookMode.
  • buildModeActive — set by Signals.OnBuildModeChanged; see Placement camera.

On every CharacterAdded a new MotionMaster.Spring (offsetSpring) is created bound to a plain { Value, Parent = true } holder (offsetHolder), not directly to humanoid.CameraOffset — the spring drives offsetHolder.Value, which the render step then feeds into CameraRig.Compose as the screen-relative offset. The spring's Omega/Zeta come from CameraConfig; it is destroyed on CharacterRemoving. The render step runs at Camera priority via RunService:BindToRenderStep("Camera", Enum.RenderPriority.Camera.Value, ...).

CameraRig.luau (ReplicatedStorage/SharedModules/CameraRig.luau)

Pure, stateless camera math shared by nothing else today but kept separate so it's independently testable/reviewable:

  • CameraRig.ClampPitch(pitch, minPitch, maxPitch): number — math.clamp wrapper.
  • CameraRig.Compose(focusPosition, offset, yaw, pitch, distance, lookOffset): (CFrame, Vector3) — rotates offset into the yaw/pitch look frame, adds it to focusPosition to get the adjusted focus, then backs the camera off distance studs along the look vector. Returns (cameraCFrame, adjustedFocusPosition); the caller assigns these to camera.CFrame and camera.Focus respectively.

Per-mode look angle​

lookOffset is an optional Vector2 (radians, X=pitch, Y=yaw) that rotates the look direction about the fixed camera position — the camera position and the occlusion raycast (which fires before Compose runs, off targetDistance/renderDistance) are untouched. nil/zero is a no-op, matching the pre-existing camera behavior exactly.

CameraConfig.ShootingLookAngle and CameraConfig.ThirdPersonLookAngle supply this in degrees (X=pitch, +up/−down; Y=yaw, +left/−right); CameraController blends the active mode's angle with a second MotionMaster.Spring — mirroring offsetSpring/offsetHolder exactly (retargeted on the same applyState() calls that retarget the offset spring, created/destroyed alongside it) — converts the blended value to radians, and passes it into CameraRig.Compose every frame. Because aim/shot raycasts read the live camera through screen center rather than a separate aim-vector, aiming stays consistent under any angle with no additional math to keep in sync.

Modes​

Locked third-person (default) — mouse always drives yaw/pitch (lookActive() returns true); MouseBehavior = LockCenter, cursor hidden; the HRP lerps to face humanoid.MoveDirection while moving.

Aim — entered only via Signals.RequestShootingCamera(true). Shoulder offset (CameraConfig.ShootingOffset) via the offset spring, reticle visible, mouse locked+hidden, HRP lerps to face the camera's yaw (not movement direction) so aiming and strafing look correct together. Exiting fires Signals.OnShootingCameraToggled(false).

Free-look — toggled by LeftAlt when not aiming. Cursor is freed and shown (MouseBehavior = Default), but lookActive() only returns true while the right mouse button is held (UserInputService:IsMouseButtonPressed(Enum.UserInputType.MouseButton2)) — a faithful port of the old default-camera free-look behavior. HRP still lerps to face movement direction, same as locked third-person.

Signals.RequestMouseIcon is orthogonal to all three modes: while guiRequestsMouse is true (and aimMode is false), the cursor is freed/shown and lookActive() returns false regardless of freeLookMode, for GUIs (e.g. the workbench) that need a clickable cursor.

Sensitivity​

sensitivity is read once at startup from SettingsClient.Get("CameraSensitivity") and kept live-updated by subscribing to Signals.OnSettingChanged (filtering on key == "CameraSensitivity"). Every frame that lookActive() is true, raw pixel delta from UserInputService:GetMouseDelta() is scaled by CameraConfig.MouseLookBaseSpeed * sensitivity before being applied to yaw/pitch. See Settings for how CameraSensitivity is defined, synced, and persisted.

Zoom​

Scroll wheel input (UserInputService.InputChanged, filtered to Enum.UserInputType.MouseWheel and not gameProcessed) adjusts targetDistance by CameraConfig.ScrollZoomStep per notch, clamped to [CameraConfig.CameraMinZoomDistance, maxDistanceForMode()]. maxDistanceForMode() returns ShootingCameraMaxZoomDistance in aim mode or ThirdPersonCameraMaxZoomDistance otherwise — the same per-mode ceiling switch the old CameraBoomController did off OnShootingCameraToggled, now just a local function call since everything lives in one script.

Occlusion​

Folded into CameraController's own render step (previously a second script, CameraBoomController.client.luau, now deleted). Each frame: a raycast runs from the offset focus point (subject.Position + offset rotated into the look frame) toward the desired camera position, excluding the local character (RaycastParams.FilterType = Exclude, RespectCanCollide = true). If it hits, occludedDistance is clamped to hitDistance - CameraConfig.BoomBuffer (floored at CameraMinZoomDistance); otherwise it's just targetDistance. A separate renderDistance is lerped toward occludedDistance at BoomSmoothingSpeed * dt per frame and is what actually gets passed to CameraRig.Compose — targetDistance (the zoom-wheel target) is never touched by occlusion, so releasing from behind a wall smoothly zooms back out to the player's chosen distance.

Placement camera​

While build mode is active, PlacementCameraController.client.luau — a separate script, not part of CameraController — takes exclusive ownership of the camera:

  • Sets Camera.CameraType = Enum.CameraType.Scriptable and drives Camera.CFrame every frame: fixed height and pitch above the player (PlacementConfig.TopDownHeight/TopDownPitch), locked to whatever yaw the player was facing when build mode started.
  • Eases into and out of the top-down angle via an exponential chase-lerp (alpha = 1 - exp(-CameraTransitionSpeed * dt), same idiom as PlacementSystem's FreeModeLerpSpeed/RotationLerpSpeed) rather than snapping instantly. On exit there's no live Custom-camera CFrame to blend toward, so it eases toward an approximation reconstructed from the camera's offset relative to the player's HumanoidRootPart at the moment build mode was entered, applied to the player's current position — then hands off to Enum.CameraType.Custom once that blend has settled (EXIT_SETTLE_TIME, ≈0.2s at the default speed). Any residual approximation error is invisible: the instant Custom resumes control, it corrects to the true position.
  • Also fades any PlacementConfig.OccluderTag-tagged parts (e.g. roofs) to OccluderTransparency for the duration, restoring their original transparency on exit.
  • Fires Signals.RequestMouseIcon(true) on PC (gated on UserInputService.MouseEnabled and UserInputService.KeyboardEnabled) so CameraController frees and shows the cursor instead of locking it to screen-center. This is required because the placement camera doesn't rotate with mouse movement, so mouse.UnitRay (used by PlacementClient for the placement raycast) needs a cursor that can actually move to aim anywhere but straight down at the player.
  • Restores Enum.CameraType.Custom immediately (hard cut, no blend) on CharacterRemoving — a backstop in case build mode didn't cleanly exit first, e.g. character death — the mouse-icon request and occluder fade are restored at the same point (skipped if a build-mode exit already restored them moments earlier).

CameraController and PlacementCameraController now both own the Scriptable camera at different times, and coordinate via Signals.OnBuildModeChanged. Unlike the old default-camera (Custom) architecture — where CameraController never touched Camera.CFrame/Camera.CameraType and so ran harmlessly underneath the placement camera regardless of what it did — CameraController is now itself a Scriptable-camera owner and would fight PlacementCameraController for the same properties every frame if left running. CameraController subscribes to Signals.OnBuildModeChanged and sets buildModeActive accordingly; its render step's first statement is if buildModeActive then return end, a full no-op (no CFrame, Focus, or CameraType writes) for the duration of build mode. On resume it reasserts camera.CameraType = Enum.CameraType.Scriptable (guarded — only writes if the current value isn't already Scriptable, to avoid a redundant property set every frame).

Accepted ~0.2s exit-stutter

PlacementCameraController's own exit-blend keeps writing camera.CFrame for EXIT_SETTLE_TIME (≈0.2s at the default CameraTransitionSpeed) after build mode ends, before it hands CameraType back to Custom. Since CameraController resumes its own Scriptable writes immediately when OnBuildModeChanged(false) fires, there is a brief window where both scripts could in principle write Camera.CFrame on the same frame-ish timescale, producing a small visual stutter at the exact moment of exiting build mode. This is a known, accepted residual limitation — not a bug to be silently fixed — because eliminating it would require either a new cross-module "exit fully settled" signal or coupling CameraController to PlacementCameraController's private EXIT_SETTLE_TIME constant, both judged not worth the coupling for a sub-quarter-second cosmetic blip.

Key files​

  • src/StarterPlayer/StarterPlayerScripts/CameraController.client.luau — state machine, mouse-look, zoom, occlusion, offset spring, render step, signal wiring
  • src/ReplicatedStorage/SharedModules/CameraRig.luau — stateless CFrame composition (Compose, ClampPitch)
  • src/StarterPlayer/StarterPlayerScripts/PlacementCameraController.client.luau — owns the camera during build mode; see Placement camera
  • src/ReplicatedStorage/SharedModules/Configs/CameraConfig.luau — all camera tuning constants
  • src/ReplicatedStorage/SharedModules/Signals/init.luau — RequestShootingCamera, OnShootingCameraToggled, RequestMouseIcon, OnBuildModeChanged, OnSettingChanged

Gotchas​

Aim mode is signal-only

There is no keybind that activates aimMode directly. Only external systems fire Signals.RequestShootingCamera. If a new tool or system needs to enter aim mode it must fire this signal — do not read or write the aimMode local directly.

  • Do not use TweenService to animate the camera offset. offsetSpring is a MotionMaster.Spring driver bound to offsetHolder.Value; bypassing it will produce conflicting states and the spring will override any TweenService tween on the next frame.
  • CameraController and PlacementCameraController both write Camera.CameraType/Camera.CFrame and must never run their write paths in the same frame — that's what buildModeActive (via Signals.OnBuildModeChanged) exists to prevent. Do not add a third script that writes Camera.CFrame without wiring it into this same coordination.
  • The offset spring is re-created on every CharacterAdded and destroyed on CharacterRemoving. Holding a reference to an old spring past the character death will produce a dangling driver pointing at a destroyed Humanoid.
  • freeLookMode frees and shows the mouse cursor, but — unlike the old default-camera implementation — does not re-enable humanoid.AutoRotate; CameraController always drives HRP facing itself (toward camera yaw in aim, toward move direction otherwise) and sets humanoid.AutoRotate = false unconditionally (skipped entirely while humanoid.Sit is true). Any system that expects rotation to be script-driven should listen to OnShootingCameraToggled rather than polling AutoRotate.
  • A GUI that needs a clickable cursor fires Signals.RequestMouseIcon:Fire(true); while set (and not aiming) the camera holds MouseBehavior = Default and shows the cursor, restoring LockCenter on Fire(false). The PC gate lives in the producer (WorkbenchGuiController, PlacementCameraController), so the camera frees the mouse whenever asked regardless of platform.
  • CameraSensitivity changes take effect on the very next frame via Signals.OnSettingChanged — there is no need to re-fetch SettingsClient.Get manually or restart the character.
