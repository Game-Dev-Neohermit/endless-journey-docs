Stamina & Sprint

Sprint is client-predicted for responsive feel and server-authoritative for integrity. The server runs the canonical stamina simulation and pushes syncs at up to 10 Hz; the client uses each sync to gate visual and audio effects.

Data flow​

Player holds Shift (or mobile toggle)
       │
       ▼
SprintController (client)
  • applySprintIntent() → Packets.StaminaSprintIntent:Fire(true) ──► StaminaManager (server)
                                                                       • sets record.SprintIntent
                                                                       • runs Heartbeat drain/regen
                                                                       • syncs via StaminaStateSync
  ◄── Packets.StaminaStateSync (serverStamina, serverIsSprinting) ───
  • currentStamina = serverStamina
  • if !serverIsSprinting → setSprinting(false)
  • Signals.OnStaminaValueChanged:Fire(currentStamina) ──► HUD bar

  (RenderStepped — every frame)
  • setSprinting(sprintIntent AND canSprintNow())
    • humanoid.WalkSpeed = SprintSpeed / WalkSpeed
    • tweenFov(SprintFOV / DefaultFOV)
    • Signals.OnSprintToggled:Fire(isSprinting)

  ◄── Packets.StaminaBuffSync (infinite, regenMult, usageMult) ──────
  • Signals.OnStaminaBuffsChanged:Fire(...)  ──► HUD / buff icons

Client / Server / Shared​

Client (SprintController.client.luau)

  • Binds sprint to LeftShift and ButtonB (gamepad) via ContextActionService; a separate MobileSprintToggled signal handles the mobile toggle button.
  • On each RenderStepped tick calls canSprintNow() (wraps SprintValidation.CanHumanoidSprint) and calls setSprinting accordingly.
  • setSprinting sets humanoid.WalkSpeed, tweens FieldOfView via TweenPlus, and fires Signals.OnSprintToggled.
  • WalkSpeed is set client-side only; there is no server-side speed reconciliation (see audit note S3 in the source).
  • On StaminaStateSync: clamps received stamina, forces sprint off if the server says so, fires Signals.OnStaminaValueChanged for the HUD.
  • On StaminaBuffSync: forwards buff state to Signals.OnStaminaBuffsChanged for UI and icon updates.
  • Resets sprint intent on CharacterRemoving and on WindowFocusReleased.

Server (StaminaManager.luau)

  • Maintains a StaminaRecord per player (Stamina, IsSprinting, SprintIntent, LastSprintTime, LastSyncTime).
  • On StaminaSprintIntent packet: immediately updates sprint state and calls syncPlayer.
  • Heartbeat loop: clamps dt to MAX_STAMINA_STEP_DT = 0.1 s to prevent large delta spikes. Drains stamina at StaminaDrain * dt * UsageMultiplier while sprinting; regenerates at StaminaRegen * dt * RegenMultiplier after RegenDelay seconds of not sprinting.
  • Syncs to the client when: sprint state changes, stamina hits 0 (forced stop), stamina refills to max, or periodic sync interval (STAMINA_SYNC_INTERVAL = 0.1 s) elapses while stamina is changing.
  • Consults StaminaBuffManager each tick for buff multipliers; resyncs immediately on Signals.OnServerStaminaBuffStateChanged.
  • StaminaManager.RestoreStamina(player, amount) is available for pickup items but has no caller yet.

Shared (SprintValidation.luau)

  • SprintValidation.CanHumanoidSprint(humanoid, rules) — returns false if health is 0, MoveDirection magnitude is below MinMoveDirection, the character is moving backward beyond MaxBackwardComponent, or horizontal speed is below MinHorizontalSpeed.
  • Called on both client (canSprintNow) and server (canPlayerSprint) to keep the gate condition identical.

Key files​

  • src/StarterPlayer/StarterPlayerScripts/SprintController.client.luau — client prediction: WalkSpeed, FOV tween, intent signalling, sync consumption
  • src/ServerStorage/SharedModules/StaminaManager.luau — server authority: drain/regen simulation, sync dispatch, buff application
  • src/ReplicatedStorage/SharedModules/SprintValidation.luau — shared sprint gate conditions (humanoid state checks)
  • src/ReplicatedStorage/SharedModules/Configs/StaminaConfig.luau — all tuning constants

Buff presets (StaminaRegenBuff, StaminaUsageBuff, InfiniteStaminaBuff) define strength and duration for collectible buffs; icons are asset IDs for the HUD.

Gotchas​

Sprint logic must be mirrored on both sides

SprintValidation.CanHumanoidSprint is the shared gate. If you add a new sprint-blocking condition (e.g. stun), add it to SprintValidation and verify it is called by both SprintController (client) and StaminaManager (server). A condition added only to one side will cause desyncs.

  • WalkSpeed is client-only. The server does not validate movement speed; a cheating client can move at any speed. If movement integrity becomes necessary, add a server-side speed sanity check.
  • STAMINA_SYNC_INTERVAL = 0.1 s (10 Hz). The server only sends a sync when stamina is actively changing. If stamina is full and the player is standing still, no sync is sent — this is intentional.
  • MAX_STAMINA_STEP_DT = 0.1 s clamp. The server caps the Heartbeat delta so a lag spike cannot drain or regen an unrealistic amount of stamina in one tick. Do not remove this clamp.
  • Buff state is authoritative on the server. StaminaBuffSync pushes the current multipliers to the client for display only; the client never applies buffs directly to the drain/regen calculation.
  • StaminaManager.Initialize() must be called once. It is called by StaminaSystemLoader.server.luau; do not call it from a second script.
