Proximity Pickup

Dropped craft-material Tools and shredder-ejected material handles register with a server pickup system; any player who walks into the detection sphere claims the item. Unclaimed items auto-collect to the owner after a configurable delay. The client plays a hover/spin effect on unclaimed items and a float-to-hand animation on claim.

Data flow​

── DROP PATH (DroppedToolService) ───────────────────────────────────────────────
Player presses Backspace → Tool drops as direct child of workspace
workspace.DescendantAdded fires on IsCraftMaterial Tool
  handle.CollisionGroup = "DroppedMaterial"
  handle.CanCollide = true, Anchored = false
  DropLandingHelper.waitForLanding(handle) polling loop:
    every DROP_POLL_INTERVAL (0.1 s): GetTouchingParts → DroppableSurface contact?
    velocity.Magnitude < SETTLED_VELOCITY_THRESHOLD (0.5 studs/s)?
  → result "landed":
    handle.Anchored = true, rotation reset to identity
    ProximityPickupServer.RegisterItem(tool, metadata, callback, keepModel=true)

── SHREDDER PATH (ShredderServer) ────────────────────────────────────────────────
ejectMaterials() arc completes → handle anchored at landing pos
  ProximityPickupServer.RegisterItem(handle, metadata, pickupCallback, false)
  CollectionService:AddTag(handle, "CraftMaterial")

── REGISTRATION (ProximityPickupServer.RegisterItem) ─────────────────────────────
  generate itemId (GUID)
  part:SetAttribute("PickupItemId", itemId)
  CollectionService:AddTag(part, "PickupItem")
  spawn invisible sphere zone (DEFAULT_RADIUS=6 studs) in workspace.PickupZones
  zone.Touched → player enters → executeClaimAsync()
  task.delay(MERGE_DELAY=1s) → _TryMerge() [same ItemType, within MERGE_RADIUS=2 studs]
  ──── PickupItemReady:Fire(part, itemId) ─────────────────────────────────────────►

── CLIENT (ProximityPickupController) ────────────────────────────────────────────
  PickupItemReady.OnClientEvent(handle, itemId):
    HoverEffect.Apply(handle, HOVER_HEIGHT, HOVER_DURATION,
                      { FloorOffset, SpinDuration })
    AncestryChanged → cleanupItem on destroy

── CLAIM (zone.Touched or ProximityPickupServer.Claim) ───────────────────────────
Server:
  record.State = "Claimed", record.Zone:Destroy()
  part.CanCollide = false (all descendants)
  ──── PickupItemClaimed:Fire(itemId, claimerPlayer) ──────────────────────────────►
  task.delay(FLOAT_DURATION=0.25s):
    callback(player, metadata) → tool.Parent = player.Backpack
    if not keepModel: part:Destroy()
    activeItems[itemId] = nil

Client:
  PickupItemClaimed.OnClientEvent(itemId, claimer):
    cleanupItem (stop hover)
    if claimer == LocalPlayer:
      SoundManager.PlaySFXAt("ProximityPickup", anchor.Position)
      MotionMaster.Play(handle, { CFrame = hrp.CFrame offset }, { Duration=0.25, Linear })
    else:
      handle:Destroy()

── AUTO-COLLECT (ShredderServer loop, 0.5 s poll) ────────────────────────────────
  now - SpawnTime >= AUTO_COLLECT_DELAY (45 s):
    ProximityPickupServer.Claim(mat, owner)
    if not registered: callback(owner) + mat:Destroy()

Client / Server / Shared​

Client (ProximityPickupController.client.luau) Listens to two packets only; creates no UI and does no proximity math. PickupItemReady applies a HoverEffect (bob + Y-spin) to the handle via a Janitor-managed cleanup handle, and wires AncestryChanged so the effect stops cleanly when the part is destroyed. PickupItemClaimed stops the hover effect, then for the local claimer plays a pickup SFX (via SoundManager.PlaySFXAt using CharacterAnchor to resolve the player's position) and tweens the handle toward the camera using MotionMaster.Play; for all other clients it destroys the handle immediately.

Server (ProximityPickupServer.luau) RegisterItem(part, metadata, callback, keepModel?) is the sole public registration entry. It generates a GUID itemId, tags the part "PickupItem", creates an invisible anchored sphere zone in workspace.PickupZones, and fires PickupItemReady to all clients. zone.Touched is the primary claim trigger (any player, shared-loot semantics). Claim(part, player) is the programmatic path used by the shredder's auto-collect loop. Both paths call the same executeClaimAsync which transitions the record to "Claimed", destroys the zone, broadcasts PickupItemClaimed, then after FLOAT_DURATION calls the callback and cleans up. _TryMerge runs after MERGE_DELAY and absorbs a newly registered handle into a nearby same-type unclaimed survivor, accumulating Quantity on the survivor.

Dropped-tool server (DroppedToolService.server.luau) Bootstraps two PhysicsService collision groups: DroppedMaterial (Tools that leave the player's hand) and DroppableSurface (tagged geometry). DroppedMaterial is set non-collidable with Default and collidable with DroppableSurface so dropped items fall through characters and walls but land on tagged floors. A workspace.DescendantAdded listener catches craft-material Tools parented directly to workspace (the Roblox default Backspace drop path) and delegates to DropLandingHelper.waitForLanding, which polls GetTouchingParts plus velocity until the handle settles on a DroppableSurface. Landing triggers RegisterItem with keepModel = true (the Tool itself is the inventory object, not a clone).

Shared (ProximityPickupConfig.luau) All tunable constants for radius, animation durations, merge behaviour, and the landing poll cadence.

Key files​

  • src/ServerStorage/SharedModules/ProximityPickupServer.luau — RegisterItem, Claim, zone creation, shared-loot zone.Touched handler, _TryMerge, player-disconnect cleanup
  • src/StarterPlayer/StarterPlayerScripts/ProximityPickupController.client.luau — PickupItemReady hover/spin, PickupItemClaimed float-to-hand animation and SFX
  • src/ServerScriptService/DroppedToolService.server.luau — DroppableSurface tag wiring, DescendantAdded drop detection, DropLandingHelper integration
  • src/ServerStorage/SharedModules/CollisionGroups.luau — centralized registrar for every collision group + its collidability matrix (DroppedMaterial, DroppableSurface, plus Character and WeaponProjectile for the weapon system); required by the services that assign groups
  • src/ReplicatedStorage/SharedModules/Configs/ProximityPickupConfig.luau — radius, float duration, hover/spin parameters, merge settings, landing poll constants

Config knobs​

All constants live in src/ReplicatedStorage/SharedModules/Configs/ProximityPickupConfig.luau.

FieldDefaultEffect
DEFAULT_RADIUS6Studs; radius of the pickup sphere zone
FLOAT_DURATION0.25Seconds the handle floats to the player's hand after claim
HOVER_HEIGHT1.25Studs; bob amplitude of the hover effect
HOVER_DURATION2.25Seconds per half-cycle of the bob
SPIN_DURATION6Seconds per full Y-axis rotation while hovering
MERGE_RADIUS2Studs; maximum distance for same-type item merge
MERGE_ENABLEDtrueKill switch to disable merging globally
MERGE_DELAY1.0Seconds after registration before merge attempt
SETTLED_VELOCITY_THRESHOLD0.5Studs/s; handle velocity below this is considered at rest
DROP_POLL_INTERVAL0.1Seconds between GetTouchingParts checks during landing
DROP_LANDING_TIMEOUT60Seconds before giving up on a handle that never lands

Gotchas​

Shared loot — not owner-only

Any player who steps into the pickup sphere claims the item, regardless of who dropped it or who the shredder owner was. The auto-collect timer (AUTO_COLLECT_DELAY in ShredderConfig, 45 s) returns unclaimed floor materials to the owner via ProximityPickupServer.Claim. If owner-only pickup is ever needed, the RegisterItem signature must be extended with an owner: Player? parameter and the zone.Touched handler must gate on it (see audit comment PP6 in ProximityPickupServer).

DroppableSurface tagging — no code change needed. Any BasePart tagged "DroppableSurface" in CollectionService is automatically assigned the DroppableSurface collision group at runtime via GetInstanceAddedSignal. To make a new floor or shelf surface catchable, tag it in Studio only.

Collision groups are registered in one place. CollisionGroups.luau (ServerStorage/SharedModules) is the sole registrar and owns the full collidability matrix. Besides DroppedMaterial/DroppableSurface, it defines Character (every character BasePart, assigned by CharacterCollisionService) and WeaponProjectile (thrown charges, assigned by ServerProjectile). Because characters now live in their own group rather than Default, dropped materials and projectiles both pass through players while still colliding with world geometry. Any system that needs a new group or a new pair rule should edit CollisionGroups.luau, not call PhysicsService directly.

keepModel semantics: when keepModel = true (the DroppedToolService path), the registered part is the actual Tool that will go into the player's Backpack — RegisterItem will not destroy it. The callback sets tool.Parent = player.Backpack. When keepModel = false (the shredder path), the server clones the template, registers the clone, and the callback grants a fresh clone again; the floor handle is destroyed after claim.

Zone placement: pickup zones are parented to workspace.PickupZones (not to the item part). This prevents "trying to set locked parent!" physics warnings when the zone is destroyed at claim time while the item is still mid-float.

_TryMerge skips keepModel items: the merge logic will not absorb a keepModel item into another, because merging would destroy one of the actual inventory objects. Only non-keepModel handles (shredder clones) are eligible for merging.

Late-joining players: ProximityPickupServer has a Players.PlayerAdded listener that replays all currently "Unclaimed" PickupItemReady events to the new client, so items already on the floor will show their hover effect for late joiners.
