Progression (XP & Level)

Server-authoritative, party-shared XP & Level system persisted with ProfileStore.

Data model​

The profile stores a single value, TotalXP (lifetime cumulative). Level and progress are derived from it via XPCurve.luau, so re-tuning the curve never desyncs saved data.

Curve​

xpToNext(L) = round(CURVE_COEFF * L ^ CURVE_EXP) + CURVE_OFFSET (defaults 5, 1.5, 45), cap MAX_LEVEL = 100. Total to level 100 ≈ 202,000 XP. All constants live in Configs/XPConfig.luau.

Earning (party-shared)​

XP is shared with the whole party; one party occupies one server, so every player in the server receives the full award.

  • Distance: while the train is in its "go" state (running — not braked, not stalled), the party earns DISTANCE_XP_PER_TICK every DISTANCE_TICK_SECONDS. Driven off Signals.SetTrainState. The train starts braked, so no XP accrues before the first un-brake.
  • Kills: any EnemyNPC death awards KILL_XP to the party (attribution- agnostic). Wired in XPSystemLoader.

Components​

  • Configs/XPConfig.luau — tuning constants.
  • XPCurve.luau — pure level/progress math.
  • XPManager.luau (ServerStorage) — profile lifecycle, award API (AddXP, AddPartyXP), replication. Runs in both places.
  • XPSystemLoader.server.luau — gameplay-only earner wiring.
  • XPController.client.luau — replication bridge → Signals.OnXPChanged, and the level-up toast via Signals.RequestNotification.

Cross-place (lobby ↔ gameplay)​

DataStores are universe-wide. Both places use the same STORE_NAME and key (tostring(UserId)), so XP/Level are shared automatically; ProfileStore session-locking serializes the teleport handoff. The lobby place must run XPManager.Initialize() and XPController (for display + clean handoff) but NOT XPSystemLoader — no earners in the lobby. The lobby mirror is a separate deployment, not part of this repo.

Not yet built​

XP bar HUD (will consume OnXPChanged), level rewards (hook: XPLevelUp), per-killer attribution, additional XP sources.
