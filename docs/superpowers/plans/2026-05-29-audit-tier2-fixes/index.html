Task 1: [SH1] Implement the documented shredder eject cap​

MAX_ANIMATED_EJECT_ITEMS and DIRECT_GRANT_BATCH_SIZE are defined and documented but unused; ejectMaterials animates the entire sequence. Implement the cap: animate up to the max, then direct-grant the overflow in batches.

Files:

  • Modify: src/ServerScriptService/ShredderServer.server.luau (ejectMaterials)

  • Step 1: Add a direct-grant helper above ejectMaterials

Insert immediately before the local function ejectMaterials(...) definition:

-- Grants a single material Tool straight to the player's Backpack (overflow path:
-- used when the eject count exceeds MAX_ANIMATED_EJECT_ITEMS so we don't spawn an
-- unbounded number of world parts + tweens).
local function grantMaterialTool(owner: Player, materialName: string)
	local template = getMaterialTemplate(materialName)
	if not template then
		return
	end
	local tool = template:Clone()
	tool:SetAttribute("MaterialType", materialName)
	tool:SetAttribute("ItemType", materialName)
	tool:SetAttribute("IsCraftMaterial", true)
	tool.CanBeDropped = false
	tool.Parent = owner.Backpack
end
  • Step 2: Compute the animated count and drive stream timing from it

In ejectMaterials, replace the itemCount == 0 guard + streamDelay block:

	local itemCount = #sequence
	if itemCount == 0 then
		unlockWorkbench(workbench)
		return
	end

	-- Cap how many items get the full arc animation; the rest are granted directly.
	local animatedCount = math.min(itemCount, ShredderConfig.MAX_ANIMATED_EJECT_ITEMS)

	local streamDelay = ShredderConfig.ITEM_EJECT_DELAY
	if animatedCount > 1 then
		local capWindow = math.max(ShredderConfig.MAX_STREAM_DURATION, 0)
		if capWindow > 0 then
			streamDelay = math.min(streamDelay, capWindow / (animatedCount - 1))
		end
	end
  • Step 3: Loop only over the animated slice

Change the loop header from for index, materialName in sequence do to an index loop bounded by animatedCount, and add the local materialName:

	for index = 1, animatedCount do
		local materialName = sequence[index]

		-- Validate the owner is still in-game before each item.
		if not owner.Parent then
			break
		end

(The entire existing per-item body — template lookup, handle clone, pickupCallback, droppedMaterials insert, scatter math, SplineMove, OnComplete register+tag — stays exactly as written.)

  • Step 4: Bound the inter-item wait by animatedCount

Change the end-of-loop stream wait (currently if index < itemCount and streamDelay > 0 then):

		if index < animatedCount and streamDelay > 0 then
			-- Stream delay between items.
			task.wait(streamDelay)
		end
	end
  • Step 5: Direct-grant the overflow in batches before unlocking

Immediately after the animated for loop (and before the final task.wait(ShredderConfig.ARC_DURATION)):

	-- Overflow beyond the animation cap is granted directly, in scheduler-friendly batches.
	if itemCount > animatedCount then
		local grantedInBatch = 0
		for index = animatedCount + 1, itemCount do
			if not owner.Parent then
				break
			end
			grantMaterialTool(owner, sequence[index])
			grantedInBatch += 1
			if grantedInBatch >= ShredderConfig.DIRECT_GRANT_BATCH_SIZE then
				grantedInBatch = 0
				task.wait()
			end
		end
	end

	-- Wait for the last arc to complete before unlocking.
	task.wait(ShredderConfig.ARC_DURATION)
	unlockWorkbench(workbench)
  • Step 6: Studio verification — small shred unchanged

Shred a handful of junk (well under 60 materials). Expected: all materials arc out and are collectable exactly as before; the reported wood/metal counts match what lands.

  • Step 7: Studio verification — large shred is capped, totals still correct

Give yourself a large junk pile (e.g. many tier-4 junks → hundreds of materials) and shred. Expected: at most MAX_ANIMATED_EJECT_ITEMS (60) materials animate; the remainder appear directly in your Backpack within a second or two; the total Tools received equals wood+metal from the toast; no visible frame hitch from spawning hundreds of parts at once.

Task 2: [PP2] Remove the orphaned MaterialPickupService​

MaterialPickupService only registers CraftMaterial-tagged models lacking the PickupItem tag, but both real producers add PickupItem first — so it never fires for them. (If you instead want a Studio-authored pre-placed material feature, repair it to the Wood/Metal CraftingMaterials scheme — but that is out of scope here.)

Task 3: [SH2] ShredderClient toast → MotionMaster (CLAUDE.md compliance)​

The toast fade uses TweenService:Create, the only TweenService use in the project and a direct CLAUDE.md violation. Mirror TrainClient's MotionMaster-based toast.

  • Step 1: Swap the service require for MotionMaster

and add a MotionMaster require alongside the other SharedModules requires (after the Packets require):

  • Step 2: Loosen the toastTween type

Change the declaration:

  • Step 3: Update the cancel-in-progress block in showToastText

Replace the existing cancel block:

		toastTween:Cancel()
		toastTween:Destroy()
		toastTween = nil
	end
  • Step 4: Replace the fade-out tween with MotionMaster

Replace the task.delay(TOAST_DISPLAY_TIME, ...) body's tween section:

	task.delay(TOAST_DISPLAY_TIME, function()
		if mySerial ~= toastSerial then
			return
		end

		local tw = MotionMaster.Create(toastFrame, { BackgroundTransparency = 1 }, {
			Duration = 0.5,
			Model = "EaseOutQuad",
		})
		toastTween = tw
		tw:OnComplete(function()
			tw:Destroy()
			if mySerial ~= toastSerial then
				return
			end
			toastFrame.Visible = false
			toastTween = nil
		end)
		tw:Play()
	end)

	newSound:Play()

	if not newSound.IsLoaded then
		newSound.Loaded:Wait()

	-- Return objects to pools
