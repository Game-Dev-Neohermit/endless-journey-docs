Proximity Merge Delay Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Add a configurable silent delay before nearby same-type items merge, so players have time to see both items before they combine.

Architecture: Add MERGE_DELAY constant to the existing config module, then wrap the _TryMerge call site in ProximityPickupServer with task.delay. An activeItems guard inside the callback handles the race where an item is picked up before the delay fires.

Tech Stack: Luau, Roblox task library

Task 1: Add MERGE_DELAY to config​

Files:

  • Modify: src/ReplicatedStorage/SharedModules/Configs/ProximityPickupConfig.luau:13-14

  • Step 1: Open the config file and add the new field after MERGE_ENABLED

Current lines 13–14:

	MERGE_RADIUS = 2, -- studs; distance threshold for same-type item merge
	MERGE_ENABLED = true, -- kill switch; set false to disable merging globally

Replace with:

	MERGE_RADIUS = 2, -- studs; distance threshold for same-type item merge
	MERGE_ENABLED = true, -- kill switch; set false to disable merging globally
	MERGE_DELAY = 1.5, -- seconds to wait after registration before attempting merge
  • Step 2: Commit
git add "src/ReplicatedStorage/SharedModules/Configs/ProximityPickupConfig.luau"
git commit -m "config: add MERGE_DELAY constant for proximity merge timing"

Task 2: Defer _TryMerge call in ProximityPickupServer​

Files:

  • Modify: src/ServerStorage/SharedModules/ProximityPickupServer.luau:181

  • Step 1: Locate the call site

Open src/ServerStorage/SharedModules/ProximityPickupServer.luau. Find line 181 — it reads:

	_TryMerge(itemId)

It sits between executeClaimAsync zone setup and PickupItemReady:Fire(...).

  • Step 2: Replace with the deferred call

Replace just that one line:

	task.delay(ProximityPickupConfig.MERGE_DELAY, function()
		if activeItems[itemId] then
			_TryMerge(itemId)
		end
	end)

The guard if activeItems[itemId] then makes the callback a no-op if the item was picked up, claimed, or destroyed before the delay fires.

  • Step 3: Commit
git add "src/ServerStorage/SharedModules/ProximityPickupServer.luau"
git commit -m "feat: delay proximity item merge by MERGE_DELAY seconds"

Task 3: Verify in Studio​

There is no automated test suite — verification happens in Roblox Studio.

  • Step 1: Start Rojo and open Studio
rojo serve

Open the place file in Roblox Studio and connect the Rojo plugin.

  • Step 2: Verify basic merge delay

Start a playtest. Drop (or trigger the shredder to produce) two same-type items within 2 studs of each other.

Expected: Both items are visible as separate entities for ~1.5 s, then silently merge into one item with combined quantity.

  • Step 3: Verify pickup race (guard test)

Drop two same-type items within 2 studs. Before 1.5 s elapses, walk over and pick up one of them.

Expected: The pickup succeeds normally. The remaining item stays as a standalone pickup — no error, no phantom merge attempt on a destroyed item.

  • Step 4: Verify shredder cascade (3-item case)

Trigger the shredder to drop 3 same-type items in rapid succession (0.1–0.2 s intervals) within 2 studs of each other.

Expected: All 3 items are visible for ~1.5 s, then cascade-merge over ~0.2 s into one item whose quantity equals the sum of all three.

  • Step 5: Verify zero-delay fallback

In ProximityPickupConfig.luau, temporarily set MERGE_DELAY = 0. Re-run the Rojo sync and playtest.

Expected: Merging behaves as it did before this change — effectively instant. Restore MERGE_DELAY = 1.5 when done.
