Friendly Fire Prevention Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Stop all friendly fire — players can't damage players or friendly NPCs, enemy NPCs can't damage enemy NPCs or friendly NPCs — by enforcing a faction policy at the single server damage choke point.

Architecture: A new shared Factions module owns the policy (faction resolution from a Player/Model + a default-deny canDamage table). CombatService.ApplyToModel resolves attacker and target factions and rejects disallowed pairs before applying damage, with a self-exemption so a player's own AOE still self-damages. The "NPC" CollectionService tag is replaced by "EnemyNPC" / "FriendlyNPC"; NpcCollisionService watches both. Because melee, guns, and AOE all funnel through ApplyToModel, one check covers everything.

Tech Stack: Luau, Rojo, Roblox CollectionService tags, existing CombatService / HealthManager / NpcCollisionService. No automated test suite — verification is manual in Roblox Studio via live Rojo sync (do not run rojo build or selene).

Spec: docs/superpowers/specs/2026-06-09-friendly-fire-prevention-design.md

Task 1: Create the Factions shared module​

Files:

  • Create: src/ReplicatedStorage/SharedModules/Factions.luau

  • Step 1: Write the module

--!strict
--!native

--[=[
    @class Factions
    Combat faction policy shared by client and server. Resolves a Player or a
    Humanoid-bearing Model to a `Faction`, and decides whether one faction may
    damage another via a default-deny hostility table.

    Faction comes from: a Player (or a Model that is a player's character) →
    "Player"; a Model tagged `EnemyTag` → "Enemy"; a Model tagged `FriendlyTag`
    → "Friendly". These two tags REPLACE the former single "NPC" tag — being
    either tag marks a Model as a combatant (damageable + collision pass-through;
    see NpcCollisionService).

    Only Player<->Enemy damage is allowed. Every other ordered pair is denied,
    so there is no player-vs-player or enemy-vs-enemy damage, and friendly NPCs
    (e.g. the trader) cannot be damaged by anyone.

    The actual block is enforced server-side in CombatService; this module is
    shared so the client can reuse `resolve` for UI (e.g. hitmarker suppression).
]=]

local CollectionService = game:GetService("CollectionService")
local Players = game:GetService("Players")

export type Faction = "Player" | "Friendly" | "Enemy"

local Factions = {}

Factions.EnemyTag = "EnemyNPC"
Factions.FriendlyTag = "FriendlyNPC"

-- Faction tags that mark a Model as a combatant. Iterated by NpcCollisionService.
Factions.NpcTags = { Factions.EnemyTag, Factions.FriendlyTag }

-- Default-deny hostility table: canDamageTable[attacker][target] == true ⇒ allowed.
local canDamageTable: { [Faction]: { [Faction]: boolean } } = {
	Player = { Enemy = true },
	Enemy = { Player = true },
	Friendly = {},
}

-- Resolve a Player or Model to its Faction, or nil if it is not a combatant
-- (nil actor, or a Model with neither faction tag and no backing player).
function Factions.resolve(actor: (Player | Model)?): Faction?
	if actor == nil then
		return nil
	end

	if actor:IsA("Player") then
		return "Player"
	end

	-- actor is a Model from here.
	local model = actor :: Model
	if Players:GetPlayerFromCharacter(model) then
		return "Player"
	end
	if CollectionService:HasTag(model, Factions.EnemyTag) then
		return "Enemy"
	end
	if CollectionService:HasTag(model, Factions.FriendlyTag) then
		return "Friendly"
	end
	return nil
end

-- True if `attacker` is permitted to deal combat damage to `target`.
function Factions.canDamage(attacker: Faction, target: Faction): boolean
	local row = canDamageTable[attacker]
	return row ~= nil and row[target] == true
end

return Factions

	humanoid: Humanoid,

Replace with:

-- True when `model` is the attacker's own character/model. Self-damage is exempt
-- from the faction block so a player's own AOE can still hurt them (governed by
-- the weapon's `ignore` list), while still blocking damage to OTHER same-faction
-- targets.
local function isSelf(attacker: (Player | Model)?, model: Model): boolean
	if attacker == nil then
		return false
	end
	if attacker:IsA("Player") then
		return attacker.Character == model
	end
	return attacker == model
end

function CombatService.ApplyToModel(
	model: Model,
	humanoid: Humanoid,
	amount: number,
	attackType: WeaponTypes.DamageType,
	attacker: (Player | Model)?,
	aoeVariant: ("Gas" | "Explosion")?
): boolean
	if amount <= 0 then
		return false
	end

	-- Target must be a combatant (a player's character or a faction-tagged NPC).
	local targetFaction = Factions.resolve(model)
	if not targetFaction then
		return false
	end

	-- Faction gate. nil attacker = environment (fall damage, hazards) → bypass.
	-- Self is exempt so own-AOE self-damage still lands.
	local attackerFaction = Factions.resolve(attacker)
	if
		attackerFaction
		and not isSelf(attacker, model)
		and not Factions.canDamage(attackerFaction, targetFaction)
	then
		return false
	end

	-- Route a player's character through HealthManager (HUD-tracked record).
	local targetPlayer = Players:GetPlayerFromCharacter(model)
	if targetPlayer then
		local sourcePlayer = if attacker ~= nil and attacker:IsA("Player") then attacker else nil
		HealthManager.ApplyDamage(targetPlayer, amount, attackType, sourcePlayer, aoeVariant)
		return true
	end

	-- Otherwise it is a faction-tagged NPC: damage the Humanoid directly.
	if humanoid.Health > 0 then
		humanoid:TakeDamage(amount)
	end
	return true
end

		if instance:IsA("Model") then

	end)

	CollectionService:GetInstanceRemovedSignal(tag):Connect(function(instance)
		if instance:IsA("Model") then

Note: watchModel/unwatchModel are already idempotent (watched[model] guard), so a Model carrying one faction tag is handled exactly once. The unwatchModel on removal is safe because a model carries a single faction tag — removing it stops its watch. (If a model ever held both tags, removing one would unwatch while the other tag still applies; not a supported configuration, and out of scope.)
