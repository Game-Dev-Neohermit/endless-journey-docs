Moonwave Documentation Site Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Replace the monolithic Project-Maintenance-Guide.md with a Moonwave-powered documentation site (narrative guides + auto-generated API reference for the cross-cutting/system modules), published to a separate public GitHub Pages repo via CI.

Architecture: Moonwave (Docusaurus under the hood) reads hand-written Markdown from a root docs/ folder for narrative pages, and extracts --[=[ ]=] doc-comments from src/ for the API section. The private repo holds all source (moonwave.toml, docs/, .moonwave/, annotated src/); a GitHub Action builds on push to main and deploys the static build/ output to a separate public docs repo's gh-pages branch, served via GitHub Pages.

Tech Stack: Moonwave CLI (npm), Docusaurus, GitHub Actions, peaceiris/actions-gh-pages, Luau (moonwave doc-comments).

Spec: docs/superpowers/specs/2026-06-05-moonwave-docs-site-design.md

Implementation deviations from spec (decided during planning):

  • Diagrams: use fenced ASCII box-diagrams instead of Mermaid (moonwave's simple build flow has no Mermaid hook). Mermaid remains a documented later option via a full-Docusaurus eject.
  • Edit/source links: keep them pointed at the private repo (owner has access; works for the primary audience) rather than disabling them.

Verification model: there is no test suite. Each task is verified by running moonwave dev/moonwave build and confirming the site builds and the expected pages/sidebar render. Treat a clean moonwave build (no broken-link/extraction errors) as the pass condition.

Annotation target paths (resolved):

  • Shared: src/ReplicatedStorage/SharedModules/{SoundManager/init,MotionMaster,PlacementSystem,SprintValidation,ShredderMath,ShredderResultCodes,GenericPoolInstance,GenericPoolObject,SpawnHelper,GrabHookVisuals,PlaceableActions,BindableCore,NotificationManager/init,Signals/init,Packets/init}.luau
  • Client: src/StarterPlayer/StarterPlayerScripts/{CameraController,CameraBoomController,JunkController,TrainClient,TrainFuelGuiController,ShredderClient}.client.luau, src/StarterPack/Grabhook/GrabHook.client.luau
  • Server: src/ServerScriptService/{JunkService,ShredderServer}.server.luau, src/ServerStorage/SharedModules/TrainFuelManager.luau

Phase 0 — Owner prerequisites (manual, one-time)​

These are performed by the repo owner outside the agent. The plan records them because later CI tasks depend on them.

Task 0: Provision the public docs repo + deploy key​

  • Step 1: Create the public docs repo

Create a new public repo Game-Dev-Neohermit/endless-journey-docs on GitHub (empty, no README needed). If a different name is chosen, update baseUrl/url in Task 2 and the external_repository in Task 24 to match.

  • Step 2: Generate an SSH deploy key

Run locally:

ssh-keygen -t ed25519 -C "endless-journey-docs-deploy" -f ./docs_deploy_key -N ""

This produces docs_deploy_key (private) and docs_deploy_key.pub (public). Do NOT commit these.

  • Step 3: Register the keys

  • In endless-journey-docs → Settings → Deploy keys → Add deploy key → paste docs_deploy_key.pub, check "Allow write access".

  • In Endless-Journey (private) → Settings → Secrets and variables → Actions → New repository secret → name DOCS_DEPLOY_KEY, value = full contents of docs_deploy_key (private).

  • Step 4: Enable Pages on the docs repo

In endless-journey-docs → Settings → Pages → Source = "Deploy from a branch", Branch = gh-pages / (root). (The branch won't exist until the first CI run; set this after Task 24's first successful deploy if the option is unavailable now.)

  • Step 5: Delete the local key copies
rm ./docs_deploy_key ./docs_deploy_key.pub

Phase 3 — API annotation (hybrid set)​

Annotation format (moonwave): a --[=[ ... ]=] block with @class Name above the module table, @within Name blocks above each documented function with @param name type -- desc and @return type -- desc, optional @tag, and a realm tag @server or @client for realm-specific modules. Example:

--[=[
  @class SoundManager
  @client
  Single entry point for all client audio (SFX, BGM, ambience).
]=]
local SoundManager = {}

--[=[
  Plays a 2D sound effect by name.
  @within SoundManager
  @param name string -- The SFX name from SoundConfig
  @param opts table? -- Optional overrides (volume, pitch)
  @tag audio
]=]
function SoundManager.PlaySFX(name, opts) end

For each module: add the @class block, then annotate its public functions (skip locals). After each task, run moonwave build and confirm the new class appears under the API sidebar with its functions. Annotations must not change runtime behavior — comments only.

Phase 4 — CI publish​

Task 21: GitHub Action — build and deploy to the public docs repo​

Files: Create .github/workflows/publish-docs.yml

  • Step 1: Create the workflow
name: publish-docs
on:
  push:
    branches: ["main"]
    paths:
      - "docs/**"
      - ".moonwave/**"
      - "moonwave.toml"
      - "src/**"
      - ".github/workflows/publish-docs.yml"
  workflow_dispatch:

jobs:
  publish:
    runs-on: ubuntu-latest
    name: Build and publish docs
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "22"
      - run: npm i -g moonwave@latest
      - name: Build site
        run: moonwave build --out-dir build
      - name: Strip internal working docs from the published output
        run: rm -rf build/superpowers build/audits
      - name: Deploy to docs repo
        uses: peaceiris/actions-gh-pages@v4
        with:
          deploy_key: ${{ secrets.DOCS_DEPLOY_KEY }}
          external_repository: Game-Dev-Neohermit/endless-journey-docs
          publish_branch: gh-pages
          publish_dir: ./build
          cname: ""
  • Step 2: Push to a branch and dry-run via workflow_dispatch

Commit on a feature branch first; trigger the workflow manually from the Actions tab (the workflow_dispatch event). Expected: build succeeds and peaceiris pushes to endless-journey-docs@gh-pages. If the deploy step fails on auth, re-check the DOCS_DEPLOY_KEY secret and the docs-repo deploy key (Task 0).

  • Step 3: Confirm the live site

After the docs repo Pages build finishes, open https://game-dev-neohermit.github.io/endless-journey-docs/ and confirm the Introduction and sidebar render. Confirm there is no superpowers/ or audits/ content reachable.

  • Step 4: Commit
git add .github/workflows/publish-docs.yml
git commit -m "ci(docs): build and deploy moonwave site to public docs repo"
