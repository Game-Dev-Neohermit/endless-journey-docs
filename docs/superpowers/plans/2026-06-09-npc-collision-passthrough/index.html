NPC Projectile Pass-Through & Tag Consolidation Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Execution model (decided): Implementation is done by Sonnet. After each task's code steps are complete and committed, an Opus reviewer inspects that task's diff against the task spec BEFORE the next task starts. The reviewer checks: correctness vs. the task's stated behavior, type consistency with earlier tasks, no placeholders, and adherence to project conventions (Janitor cleanup, CollisionGroups reuse, no ad-hoc collision-group registration, no rojo build/selene runs). If the reviewer flags issues, Sonnet fixes them and the reviewer re-checks before proceeding. The final Studio verification (Task 4) is the human's, as noted there.

Goal: Make thrown weapons and their client trajectory preview pass through NPCs (not just players) by placing "NPC"-tagged models' parts in the Character collision group, and consolidate the Damageable tag into that single NPC tag.

Architecture: A new server service (NpcCollisionService.server.luau, sibling to CharacterCollisionService) assigns the existing Character collision group to every BasePart of any "NPC"-tagged Model, keyed off CollectionService. CombatService switches its damage-gating tag from "Damageable" to "NPC", so one tag drives both projectile pass-through and damage routing. No new collision group, no matrix change, no client change (collision groups replicate to clients, so the WeaponProjectile raycast passes through automatically).

Tech Stack: Luau, Roblox CollectionService (GetTagged / GetInstanceAddedSignal / GetInstanceRemovedSignal), PhysicsService collision groups (via the existing CollisionGroups registrar), Janitor (howmanysmall/janitor).

Note on testing: This project has no automated test suite — verification happens in Roblox Studio (per CLAUDE.md). The "Verify" task below lists concrete Studio checks the developer performs after syncing with rojo serve. Do not run rojo build or selene (project preference).

Task 1: Create the NpcCollisionService bootstrap​

Files:

  • Create: src/ServerScriptService/NpcCollisionService.server.luau

This is a self-contained server bootstrap modeled on the existing CharacterCollisionService.server.luau (player equivalent). Because there is no unit-test harness, write the complete script, then verify in Studio (Task 4).

  • Step 1: Write the full script

Create src/ServerScriptService/NpcCollisionService.server.luau with exactly this content:

--!strict

--[=[
    @class NpcCollisionService
    @server
    Places every BasePart of every `"NPC"`-tagged Model into the `Character`
    collision group (see CollisionGroups), so thrown charges (`WeaponProjectile`)
    and dropped materials (`DroppedMaterial`) pass through NPCs exactly as they
    pass through players. This is the non-player sibling of
    CharacterCollisionService: players are handled by Players events there, NPCs
    are handled by the CollectionService `"NPC"` tag here.

    The same `"NPC"` tag also gates direct Humanoid damage in CombatService, so a
    single tag makes a Model both projectile-pass-through and damageable.

    Parts that stream in after tagging (R15 limbs, accessories) are caught via a
    per-model `DescendantAdded` connection owned by a per-model Janitor. The
    Janitor is torn down when the tag is removed OR the model is destroyed —
    `GetInstanceRemovedSignal` fires in both cases, so no separate `Destroying`
    backstop is needed.
]=]

local CollectionService = game:GetService("CollectionService")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local ServerStorage = game:GetService("ServerStorage")

local Janitor = require(ReplicatedStorage.Packages:WaitForChild("Janitor"))
local CollisionGroups = require(ServerStorage.SharedModules:WaitForChild("CollisionGroups"))

local NPC_TAG = "NPC"

-- One Janitor per watched model, holding that model's DescendantAdded connection.
local watched: { [Model]: Janitor.Janitor } = {}

local function assign(instance: Instance)
	if instance:IsA("BasePart") then
		instance.CollisionGroup = CollisionGroups.Character
	end
end

local function watchModel(model: Model)
	if watched[model] then
		return
	end

	for _, descendant in model:GetDescendants() do
		assign(descendant)
	end

	local janitor = Janitor.new()
	janitor:Add(model.DescendantAdded:Connect(assign), "Disconnect")
	watched[model] = janitor
end

local function unwatchModel(model: Model)
	local janitor = watched[model]
	if janitor then
		janitor:Destroy()
		watched[model] = nil
	end
end

-- Connect the add/remove signals BEFORE iterating existing tagged instances, so a
-- tag applied during startup is never missed.
CollectionService:GetInstanceAddedSignal(NPC_TAG):Connect(function(instance)
	if instance:IsA("Model") then
		watchModel(instance)
	end
end)

CollectionService:GetInstanceRemovedSignal(NPC_TAG):Connect(function(instance)
	if instance:IsA("Model") then
		unwatchModel(instance)
	end
end)

for _, instance in CollectionService:GetTagged(NPC_TAG) do
	if instance:IsA("Model") then
		watchModel(instance)
	end
end

Task 4: Studio verification​

Files: none (manual verification by the developer).

First, in Studio, re-tag the NPC: select Workspace.Dummy, open the Tag Editor, remove the Damageable tag and add the NPC tag. (If other models carry Damageable, re-tag them too.) Then sync with rojo serve and press Play.

  • Step 1: Trajectory arc passes through the NPC. Equip the Grenade and aim the camera so the arc crosses the Dummy's body. The green arc should pass through the Dummy and continue to world geometry behind/under it — it must not stop on the Dummy.

  • Step 2: Projectile passes through the NPC. Throw the Grenade through/at the Dummy. The thrown charge should pass through the Dummy's body and settle/detonate on world geometry, not bounce off the Dummy.

  • Step 3: NPC still takes damage. Confirm the Dummy's Humanoid loses health from the detonation AOE (damage routing now via the NPC tag). A Dummy with no NPC tag should take no damage — optional negative check.

  • Step 4: C4 behaves the same. Equip C4, repeat Steps 1-2 — arc and projectile pass through the Dummy; detonation damages it.

  • Step 5: No player regression. Confirm players still collide with each other and with world geometry as before (the Character group's other relationships are unchanged), and the Output window shows no errors on join, NPC tag add/remove, or NPC destruction.

If any check fails, fix the relevant module and re-verify before continuing.
