Perk Player Armor Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Wire the Player Armor personal perk so that ArmorReduction (already published by the Spec 1 dispatcher) reduces all incoming player damage at the single server damage chokepoint.

Architecture: One edited source file. HealthManager.applyDamageInternal reads the per-player PerkBuffs/<UserId>.ArmorReduction attribute via the module's existing perkBonus helper, clamps it to [0, 0.75], and scales amount by (1 - reduction) immediately before subtracting from the health record. No new modules, packets, GUI, or persistence. Two docs are updated in the same commit.

Tech Stack: Roblox / Luau / Rojo. Server module ServerStorage/SharedModules/HealthManager.luau. Reads ReplicatedStorage/PerkBuffs (written solely by PerkEffectsDispatcher, Spec 1).

Context the implementer must know​

  • Spec: docs/superpowers/specs/2026-06-12-perk-player-armor-design.md (Spec 3 of 5).
  • No automated test suite exists. Per CLAUDE.md, verification happens in Roblox Studio. There is no pytest/jest equivalent — "verify" steps below are Studio observations, not test commands. Do not add a test framework.
  • Do not run rojo build or selene — the user syncs live with Studio and has asked to skip both as verification steps.
  • The perkBonus helper already exists in HealthManager.luau (around line 75): 
    local function perkBonus(player: Player, key: string): number
        local folder = ReplicatedStorage:FindFirstChild("PerkBuffs")
        local holder = folder and folder:FindFirstChild(tostring(player.UserId))
        return holder and (holder:GetAttribute(key) :: number?) or 0
    end
    The spec's pseudocode does an inline FindFirstChild read; prefer the existing helper instead — it is the established pattern in this file (used for HPBonus, RegenBonus). Only the clamp is Armor-specific.
  • Insertion point: inside applyDamageInternal, after the existing amount clamp + if amount <= 0 then return end guard (current line ~117) and before record.Health = math.max(0, record.Health - amount) (current line ~134). Placing it after the amount <= 0 guard means a zero/negative hit short-circuits before the armor math, and the reduction applies to the already-validated amount.
  • Composition order is correct by construction: the attacker's DamageBonus (Spec 2) is applied in WeaponServer before HealthManager.ApplyDamage is called, so the amount arriving here is already post-attacker-bonus. Armor scales that final number: base * (1 + DamageBonus) * (1 - ArmorReduction).

Task 1: Apply ArmorReduction in the damage chokepoint​

Files:

  • Step 1: Read the current function body to confirm the anchor lines

Read src/ServerStorage/SharedModules/HealthManager.luau and locate, inside applyDamageInternal:

	-- Clamp to a sane positive range; no single hit can exceed the full health pool.
	local amount = math.clamp(info.Amount, 0, record.MaxHealth)
	if amount <= 0 then
		return
	end

…followed (after the commented "Future: per-type processing" block) by:

	record.Health = math.max(0, record.Health - amount)

These are the two anchors for the edit.

  • Step 2: Insert the armor mitigation

Insert the following block immediately before the record.Health = math.max(0, record.Health - amount) line (i.e. after the commented "Future: per-type processing" block):

	-- Player Armor perk (Spec 3): flat % incoming-damage reduction.
	-- Applied to the final, post-attacker-bonus `amount` at the single damage sink, so
	-- every attack category (Melee/Bullet/AOE/environment) is covered with no per-call-site
	-- edits. Read per hit (no caching) so mid-combat allocate/respec applies on the next hit.
	-- Hard-clamped to 0.75 so future additive sources can never stack to immunity.
	local reduction = math.clamp(perkBonus(player, "ArmorReduction"), 0, 0.75)
	amount = amount * (1 - reduction)

	record.Health = math.max(0, record.Health - amount)

Replace the existing bare record.Health = math.max(0, record.Health - amount) line with the block above (the block ends by re-stating that same line, so there must be exactly one such line afterward — do not leave a duplicate).

  • Step 3: Read back the edited region to confirm correctness

Read the edited region of src/ServerStorage/SharedModules/HealthManager.luau and confirm, in order:

  1. local amount = math.clamp(info.Amount, 0, record.MaxHealth)
  2. if amount <= 0 then return end
  3. (commented Future block)
  4. local reduction = math.clamp(perkBonus(player, "ArmorReduction"), 0, 0.75)

Confirm there is no duplicated record.Health = math.max(...) line and that perkBonus is the existing module-level helper (not a new inline FindFirstChild read).

  • Step 4: Verify in Studio (manual)

In Studio (Rojo synced), with a player who has the Armor perk allocated:

  • At Armor level 10 (PerLevel = 0.025 → ArmorReduction = 0.25), a 40-damage hit should reduce health by 30 (40 * (1 - 0.25)).
  • At Armor level 0, a 40-damage hit reduces health by 40 (unchanged behaviour).
  • Allocating/respeccing Armor mid-session changes the next hit's mitigation (no rejoin needed).
  • Environment/NPC damage routed through HealthManager.ApplyDamage is mitigated identically (defender-side, attacker-independent).

  • Step 2: Document the cap and multiplication order in docs/systems/perks.md

Immediately after the table's explanatory line:

Perks marked *(Spec N)* are declared in config and write attributes correctly but their downstream consumer is wired in a later spec. Perks marked *(deferred)* have no planned consumer yet.

add a new paragraph:

**Armor damage mitigation.** `HealthManager.applyDamageInternal` reads `ArmorReduction` per hit, clamps it to `[0, 0.75]` (so additive sources can never reach immunity), and scales the incoming `amount` by `(1 - reduction)` as the final step before subtracting from health. Because the attacker's `DamageBonus` is already applied upstream in `WeaponServer`, attacker bonus and defender armor multiply independently: `base * (1 + DamageBonus) * (1 - ArmorReduction)`. It covers all incoming damage (Melee/Bullet/AOE/environment/NPC) since it sits at the single damage sink.
  • Step 3: Update the ApplyDamage data-flow block in docs/systems/health.md

In the ASCII data-flow block, replace this section:

HealthManager.ApplyDamage (not yet called by any system):
  validate AttackType / AOEVariant
  clamp amount to [0, MaxHealth]
  record.Health -= amount
  record.LastDamageTime = os.clock()

  ──── HealthStateSync:FireClient ─────────────────────►

with (adds the armor step):

HealthManager.ApplyDamage:
  validate AttackType / AOEVariant
  clamp amount to [0, MaxHealth]
  amount *= (1 - clamp(ArmorReduction, 0, 0.75))   -- Player Armor perk (Spec 3)
  record.Health -= amount
  record.LastDamageTime = os.clock()
  humanoid.Health = record.Health
  ──── HealthStateSync:FireClient ─────────────────────►

(Note the leading "not yet called by any system" qualifier is dropped, since the perk path and combat callers now route through it.)
