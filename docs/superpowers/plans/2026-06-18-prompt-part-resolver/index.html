Prompt-Part Resolver Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Replace the client's direct-child prompt lookup with one shared, depth-agnostic PromptResolver used by all five client controllers and the server, so prompt wiring survives Model+PrimaryPart restructuring.

Architecture: A new ReplicatedStorage/SharedModules/PromptResolver.luau recursively finds a named BasePart (and its ProximityPrompt), with an optional poll-based wait for client-side replication. The server's ProximityValidation.FindPromptPart delegates to it (synchronous, no timeout); the five client controllers call it with a 10s timeout.

Tech Stack: Luau, Rojo, Roblox engine (CollectionService, ProximityPrompt, Janitor). No automated test suite — verification is in Roblox Studio after a Rojo sync.

Global Constraints​

  • Every Luau source file starts with --!strict; performance-sensitive ones also --!optimize 2 (match the file being edited).
  • All client audio goes through SoundManager; never create ad-hoc Sound instances (unaffected here, but do not regress TrainShieldController's SoundManager.PlaySFX("ShieldRecharge")).
  • Connections/instances are owned by a Janitor; never hand-roll connection arrays (the controllers already use Janitor — preserve it).
  • Do not run rojo build or selene as verification steps; the user syncs live with Studio.
  • Commits use the Claude Haiku model; never use @'...'@ here-string syntax in -m args.
  • Prompt-part name per system comes from its Config module (TrainConfig.PROMPT_PART_NAME = "ProxPromptPart", TrainConfig.SHIELD_PROMPT_PART_NAME, TechTreeConfig.PROMPT_PART_NAME, WorkbenchConfig.PROMPT_PART_NAME, CannonConfig.MOUNT_PROMPT_PART_NAME). Never hardcode the name.
  • Client wait timeout is 10 seconds (preserves current WaitForChild(name, 10) behavior).

Task 1: Create the PromptResolver shared module​

Files:

  • Create: src/ReplicatedStorage/SharedModules/PromptResolver.luau

Interfaces:

  • Consumes: nothing (leaf module, engine APIs only).

  • Produces:

    • PromptResolver.FindPart(root: Instance, partName: string, timeout: number?): BasePart?
    • PromptResolver.Find(root: Instance, partName: string, timeout: number?): (BasePart?, ProximityPrompt?)
    • Semantics: recursive FindFirstChild(partName, true); timeout nil/0 → single synchronous check (no yield); timeout > 0 → poll via task.wait() until found or deadline. Find additionally returns part:FindFirstChildWhichIsA("ProximityPrompt"), or (nil, nil) if either is missing.

  • Step 1: Write the module

--!strict
--!optimize 2

--[=[
	@class PromptResolver
	Shared, depth-agnostic lookup for interaction prompts. Finds a named `BasePart`
	anywhere under a tagged object (recursively) and the `ProximityPrompt` hosted on
	it. Used by both the server (anti-exploit validation, synchronous) and client
	controllers (prompt wiring, waits for replication). Replaces per-controller
	`WaitForChild` lookups that only matched a *direct* child and broke when props
	were nested inside Models with a PrimaryPart.
]=]
local PromptResolver = {}

--[=[
	@within PromptResolver
	Recursive lookup of the BasePart named `partName` under `root`. With `timeout`
	nil or <= 0, performs a single synchronous check (server). With `timeout` > 0,
	polls each frame until found or the deadline elapses (client replication wait —
	there is no recursive `WaitForChild`).
]=]
function PromptResolver.FindPart(root: Instance, partName: string, timeout: number?): BasePart?
	local budget = timeout or 0
	local deadline = os.clock() + budget
	while true do
		local part = root:FindFirstChild(partName, true)
		if part and part:IsA("BasePart") then
			return part :: BasePart
		end
		if os.clock() >= deadline then
			return nil
		end
		task.wait()
	end
end

--[=[
	@within PromptResolver
	Finds the prompt BasePart named `partName` under `root` and the ProximityPrompt
	parented to it. Returns `(nil, nil)` if either is missing within `timeout`.
	Prompt is matched by class (any name), mirroring server semantics.
]=]
function PromptResolver.Find(root: Instance, partName: string, timeout: number?): (BasePart?, ProximityPrompt?)
	local budget = timeout or 0
	local deadline = os.clock() + budget
	while true do
		local part = root:FindFirstChild(partName, true)
		if part and part:IsA("BasePart") then
			local prompt = part:FindFirstChildWhichIsA("ProximityPrompt")
			if prompt then
				return part :: BasePart, prompt
			end
		end
		if os.clock() >= deadline then
			return nil, nil
		end
		task.wait()
	end
end

return PromptResolver
