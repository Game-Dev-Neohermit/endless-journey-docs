Placement Smart Cancel Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Add a build-mode cancel action (key X + the existing on-screen Cancel button) that unequips a freshly-equipped placeable tool, or reverts a moved item to its original spot when that spot is still free.

Architecture: The server remembers the spot a placed item came from when a player presses Move (PlaceableRevertStore). On cancel the client always asks the server to revert via a new RequestPlacementRevert packet; the server re-validates the stored spot and re-places the item if free, otherwise the client unequips the tool. No client-side move/fresh tracking.

Tech Stack: Luau, Rojo, the project's Packet networking library, PlacementSystem shared module.

Global Constraints​

  • No automated test suite — verification is in Roblox Studio by the user. Do not run selene, rojo build, or attempt automated playtesting.
  • All client↔server traffic goes through Packets; never raw RemoteEvents.
  • Enum.KeyCode.Escape is reserved by Roblox for the in-game menu — the cancel key is X, stored in PlacementConfig.CancelKey.
  • Server stays authoritative: revert is re-validated server-side (collision); the stored CFrame is server-owned (no client CFrame, no distance cap on revert).
  • Files synced live to Studio; the user verifies each task.
  • Commits: per project convention use the Haiku model for the commit, plain -m (no @'...'@ here-strings).

Task 1: Revert store module + revert packet​

Foundation: a server-only store for the remembered spot, and the network channel the client will call. Neither has behavior on its own; they are wired up in later tasks.

Files:

  • Create: src/ServerStorage/SharedModules/PlaceableRevertStore.luau
  • Modify: src/ReplicatedStorage/SharedModules/Packets/init.luau (add packet + export)

Interfaces:

  • Produces: PlaceableRevertStore.Set(player: Player, data: RevertData), PlaceableRevertStore.Get(player: Player): RevertData?, PlaceableRevertStore.Clear(player: Player) where RevertData = { cframe: CFrame, placeableName: string, tool: Tool }.

  • Produces: Packets.RequestPlacementRevert — RemoteFunction-style packet, no payload, returns boolean (reverted). Client call: local reverted = RequestPlacementRevert:Fire(). Server: RequestPlacementRevert.OnServerInvoke = function(player) ... return boolean end.

  • Step 1: Create PlaceableRevertStore.luau

--!strict
--!optimize 2

-- ┌─────────────────────────────────────────────────────────────────────────┐
-- │  PlaceableRevertStore  (ModuleScript — ServerStorage/SharedModules)     │
-- │                                                                         │
-- │  Server-only, in-memory record of the spot a placed item came from      │
-- │  when a player pressed Move. Lets the build-mode cancel action revert   │
-- │  a moved item back to its original CFrame if that spot is still free.   │
-- │                                                                         │
-- │  Written by PlaceableActionsServer (on Move); read/consumed by          │
-- │  PlacementServer (on RequestPlacementRevert / PlaceItem / player leave).│
-- └─────────────────────────────────────────────────────────────────────────┘

local PlaceableRevertStore = {}

export type RevertData = {
	cframe: CFrame,
	placeableName: string,
	tool: Tool,
}

-- player → the spot their currently-held moved item came from
local pending: { [Player]: RevertData } = {}

function PlaceableRevertStore.Set(player: Player, data: RevertData)
	pending[player] = data
end

function PlaceableRevertStore.Get(player: Player): RevertData?
	return pending[player]
end

function PlaceableRevertStore.Clear(player: Player)
	pending[player] = nil
end

return PlaceableRevertStore

-- ─────────────────────────────────────────────────────────────────
-- Revert (build-mode cancel of a moved item)
-- ─────────────────────────────────────────────────────────────────

RequestPlacementRevert.OnServerInvoke = function(player: Player): boolean
	local data = PlaceableRevertStore.Get(player)
	if not data then
		-- Fresh placement session (no Move) — nothing to revert.
		return false
	end

	local character = player.Character
	if not character then
		PlaceableRevertStore.Clear(player)
		return false
	end

	-- Identity guard: the equipped tool must be the exact instance granted by
	-- the Move. Catches dropped / swapped / already-placed tools.
	local equipped = character:FindFirstChildOfClass("Tool")
	if equipped ~= data.tool or data.tool.Parent ~= character then
		PlaceableRevertStore.Clear(player)
		return false
	end

	local template = placeableItems:FindFirstChild(data.placeableName)
	if not template or not template:IsA("Model") then
		PlaceableRevertStore.Clear(player)
		return false
	end

	-- Re-validate the stored spot is still free (server owns the CFrame, so no
	-- distance cap — that is the point of server-side revert state).
	local req = PlacementSystem.new("BuildArea", 2)
	req.IsBuildMode = true
	req:SetGhostModel(template, ServerStorage)

	local boxCFrame, boxSize = req:GetCollisionBox(data.cframe)
	local filter = req:BuildObstructionFilter(nil)
	if not req:CheckValidity(boxCFrame, boxSize, filter) then
		-- Spot occupied — caller will unequip instead.
		req:Destroy()
		PlaceableRevertStore.Clear(player)
		return false
	end

	-- Re-place the item exactly where it was.
	local placed = (template :: Model):Clone()
	finalizeModel(placed)
	placed:PivotTo(data.cframe)
	placed.Parent = req.PlacedObjectsFolder
	placed:SetAttribute("PlaceableName", data.placeableName)

	data.tool:Destroy()
	req:Destroy()
	PlaceableRevertStore.Clear(player)
	return true
end

Task 5: Unified client cancel (revert-or-unequip)​

Replace doCancel with cancelPlacement: exit build-mode visuals immediately, ask the server to revert, and unequip the tool to the Backpack when the server did not revert. This makes the whole feature live.

Files:

  • Modify: src/StarterPlayer/StarterPlayerScripts/PlacementClient.client.luau

Interfaces:

  • Step 1: Bind the revert packet

  • Step 2: Add a cancel in-flight guard to module state

In the rate-limit / ghost state block (near local isGhostLocked = false), add:

  • Step 3: Replace doCancel with cancelPlacement

Replace the entire existing doCancel function:

local function doCancel()
	if not currentTool then
		return
	end
	currentTool = nil
	placement:SetBuildMode(false)
	isGhostLocked = false
	Signals.OnGhostLockChanged:Fire(false)
	ClientToggleGhost:Fire(false, nil)
	setShiftLockGate(false)
	Signals.OnBuildModeChanged:Fire(false)
end

with:

local function cancelPlacement()
	if not placement.IsBuildMode or not currentTool then
		return
	end
	if cancelInFlight then
		return
	end
	cancelInFlight = true

	-- Snappy local exit of build-mode visuals (mirrors the old doCancel).
	currentTool = nil
	placement:SetBuildMode(false)
	isGhostLocked = false
	Signals.OnGhostLockChanged:Fire(false)
	ClientToggleGhost:Fire(false, nil)
	setShiftLockGate(false)
	Signals.OnBuildModeChanged:Fire(false)

	-- Ask the server to revert a moved item to its original spot. If it did not
	-- (fresh session, or spot now occupied), unequip the tool to the Backpack.
	task.spawn(function()
		local reverted = RequestPlacementRevert:Fire()
		cancelInFlight = false
		if not reverted then
			local character = localPlayer.Character
			local humanoid = character and character:FindFirstChildWhichIsA("Humanoid")
			if humanoid then
				(humanoid :: Humanoid):UnequipTools()
			end
		end
		-- If reverted, the server destroyed the tool; the character's
		-- ChildRemoved listener runs unequipTool (idempotent — currentTool is nil).
	end)
end
  • Step 4: Point the cancel signal at the new function

Replace:

with:

Signals.RequestPlacementCancel:Connect(cancelPlacement)
