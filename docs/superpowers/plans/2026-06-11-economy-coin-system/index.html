Economy / Coin System Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Build a server-authoritative coin wallet, persisted via a dedicated PlayerCoins ProfileStore profile and shared across the lobby and gameplay places, exposing an AddCoins/DeductCoins/GetCoins API for future earners and sinks.

Architecture: A file-for-file mirror of the shipped XP/Level system. CoinManager (ServerStorage) owns the ProfileStore lifecycle, the wallet API, and per-player replication; a thin place-agnostic CoinSystemLoader calls CoinManager.Initialize(); one CoinStateSync packet replicates the balance; CoinController (client) re-fires Signals.OnCoinsChanged. Earners (session completion, daily/weekly challenges) and sinks (shop) are out of scope and call the API.

Tech Stack: Luau, Rojo, ProfileStore (ServerStorage/SharedModules/ProfileStore), the project's Packets (bytenet-style) and Signals (in-process bus) modules.

Reference spec: docs/superpowers/specs/2026-06-11-economy-coin-system-design.md

Conventions for this plan (read first)​

  • No automated tests in this repo. CLAUDE.md: "There is no automated test suite; verification happens in Studio." Each task's verification is a Studio command-bar snippet (run server-side via the Run ▸ command bar, "Server" context) plus an observation. These replace the usual failing-test/passing-test steps.

  • After all code tasks, Task 7 updates the docs (networking-map.md, signals-map.md, new economy.md) in a single commit, per CLAUDE.md's same-commit docs rule.

Task 4: CoinManager (server authority)​

Files:

  • Create: src/ServerStorage/SharedModules/CoinManager.luau

Depends on Task 1 (CoinConfig) and Task 2 (CoinStateSync packet).

  • Step 1: Create the manager module
--!strict

--[=[
	@class CoinManager
	@server
	Place-agnostic authority for the player coin wallet. Owns the PlayerCoins
	ProfileStore profile lifecycle (one session per player, key = UserId), the
	earn/spend/read API, and per-player replication via `CoinStateSync`.

	Runs in BOTH the lobby and gameplay places. Coin *sources* (gameplay-session
	completion, daily/weekly challenges) and *sinks* (shop) are SEPARATE systems
	that call `AddCoins` / `DeductCoins`; they are not part of this module.

	Cross-place: `STORE_NAME` + `tostring(UserId)` key are identical in every
	place of the universe, so the same DataStore record is shared. ProfileStore
	session-locking serializes the lobby↔gameplay teleport handoff automatically.
]=]

local Players = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local ServerStorage = game:GetService("ServerStorage")

local SharedModules = ReplicatedStorage.SharedModules
local CoinConfig = require(SharedModules.Configs:WaitForChild("CoinConfig"))
local Packets = require(SharedModules:WaitForChild("Packets"))
local ProfileStore = require(ServerStorage.SharedModules:WaitForChild("ProfileStore"))

local PROFILE_TEMPLATE = {
	Coins = CoinConfig.STARTING_BALANCE,
}

local PlayerStore = ProfileStore.New(CoinConfig.STORE_NAME, PROFILE_TEMPLATE)
local Profiles: { [Player]: any } = {}

local CoinManager = {}
local initialized = false

-- Fire the current balance to one player.
local function replicate(player: Player)
	local profile = Profiles[player]
	if not profile then
		return
	end
	Packets.CoinStateSync:FireClient(player, profile.Data.Coins)
end

--[=[
	@within CoinManager
	Return the player's current coin balance, or 0 if the profile is not loaded.
]=]
function CoinManager.GetCoins(player: Player): number
	local profile = Profiles[player]
	if not profile then
		return 0
	end
	return profile.Data.Coins
end

--[=[
	@within CoinManager
	Award `amount` coins to a single player. No-op if `amount <= 0` or the
	profile is not loaded. Clamps the new balance to `CoinConfig.MAX_BALANCE`,
	then replicates. `reason` is an optional source tag recorded in the server
	log only (e.g. "DailyChallenge", "SessionComplete").
]=]
function CoinManager.AddCoins(player: Player, amount: number, reason: string?)
	if amount <= 0 then
		return
	end
	local profile = Profiles[player]
	if not profile then
		return
	end
	local newBalance = math.min(profile.Data.Coins + amount, CoinConfig.MAX_BALANCE)
	profile.Data.Coins = newBalance
	if reason then
		print(("[CoinManager] +%d coins to %s (%s) → %d"):format(amount, player.Name, reason, newBalance))
	end
	replicate(player)
end

--[=[
	@within CoinManager
	Atomically deduct `amount` coins from a single player. Returns `true` on
	success. Returns `false` with **no mutation** if `amount <= 0`, the profile
	is not loaded, or the balance is insufficient. This is the contract a future
	shop relies on.
]=]
function CoinManager.DeductCoins(player: Player, amount: number): boolean
	if amount <= 0 then
		return false
	end
	local profile = Profiles[player]
	if not profile then
		return false
	end
	if profile.Data.Coins < amount then
		return false
	end
	profile.Data.Coins -= amount
	replicate(player)
	return true
end

local function onPlayerAdded(player: Player)
	local profile = PlayerStore:StartSessionAsync(tostring(player.UserId), {
		Cancel = function()
			return player.Parent ~= Players
		end,
	})

	if profile == nil then
		player:Kick("Coin profile failed to load — please rejoin.")
		return
	end

	profile:AddUserId(player.UserId) -- GDPR compliance
	profile:Reconcile() -- fill missing fields from PROFILE_TEMPLATE

	profile.OnSessionEnd:Connect(function()
		Profiles[player] = nil
		player:Kick("Coin profile session ended — please rejoin.")
	end)

	if player.Parent == Players then
		Profiles[player] = profile
		replicate(player)
	else
		-- Player left before the session started.
		profile:EndSession()
	end
end

--[=[
	@within CoinManager
	Wire up the profile lifecycle. Call exactly once per server (from a loader).
]=]
function CoinManager.Initialize()
	if initialized then
		return
	end
	initialized = true
	-- Players who joined before this script ran.
	for _, player in Players:GetPlayers() do
		task.spawn(onPlayerAdded, player)
	end

	Players.PlayerAdded:Connect(onPlayerAdded)

	Players.PlayerRemoving:Connect(function(player)
		local profile = Profiles[player]
		if profile then
			profile:EndSession()
		end
	end)
end

return CoinManager

# Economy (Coins)

Server-authoritative coin wallet persisted with **ProfileStore**, in a profile
separate from XP. The balance is shared across the lobby and gameplay places.

## Data model

The `PlayerCoins` profile stores a single value, `Coins`. `STORE_NAME`
(`"PlayerCoins"`) and the `UserId` key are identical in every place of the
universe, so the lobby and gameplay share one DataStore record; ProfileStore
session-locking serializes the teleport handoff. All bounds live in
`Configs/CoinConfig.luau` (`STARTING_BALANCE`, `MAX_BALANCE`).

## API (server-authoritative)

`CoinManager` (ServerStorage) is the sole authority:

- `CoinManager.GetCoins(player): number` — current balance, `0` if no profile.
- `CoinManager.AddCoins(player, amount, reason?)` — award coins; no-op if
  `amount <= 0` or no profile; clamps to `MAX_BALANCE`. `reason` is an optional
  source tag logged server-side.
- `CoinManager.DeductCoins(player, amount): boolean` — atomic spend; returns
  `false` with no mutation on `amount <= 0`, missing profile, or insufficient
  funds.
- `CoinManager.Initialize()` — wires the profile lifecycle; called once by
  `CoinSystemLoader` in both places.

## Replication

Every successful mutation fires `CoinStateSync (balance: U32)` to the owning
client. `CoinController` re-fires it as `Signals.OnCoinsChanged(balance)` for a
future coin HUD. There is no client→server packet — earning and spending are
fully server-driven.

## Out of scope (future work)

Earning sources (gameplay-session completion, daily/weekly challenges), sinks
(shop + purchase packet), and the coin HUD are separate systems that call the
`CoinManager` API; they are not part of the wallet module.

Final verification (after all tasks)​

Run a full Play Solo session and confirm, in order:

  1. Fresh balance — a new player's GetCoins returns STARTING_BALANCE (0).
  2. Earn — AddCoins(p, N, "test") raises the balance by N and the client OnCoinsChanged fires with the new total.
  3. Guarded spend — DeductCoins succeeds when funded (returns true, balance drops) and fails cleanly when underfunded (returns false, balance unchanged).
  4. Clamp — AddCoins(p, CoinConfig.MAX_BALANCE + 1000) caps at MAX_BALANCE.
  5. Persistence — stop, re-enter Play Solo, and confirm the balance restored (Studio uses a mock DataStore; the value persists within the session's store). For real persistence, verify in a published place test.
  6. Cross-place (if feasible) — teleport lobby↔gameplay and confirm the same balance and a clean session handoff (no double-lock kick).

All six pass ⇒ the wallet module is complete and the earner/shop systems can build on CoinManager.
