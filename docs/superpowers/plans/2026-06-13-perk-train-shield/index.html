Train Shield + Train Shield Perk Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Build the train's global, server-authoritative shield pool (the damageable defensive entity the Tech Tree's MaxHP buff and the TrainShield perk have been feeding into the void), recharged by players feeding Energy items at a console, depleting to a unified game over.

Architecture: Mirrors the fuel system's server-authoritative, event-driven pattern. A new TrainShieldManager (ServerStorage) owns global currentShield/maxShield, exposes ApplyDamage (the single damage sink for future combat) and RechargeFromEnergy (mirrors ReqRefuelTrain), and replicates via a new TrainShieldSync packet. Max capacity = (BASE_SHIELD + TechTreeBuffs.MaxHP) * (1 + PartyPerkBuffs.TrainShieldBonus) — Tech additive, perk multiplicative — recomputed live while preserving the fill ratio. Two helpers currently private to TrainFuelManager (Energy-tool scanning, proximity validation) are extracted to shared modules so both systems use one copy, and the fuel game-over is unified into a shared TrainGameOver authority so "fuel stalled" and "shield depleted" funnel through one idempotent trigger.

Tech Stack: Luau, Rojo, Roblox engine, Packets (typed networking), Signals (in-process bus), Janitor (cleanup), SoundManager, CollectionService.

Testing & verification note​

This project has no automated test suite — verification happens in Studio (per CLAUDE.md), and the workflow skips selene, skips rojo build, and skips agent-driven playtesting (per saved preferences). Each task therefore replaces the skill's pytest/TDD loop with: implement → check the stated Acceptance criteria (code-level, read by the implementer) → commit. Two STUDIO CHECKPOINT blocks mark points where the user runs a live Studio playtest before continuing. The user syncs src/ into Studio live via rojo serve, so no build step is needed.

The spec being implemented is docs/superpowers/specs/2026-06-12-perk-train-shield-design.md.

Task 4: Extract EnergyToolHelper​

Pull the Energy-tool detection/consumption that is currently private to TrainFuelManager into a shared module. This task creates the module; Task 7 refactors the fuel manager to use it.

Files:

  • Create: src/ServerStorage/SharedModules/EnergyToolHelper.luau

  • Step 1: Write the module — exact copies of the fuel manager's getEnergyTier/gatherEnergyTools plus a ConsumeTool that folds in the fuel manager's unequip-then-destroy step:

--!strict
--!optimize 2

--[=[
	@class EnergyToolHelper
	@server
	Shared server-side helpers for identifying and consuming "Energy" Tool items
	from a player's backpack/character. Used by both the train fuel and train
	shield recharge flows so the detection/consumption logic lives in one place.

	An Energy tool is a `Tool` whose `PrimaryPart` carries attribute `Type == "Energy"`
	and a numeric `Tier` (1..5).
]=]
local EnergyToolHelper = {}

local ENERGY_TYPE = "Energy"

--[=[
	@within EnergyToolHelper
	Returns the numeric `Tier` of an Energy tool, or `nil` if `tool` is not a
	valid Energy tool.
]=]
function EnergyToolHelper.GetEnergyTier(tool: Instance): number?
	if not tool:IsA("Tool") then
		return nil
	end
	local pp = (tool :: Tool).PrimaryPart
	if not pp then
		return nil
	end
	if pp:GetAttribute("Type") ~= ENERGY_TYPE then
		return nil
	end
	local tier = pp:GetAttribute("Tier")
	if typeof(tier) ~= "number" then
		return nil
	end
	return tier :: number
end

--[=[
	@within EnergyToolHelper
	Collects every Energy tool the player currently holds — both in their
	Backpack and the one (if any) equipped on their character.
]=]
function EnergyToolHelper.GatherEnergyTools(player: Player): { Tool }
	local result: { Tool } = {}
	for _, item in player.Backpack:GetChildren() do
		if EnergyToolHelper.GetEnergyTier(item) then
			table.insert(result, item :: Tool)
		end
	end
	local character = player.Character
	if character then
		local equipped = character:FindFirstChildWhichIsA("Tool")
		if equipped and EnergyToolHelper.GetEnergyTier(equipped) then
			table.insert(result, equipped)
		end
	end
	return result
end

--[=[
	@within EnergyToolHelper
	Consumes a single Energy tool: if it is the equipped tool, unequips it first
	(so the character isn't left holding a destroyed handle), then destroys it.
]=]
function EnergyToolHelper.ConsumeTool(player: Player, tool: Tool)
	local character = player.Character
	if character and tool.Parent == character then
		local humanoid = character:FindFirstChildWhichIsA("Humanoid") :: Humanoid?
		if humanoid then
			humanoid:UnequipTools()
		end
	end
	tool:Destroy()
end

return EnergyToolHelper

Acceptance: Module returns a table with GetEnergyTier, GatherEnergyTools, ConsumeTool. Logic is byte-for-byte equivalent to TrainFuelManager's current private versions (same ENERGY_TYPE, same backpack+equipped scan, same unequip-then-destroy order).

Task 5: Extract ProximityValidation​

Pull the prompt-part lookup and proximity check that are private to TrainFuelManager into a shared module. The hardcoded TrainConfig.PROXIMITY_TOLERANCE becomes an explicit tolerance parameter so each caller passes its own.

Files:

  • Create: src/ServerStorage/SharedModules/ProximityValidation.luau

  • Step 1: Write the module:

--!strict
--!optimize 2

--[=[
	@class ProximityValidation
	@server
	Shared server-side anti-exploit helpers for prompt-based interactions:
	locating the BasePart that hosts a named ProximityPrompt, and checking that a
	player is actually within range of it. Distance uses the prompt's authored
	`MaxActivationDistance` plus a caller-supplied server tolerance, so the
	prompt's own distance stays the source of truth.
]=]
local ProximityValidation = {}

--[=[
	@within ProximityValidation
	Finds the descendant BasePart named `partName` under `root` and the
	ProximityPrompt parented to it. Returns `(nil, nil)` if either is missing.
]=]
function ProximityValidation.FindPromptPart(root: Instance, partName: string): (BasePart?, ProximityPrompt?)
	local part = root:FindFirstChild(partName, true)
	if not (part and part:IsA("BasePart")) then
		return nil, nil
	end
	local prompt = part:FindFirstChildWhichIsA("ProximityPrompt")
	return part :: BasePart, prompt
end

--[=[
	@within ProximityValidation
	True if the player's HumanoidRootPart is within
	`prompt.MaxActivationDistance + tolerance` of `promptPart`.
]=]
function ProximityValidation.IsPlayerNear(player: Player, promptPart: BasePart, prompt: ProximityPrompt, tolerance: number): boolean
	local character = player.Character
	local hrp = character and character:FindFirstChild("HumanoidRootPart") :: BasePart?
	if not hrp then
		return false
	end
	local limit = prompt.MaxActivationDistance + tolerance
	return (hrp.Position - promptPart.Position).Magnitude <= limit
end

return ProximityValidation

Acceptance: Module returns FindPromptPart and IsPlayerNear. IsPlayerNear takes tolerance as a 4th argument (the fuel manager will pass TrainConfig.PROXIMITY_TOLERANCE). Logic equivalent to the fuel manager's current private versions.

Task 6: Extract TrainGameOver​

Unify the train's game-over into one idempotent authority. Today TrainFuelManager.onGameOver is a local print stub; this module wraps that same stub behind a single fired flag so both fuel and shield funnel through it.

Files:

  • Create: src/ServerStorage/SharedModules/TrainGameOver.luau

  • Step 1: Write the module:

--!strict
--!optimize 2

--[=[
	@class TrainGameOver
	@server
	Single idempotent game-over authority for the train. Both triggers — fuel
	stalled past the grace timer (`TrainFuelManager`) and shield depleted
	(`TrainShieldManager`) — funnel through `Trigger()`, which fires the
	game-over sequence exactly once per round. `Reset()` re-arms it for a future
	round restart (not yet wired — round restart is out of scope).
]=]
local TrainGameOver = {}

local fired = false

--[=[
	@within TrainGameOver
	Whether the game-over sequence has already fired this round.
]=]
function TrainGameOver.HasFired(): boolean
	return fired
end

--[=[
	@within TrainGameOver
	Fires the game-over sequence once. Subsequent calls (e.g. shield depleting
	during a fuel stall, or vice versa) are no-ops.
]=]
function TrainGameOver.Trigger(reason: string?)
	if fired then
		return
	end
	fired = true
	print(("[TrainGameOver] GAME OVER — %s"):format(reason or "train lost"))
	-- TODO: real game-over mechanic (round reset / respawn / UI). Placeholder for now,
	-- matching the previous TrainFuelManager.onGameOver stub.
end

--[=[
	@within TrainGameOver
	Re-arms the game-over flag for a new round.
]=]
function TrainGameOver.Reset()
	fired = false
end

return TrainGameOver

Acceptance: TrainGameOver.Trigger() prints once and flips HasFired() to true; a second Trigger() is silent. Reset() returns HasFired() to false.

Task 11: TrainShieldManager — server authority​

The core module: global shield state, max formula, damage sink, Energy recharge, ratio-preserving buff updates, pre-game freeze.

Files:

  • Create: src/ServerStorage/SharedModules/TrainShieldManager.luau

  • Step 1: Write the module:

--!strict
--!optimize 2

-- ┌─────────────────────────────────────────────────────────────────────────┐
-- │  TrainShieldManager                                                      │
-- │  Authoritative, server-wide (global) train shield pool.                  │
-- │                                                                          │
-- │  Modeled on TrainFuelManager but simpler: the shield has no continuous   │
-- │  drain (regen off by default), so there is no per-frame loop and no      │
-- │  extrapolation — state changes only on damage, recharge, or a buff       │
-- │  change, and each change broadcasts a TrainShieldSync snapshot.          │
-- │                                                                          │
-- │  Max capacity = (BASE_SHIELD + TechTreeBuffs.MaxHP) * (1 + TrainShieldBonus):
-- │  Tech Tree additive, party perk multiplicative. Buff changes recompute   │
-- │  max while preserving the current fill ratio. Depletion → unified        │
-- │  game over via TrainGameOver. Recharge mirrors ReqRefuelTrain.           │
-- └─────────────────────────────────────────────────────────────────────────┘

local Players = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local CollectionService = game:GetService("CollectionService")
local ServerStorage = game:GetService("ServerStorage")

local Shared = ReplicatedStorage.SharedModules
local Configs = Shared.Configs
local TrainConfig = require(Configs:WaitForChild("TrainConfig"))
local TrainResultCodes = require(Shared:WaitForChild("TrainResultCodes"))
local Packets = require(Shared:WaitForChild("Packets"))
local Signals = require(Shared:WaitForChild("Signals"))

local ServerShared = ServerStorage.SharedModules
local EnergyToolHelper = require(ServerShared:WaitForChild("EnergyToolHelper"))
local ProximityValidation = require(ServerShared:WaitForChild("ProximityValidation"))
local TrainGameOver = require(ServerShared:WaitForChild("TrainGameOver"))

--[=[
	@class TrainShieldManager
	@server

	Global, server-authoritative module that manages the train's shield pool — a
	scalar in `0 .. maxShield`, where `maxShield` is derived from a base capacity
	plus the Tech Tree's additive `MaxHP` buff, scaled by the party `TrainShield`
	perk. The shield is the entity enemy AI / hazards will damage (future combat)
	via `ApplyDamage`, and players restore it by feeding Energy tools at a tagged
	console (`RechargeFromEnergy`). Reaching 0 triggers a unified game over.
]=]
local TrainShieldManager = {}

-- [[ STATE ]]
local currentShield = 0
local maxShield = 0
local hasStarted = false -- mirrors the fuel system's pre-game freeze
local isRecharging = false -- serializes concurrent recharge requests

-- [[ BUFF READS ]]
local function getBuffMaxHP(): number
	local techFolder = ReplicatedStorage:FindFirstChild("TechTreeBuffs")
	return (techFolder and techFolder:GetAttribute("MaxHP") :: number?) or 0
end

local function getShieldBonus(): number
	local partyFolder = ReplicatedStorage:FindFirstChild("PartyPerkBuffs")
	return (partyFolder and partyFolder:GetAttribute("TrainShieldBonus") :: number?) or 0
end

-- Tech Tree additive, perk multiplicative, composed in that order.
local function computeMax(): number
	return (TrainConfig.BASE_SHIELD + getBuffMaxHP()) * (1 + getShieldBonus())
end

local function broadcast()
	Packets.TrainShieldSync:Fire(currentShield, maxShield)
end

-- Recompute max, preserving the current fill ratio so a buff that raises max
-- doesn't fully recharge and a respec/leave that lowers it doesn't instantly deplete.
local function recomputeMax()
	local oldMax = maxShield
	local ratio = oldMax > 0 and (currentShield / oldMax) or 1
	maxShield = computeMax()
	currentShield = math.clamp(math.floor(ratio * maxShield + 0.5), 0, maxShield)
	broadcast()
end

-- [[ PUBLIC: STATE ]]

--[=[
	@within TrainShieldManager
	Returns `(currentShield, maxShield)`.
]=]
function TrainShieldManager.GetShield(): (number, number)
	return currentShield, maxShield
end

--[=[
	@within TrainShieldManager
	The single damage sink — future enemy AI / hazards call this. Clamps the
	shield at 0 and, on reaching 0, triggers the unified game over (once). No-op
	before the round is live (pre-game freeze) or after game over has fired.
]=]
function TrainShieldManager.ApplyDamage(amount: number, _source: any?)
	if not hasStarted or TrainGameOver.HasFired() then
		return
	end
	if type(amount) ~= "number" or amount ~= amount or amount <= 0 then
		return
	end
	currentShield = math.max(0, currentShield - amount)
	broadcast()
	if currentShield <= 0 then
		TrainGameOver.Trigger("shield depleted")
	end
end

-- [[ RECHARGE ]]
-- Mirrors TrainFuelManager.handleRefuel: serialize, validate the tagged console
-- + proximity, then consume Energy tools smallest-first up to maxShield.
local function handleRecharge(player: Player, console: Instance): (boolean, number, number)
	if isRecharging then
		return false, 0, TrainResultCodes.NO_ENERGY
	end
	isRecharging = true

	if
		not (
			(console:IsA("Model") or console:IsA("BasePart"))
			and CollectionService:HasTag(console, TrainConfig.SHIELD_CONSOLE_TAG)
		)
	then
		isRecharging = false
		return false, 0, TrainResultCodes.INVALID_CONSOLE
	end
	local promptPart, prompt = ProximityValidation.FindPromptPart(console, TrainConfig.SHIELD_PROMPT_PART_NAME)
	if not (promptPart and prompt) then
		isRecharging = false
		return false, 0, TrainResultCodes.INVALID_CONSOLE
	end
	if not ProximityValidation.IsPlayerNear(player, promptPart, prompt, TrainConfig.PROXIMITY_TOLERANCE) then
		isRecharging = false
		return false, 0, TrainResultCodes.TOO_FAR
	end
	if currentShield >= maxShield then
		isRecharging = false
		return false, 0, TrainResultCodes.SHIELD_FULL
	end

	local tools = EnergyToolHelper.GatherEnergyTools(player)
	if #tools == 0 then
		isRecharging = false
		return false, 0, TrainResultCodes.NO_ENERGY
	end

	-- Smallest recharge value first, so a big stockpile isn't blown on a small top-up.
	table.sort(tools, function(a, b)
		local va = TrainConfig.ShieldRecharge[EnergyToolHelper.GetEnergyTier(a) or 0] or 0
		local vb = TrainConfig.ShieldRecharge[EnergyToolHelper.GetEnergyTier(b) or 0] or 0
		return va < vb
	end)

	local shieldAdded = 0
	for _, tool in tools do
		if currentShield >= maxShield then
			break
		end
		local tier = EnergyToolHelper.GetEnergyTier(tool)
		local value = tier and TrainConfig.ShieldRecharge[tier] or 0
		if value <= 0 then
			continue
		end
		EnergyToolHelper.ConsumeTool(player, tool)
		local before = currentShield
		currentShield = math.min(maxShield, currentShield + value)
		shieldAdded += currentShield - before
	end

	if shieldAdded <= 0 then
		isRecharging = false
		return false, 0, TrainResultCodes.SHIELD_FULL
	end

	broadcast()
	isRecharging = false
	return true, shieldAdded, TrainResultCodes.NONE
end

--[=[
	@within TrainShieldManager
	Public alias of the recharge handler (the packet binds to it in Initialize).
]=]
TrainShieldManager.RechargeFromEnergy = handleRecharge

-- [[ BUFF SUBSCRIPTIONS ]]
-- The buff folders are created by other server scripts (PerkEffectsDispatcher,
-- TechEffectsDispatcher), so wait for them before subscribing.
local function subscribeBuffs()
	local techFolder = ReplicatedStorage:WaitForChild("TechTreeBuffs", 30)
	if techFolder then
		techFolder:GetAttributeChangedSignal("MaxHP"):Connect(recomputeMax)
	else
		warn("[TrainShield] TechTreeBuffs not found within 30s; MaxHP buff updates disabled")
	end
	local partyFolder = ReplicatedStorage:WaitForChild("PartyPerkBuffs", 30)
	if partyFolder then
		partyFolder:GetAttributeChangedSignal("TrainShieldBonus"):Connect(recomputeMax)
	else
		warn("[TrainShield] PartyPerkBuffs not found within 30s; TrainShieldBonus updates disabled")
	end
end

--[=[
	@within TrainShieldManager
	Initialises shield state and wires the recharge packet, join sync, buff
	subscriptions, and pre-game freeze. Call exactly once from the owning server
	script.
]=]
function TrainShieldManager.Initialize()
	maxShield = computeMax()
	currentShield = maxShield
	hasStarted = false
	isRecharging = false

	Packets.ReqRechargeShield.OnServerInvoke = handleRecharge

	-- Full sync to each joining player so their HUD bar is correct immediately.
	Players.PlayerAdded:Connect(function(player: Player)
		Packets.TrainShieldSync:FireClient(player, currentShield, maxShield)
	end)

	-- Pre-game freeze: ApplyDamage no-ops until the round is live. TrainFuelManager
	-- fires SetTrainStarted(false) at init and (true) on the first un-brake.
	Signals.SetTrainStarted:Connect(function(started: boolean)
		hasStarted = started
	end)

	broadcast()
	task.spawn(subscribeBuffs)
end

return TrainShieldManager

Task 13: TrainShieldController (client)​

Wires the console prompt to ReqRechargeShield, plays recharge SFX on success, and bridges TrainShieldSync into OnTrainShieldChanged. Mirrors TrainClient's engine-prompt handling.

  • Create: src/StarterPlayer/StarterPlayerScripts/TrainShieldController.client.luau

--!strict
--!optimize 2

--[=[
    @class TrainShieldController
    @client
    Discovers shield-console instances via CollectionService tags and wires their
    ProximityPrompt to send `ReqRechargeShield` (mirroring TrainClient's refuel
    prompt, including the "hold with no energy" early-out). On a successful
    recharge it plays a SoundManager SFX. Incoming `TrainShieldSync` packets are
    bridged into `Signals.OnTrainShieldChanged` so the HUD controller never
    touches the network layer directly.
]=]

local CollectionService = game:GetService("CollectionService")
local Players = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")

local Shared = ReplicatedStorage.SharedModules
local TrainConfig = require(Shared.Configs:WaitForChild("TrainConfig"))
local TrainResultCodes = require(Shared:WaitForChild("TrainResultCodes"))
local Packets = require(Shared:WaitForChild("Packets"))
local Signals = require(Shared:WaitForChild("Signals"))
local SoundManager = require(Shared:WaitForChild("SoundManager"))
local Janitor = require(ReplicatedStorage.Packages.Janitor)

local LocalPlayer = Players.LocalPlayer

-- ── Notification messages ──
local NOTIF_DURATION = 3
local NO_ENERGY_MESSAGE = "Hold an energy item to recharge the shield."
local SHIELD_FULL_MESSAGE = "Shield is full."

local function playerHasEnergyTool(): boolean
	local function scan(container: Instance): boolean
		for _, item in container:GetChildren() do
			local pp = item:IsA("Tool") and item.PrimaryPart
			if pp and pp:GetAttribute("Type") == "Energy" and pp:GetAttribute("Tier") then
				return true
			end
		end
		return false
	end
	if scan(LocalPlayer.Backpack) then
		return true
	end
	local char = LocalPlayer.Character
	return char ~= nil and scan(char)
end

-- ── Prompt registration ──
type ConsoleEntry = { prompt: ProximityPrompt, cleaner: Janitor.Janitor }
local knownConsoles: { [Instance]: ConsoleEntry } = {}

local function findPrompt(root: Instance, partName: string): ProximityPrompt?
	local part = root:WaitForChild(partName, 10)
	if not (part and part:IsA("BasePart")) then
		return nil
	end
	local prompt = part:WaitForChild("ProximityPrompt", 10)
	if not (prompt and prompt:IsA("ProximityPrompt")) then
		return nil
	end
	return prompt :: ProximityPrompt
end

local function registerConsole(console: Instance)
	if knownConsoles[console] then
		return
	end
	local prompt = findPrompt(console, TrainConfig.SHIELD_PROMPT_PART_NAME)
	if not prompt then
		warn(
			("[TrainShieldController] Console '%s' missing %s/ProximityPrompt — skipping."):format(
				console.Name,
				TrainConfig.SHIELD_PROMPT_PART_NAME
			)
		)
		return
	end
	local holdConn = prompt.PromptButtonHoldBegan:Connect(function()
		if not playerHasEnergyTool() then
			Signals.RequestNotification:Fire("warn", NO_ENERGY_MESSAGE, NOTIF_DURATION)
			prompt.Enabled = false
			task.delay(1, function()
				prompt.Enabled = true
			end)
		end
	end)
	local triggerConn = prompt.Triggered:Connect(function()
		task.spawn(function()
			local success, _shieldAdded, reason = Packets.ReqRechargeShield:Fire(console)
			if success then
				SoundManager.PlaySFX("ShieldRecharge")
			elseif reason == TrainResultCodes.NO_ENERGY then
				Signals.RequestNotification:Fire("warn", NO_ENERGY_MESSAGE, NOTIF_DURATION)
			elseif reason == TrainResultCodes.SHIELD_FULL then
				Signals.RequestNotification:Fire("info", SHIELD_FULL_MESSAGE, NOTIF_DURATION)
			end
		end)
	end)
	local cleaner = Janitor.new()
	cleaner:Add(holdConn, "Disconnect")
	cleaner:Add(triggerConn, "Disconnect")
	knownConsoles[console] = { prompt = prompt, cleaner = cleaner }
end

local function unregisterConsole(console: Instance)
	local entry = knownConsoles[console]
	if entry then
		entry.cleaner:Destroy()
		knownConsoles[console] = nil
	end
end

-- ── Sync → signal bridge ──
Packets.TrainShieldSync.OnClientEvent:Connect(function(currentShield, maxShield)
	Signals.OnTrainShieldChanged:Fire(currentShield, maxShield)
end)

-- ── Tag wiring ──
for _, inst in CollectionService:GetTagged(TrainConfig.SHIELD_CONSOLE_TAG) do
	if inst:IsA("Model") or inst:IsA("BasePart") then
		registerConsole(inst)
	else
		warn(
			("[TrainShieldController] SHIELD_CONSOLE_TAG on '%s' (%s) — must be a Model or BasePart."):format(
				inst.Name,
				inst.ClassName
			)
		)
	end
end
CollectionService:GetInstanceAddedSignal(TrainConfig.SHIELD_CONSOLE_TAG):Connect(function(inst)
	if inst:IsA("Model") or inst:IsA("BasePart") then
		registerConsole(inst)
	end
end)
CollectionService:GetInstanceRemovedSignal(TrainConfig.SHIELD_CONSOLE_TAG):Connect(function(inst)
	if inst:IsA("Model") or inst:IsA("BasePart") then
		unregisterConsole(inst)
	end
end)

Acceptance: Registers ShieldConsole-tagged instances, fires ReqRechargeShield on trigger, plays ShieldRecharge SFX on success, surfaces NO_ENERGY/SHIELD_FULL notifications, and bridges TrainShieldSync → OnTrainShieldChanged. Uses Janitor for connection cleanup (no hand-rolled connection arrays).

Task 14: TrainShieldGuiController (client)​

Drives the authored TrainShieldGui. Simpler than the fuel HUD: no continuous drain means no time-based extrapolation — the bar just eases toward the latest snapshot.

Files:

  • Create: src/StarterPlayer/StarterPlayerScripts/TrainShieldGuiController.client.luau

  • Step 1: Write the controller:

--!strict
--!optimize 2

--[=[
    @class TrainShieldGuiController
    @client
    Drives the authored `TrainShieldGui` HUD from `Signals.OnTrainShieldChanged`
    snapshots. Unlike the fuel bar, the shield has no continuous drain, so there
    is no per-frame extrapolation — the bar simply eases toward the latest
    authoritative (current/max) snapshot with frame-rate-independent smoothing.
    Bar color flips to a warning tint below a low threshold.
]=]

local Players = game:GetService("Players")
local RunService = game:GetService("RunService")
local ReplicatedStorage = game:GetService("ReplicatedStorage")

local Shared = ReplicatedStorage.SharedModules
local Signals = require(Shared:WaitForChild("Signals"))

local LocalPlayer = Players.LocalPlayer
local PlayerGui = LocalPlayer:WaitForChild("PlayerGui") :: PlayerGui

local FULL_COLOR = Color3.fromRGB(90, 170, 255)
local LOW_COLOR = Color3.fromRGB(200, 60, 60)
local LOW_THRESHOLD = 0.25
local SMOOTH_K = 8 -- higher = snappier easing

-- Latest authoritative snapshot. max is floored at 1 to avoid divide-by-zero.
local snap = { current = 0, max = 1 }

-- ── Resolve authored GUI (see Task 1; names are load-bearing) ──
local gui = PlayerGui:WaitForChild("TrainShieldGui")
gui.Enabled = true
local mainContainer = gui:WaitForChild("MainContainer")
local barContainer = mainContainer:WaitForChild("ShieldBarContainer")
local iconTextContainer = mainContainer:WaitForChild("ShieldBarIconTextContainer")
local bar = barContainer:WaitForChild("ShieldBar") :: Frame
local label = iconTextContainer:WaitForChild("ShieldText") :: TextLabel

Signals.OnTrainShieldChanged:Connect(function(current, max)
	snap.current = current
	snap.max = math.max(1, max)
end)

local displayedPct = 1

RunService.RenderStepped:Connect(function(dt: number)
	local targetPct = math.clamp(snap.current / snap.max, 0, 1)
	-- Frame-rate-independent exponential smoothing.
	local alpha = 1 - math.exp(-dt * SMOOTH_K)
	displayedPct += (targetPct - displayedPct) * alpha

	bar.Size = UDim2.new(displayedPct, 0, 1, 0)
	label.Text = ("%d%%"):format(math.floor(displayedPct * 100 + 0.5))
	bar.BackgroundColor3 = (displayedPct <= LOW_THRESHOLD) and LOW_COLOR or FULL_COLOR
end)
