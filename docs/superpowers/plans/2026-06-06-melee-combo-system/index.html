Melee Combo System Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Replace the single-swing melee from Plan 1 with a data-driven, left-click combo string per weapon — buffered click-to-advance, rich per-hit stats, a brief post-combo cooldown, server-authoritative with no correction.

Architecture: Each melee weapon's Combos.Primary is an ordered list of ComboSteps. A pure shared validator (resolveComboSwing) decides advance/restart/reject from timing alone and runs on both client (prediction + input buffering) and server (authority). The client predicts the step for animation/sound/hitmarker and sends a payload-less ReqMeleeSwing; the server derives the step from its own clock and applies that step's damage via CombatService.

Tech Stack: Luau, Rojo, Packet, Signals, Janitor, SoundManager, WeaponDebug, CollectionService.

Source spec: docs/superpowers/specs/2026-06-06-melee-combo-system-design.md

Conventions for this plan (read before starting)​

  • No automated test suite; project prefs are skip Selene, skip rojo build, no auto-playtest. Each task ends with a manual Studio verification (sync via rojo serve, observe the result) then a commit. Commits use the Haiku model per project git preference.
  • Every module keeps its existing header pragmas (--!strict, plus --!native on WeaponValidation) and --[=[ @class … ]=] doc-comment.
  • This plan edits the files shipped in Plan 1 (feat/weapon-system). It does not add new files. ReqMeleeSwing stays payload-less; the server never trusts client aim or a client-sent combo index.
  • Breaking change: MeleeWeaponConfig.SwingCooldown is removed; a single-swing weapon becomes a one-step combo.

Task 1: Combo types in WeaponTypes​

Files:

  • Modify: src/ReplicatedStorage/SharedModules/WeaponTypes.luau

  • Step 1: Replace the file contents

--!strict

--[=[
    @class WeaponTypes
    Shared type definitions for the weapon system. Runtime value is an empty
    table; consumers use the exported types. Melee weapons are combo-driven: a
    `MeleeWeaponConfig` carries weapon-level defaults plus a `Combos` map keyed
    by input (`Primary` = LC; `Secondary` reserved for future RC). Later plans
    extend the union with Gun/Throwable/Placed variants.
]=]

export type WeaponCategory = "Melee" | "Gun" | "Throwable" | "Placed"
export type FireMode = "Hitscan" | "Projectile"
export type DamageType = "Melee" | "Bullet" | "AOE"
export type InputKind = "Primary" | "Secondary"

export type BaseWeaponConfig = {
	Category: WeaponCategory,
	DisplayName: string,
	ToolName: string,
	Damage: number, -- melee: default per-hit damage (a step's Damage overrides it)
	DamageType: DamageType,
	HeadshotMultiplier: number?,
}

-- One hit in a combo. Only the two timing fields are required; the rest are
-- optional overrides of the weapon-level defaults ("fill only what differs").
export type ComboStep = {
	Recovery: number, -- min seconds before the NEXT hit may execute (paces swing + server anti-exploit gate)
	ChainWindow: number, -- seconds after this hit to keep the combo alive; past it the next swing restarts at 1.
	-- INVARIANT: ChainWindow >= Recovery (non-final steps). Ignored on the final step.
	Damage: number?,
	Range: number?,
	HitboxSize: Vector3?,
	AnimId: string?,
	SwingSound: string?,
	ImpactSound: string?,
}

export type ComboDef = {
	Steps: { ComboStep }, -- ordered; combo length = #Steps
	ResetCooldown: number?, -- brief lockout after the finisher before restarting at hit 1 (default 0)
}

-- Effective per-hit values after applying weapon-default fallbacks.
export type ResolvedStep = {
	Damage: number,
	Range: number,
	HitboxSize: Vector3,
	SwingSound: string,
	ImpactSound: string,
	AnimId: string?,
}

-- Authoritative + predicted combo progress. index 0 = no active combo.
export type ComboState = {
	index: number,
	lastHitTime: number,
}

export type MeleeWeaponConfig = BaseWeaponConfig & {
	Category: "Melee",
	-- Weapon-level DEFAULTS, used by any step that omits its own value:
	Range: number, -- forward reach in studs (also hitbox depth)
	HitboxSize: Vector3, -- X = width, Y = height (Z ignored; depth comes from Range)
	SwingSound: string, -- SoundConfig.Sfx key
	ImpactSound: string, -- SoundConfig.Sfx key
	SwingAnimId: string?, -- optional rbxassetid for a swing AnimationTrack
	-- Combo strings keyed by input. Only Primary (LC) is read this iteration.
	Combos: { [InputKind]: ComboDef },
}

-- Union expands in later plans (| GunWeaponConfig | ThrowableWeaponConfig | PlacedWeaponConfig).
export type WeaponConfig = MeleeWeaponConfig

return {}

Task 3: Combo validator + step resolver​

Files:

  • Modify: src/ReplicatedStorage/SharedModules/WeaponValidation.luau

  • Step 1: Require WeaponTypes

At the top of the module, after the --[=[ … ]=] doc-comment and before local WeaponValidation = {}, add:

  • Step 2: Append the two functions

Just before the final return WeaponValidation, add:

-- Decide which step THIS swing executes, and whether it's allowed right now.
-- Pure; called by BOTH client (prediction, tolerance 0) and server (authority,
-- small tolerance). `accepted == false` means "not yet" — the client buffers the
-- click and the server drops the request. Advancement is independent of whether
-- the swing hits anything.
function WeaponValidation.resolveComboSwing(
	state: Types.ComboState,
	combo: Types.ComboDef,
	now: number,
	tolerance: number
): (number?, boolean)
	local steps = combo.Steps
	local count = #steps
	local idx = state.index
	local elapsed = now - state.lastHitTime

	if idx >= 1 and idx <= count then
		if idx >= count then
			-- Finished the full combo: restart at 1 once ResetCooldown elapses.
			if elapsed < ((combo.ResetCooldown or 0) - tolerance) then
				return nil, false
			end
			return 1, true
		end

		local step = steps[idx]
		if elapsed < (step.Recovery - tolerance) then
			return nil, false -- still in this hit's recovery
		end
		if elapsed > step.ChainWindow then
			return 1, true -- chain expired → fresh combo
		end
		return idx + 1, true -- continue the chain
	end

	return 1, true -- no active combo → start at hit 1
end

-- Resolve a step's effective values, falling back to weapon-level defaults for
-- any field the step omits.
function WeaponValidation.resolveStep(config: Types.MeleeWeaponConfig, step: Types.ComboStep): Types.ResolvedStep
	return {
		Damage = step.Damage or config.Damage,
		Range = step.Range or config.Range,
		HitboxSize = step.HitboxSize or config.HitboxSize,
		SwingSound = step.SwingSound or config.SwingSound,
		ImpactSound = step.ImpactSound or config.ImpactSound,
		AnimId = step.AnimId or config.SwingAnimId,
	}
end

-- Returns a COPY of the player's combo progress for a weapon (defaults to a
-- fresh, no-active-combo state) so callers can't mutate stored state directly.
function WeaponState.GetCombo(player: Player, weaponName: string): { index: number, lastHitTime: number }
	local record = states[player]
	local current = record and record.combo[weaponName]
	if not current then
		return { index = 0, lastHitTime = -math.huge }
	end
	return { index = current.index, lastHitTime = current.lastHitTime }
end

function WeaponState.SetCombo(player: Player, weaponName: string, index: number, timestamp: number)
	ensure(player).combo[weaponName] = { index = index, lastHitTime = timestamp }
end

function WeaponState.ResetCombo(player: Player, weaponName: string)
	local record = states[player]
	if record then
		record.combo[weaponName] = nil
	end
end

Task 6: Buffered combo client (MeleeHandler)​

Files:

  • Modify: src/StarterPlayer/StarterPlayerScripts/WeaponHandlers/MeleeHandler.luau

Replaces the module-level lastSwing clock with per-Tool combo state, adds input buffering and per-step prediction.

  • Step 1: Replace the file contents
--!strict

--[=[
    @class MeleeHandler
    @client
    Category handler for melee combo weapons. On left-click it runs the shared
    `resolveComboSwing` to pick the next combo step (buffering the click while
    the current hit is still in recovery), then predicts that step: plays its
    swing sound + optional animation, runs the step hitbox for an instant
    hitmarker (`Signals.WeaponLocalHit`), draws the debug box, fires
    `Signals.WeaponComboChanged`, and sends the payload-less
    `Packets.ReqMeleeSwing` for the server to apply authoritative damage. Combo
    state is per-equipped-Tool (cleared on unequip), so it resets correctly on
    respawn/weapon-switch.
]=]

local ReplicatedStorage = game:GetService("ReplicatedStorage")

local SharedModules = ReplicatedStorage.SharedModules
local WeaponValidation = require(SharedModules:WaitForChild("WeaponValidation"))
local WeaponTypes = require(SharedModules:WaitForChild("WeaponTypes"))
local Packets = require(SharedModules:WaitForChild("Packets"))
local Signals = require(SharedModules:WaitForChild("Signals"))
local SoundManager = require(SharedModules:WaitForChild("SoundManager"))
local WeaponDebug = require(SharedModules:WaitForChild("WeaponDebug"))

local Janitor = require(ReplicatedStorage.Packages:WaitForChild("Janitor"))

export type HandlerContext = {
	player: Player,
	character: Model,
	tool: Tool,
	config: WeaponTypes.WeaponConfig,
	janitor: Janitor.Janitor, -- scoped to this equipped Tool
}

local MeleeHandler = {}

-- Per-equipped-Tool combo progress (prediction only). Cleared on unequip.
local comboByTool: { [Tool]: WeaponTypes.ComboState } = {}

local function getRootPart(character: Model): BasePart?
	return character:FindFirstChild("HumanoidRootPart") :: BasePart?
end

-- Execute one predicted combo hit and tell the server to validate it.
local function performStep(context: HandlerContext, stepIndex: number, now: number)
	local config = context.config :: WeaponTypes.MeleeWeaponConfig
	local combo = config.Combos.Primary
	if not combo then
		return
	end
	local step = combo.Steps[stepIndex]
	local resolved = WeaponValidation.resolveStep(config, step)

	comboByTool[context.tool] = { index = stepIndex, lastHitTime = now }

	local rootPart = getRootPart(context.character)
	if rootPart then
		SoundManager.PlaySFXAt(resolved.SwingSound, rootPart.Position, { Replicate = true })
	end

	if resolved.AnimId then
		local humanoid = context.character:FindFirstChildOfClass("Humanoid")
		local animator = humanoid and humanoid:FindFirstChildOfClass("Animator")
		if animator then
			local anim = Instance.new("Animation")
			anim.AnimationId = resolved.AnimId
			local track = animator:LoadAnimation(anim)
			track:Play()
			anim:Destroy()
		end
	end

	if rootPart then
		local hits = WeaponValidation.queryMeleeTargets(rootPart.CFrame, resolved.Range, resolved.HitboxSize, { context.character })
		local boxCFrame, boxSize = WeaponValidation.meleeHitbox(rootPart.CFrame, resolved.Range, resolved.HitboxSize)
		WeaponDebug.DrawBox(boxCFrame, boxSize, #hits > 0)
		if #hits > 0 then
			Signals.WeaponLocalHit:Fire(hits[1])
		end
	end

	Signals.WeaponComboChanged:Fire(config.ToolName, stepIndex, #combo.Steps)
	Packets.ReqMeleeSwing:Fire()
end

function MeleeHandler.OnEquip(context: HandlerContext)
	comboByTool[context.tool] = { index = 0, lastHitTime = -math.huge }
end

function MeleeHandler.OnActivate(context: HandlerContext)
	local config = context.config :: WeaponTypes.MeleeWeaponConfig
	local combo = config.Combos.Primary
	if not combo then
		return
	end
	local state = comboByTool[context.tool]
	if not state then
		return
	end

	local now = os.clock()
	local stepIndex, accepted = WeaponValidation.resolveComboSwing(state, combo, now, 0)
	if accepted and stepIndex then
		performStep(context, stepIndex, now)
		return
	end

	-- Busy: buffer ONE retry at the recovery/reset boundary. The keyed Janitor
	-- entry replaces (and cancels) any previously buffered retry.
	local steps = combo.Steps
	local waitUntil: number
	if state.index >= #steps then
		waitUntil = state.lastHitTime + (combo.ResetCooldown or 0)
	else
		waitUntil = state.lastHitTime + steps[state.index].Recovery
	end
	local delay = math.max(0, waitUntil - now)

	context.janitor:Add(task.delay(delay, function()
		local current = comboByTool[context.tool]
		if not current then
			return
		end
		local retryNow = os.clock()
		local retryIndex, retryOk = WeaponValidation.resolveComboSwing(current, combo, retryNow, 0)
		if retryOk and retryIndex then
			performStep(context, retryIndex, retryNow)
		end
	end), true, "comboRetry")
end

function MeleeHandler.OnUnequip(context: HandlerContext)
	comboByTool[context.tool] = nil
end

return MeleeHandler

context.janitor:Add(thread, true, "comboRetry") — adding a thread with method true makes the Janitor task.cancel it on cleanup, and the index key "comboRetry" means each new buffered retry cancels the previous one (keyed-Janitor pattern). No manual thread bookkeeping, no accumulation.

Task 7: Combo authority (WeaponServer)​

Files:

  • Modify: src/ServerScriptService/WeaponServer.server.luau

  • Step 1: Replace the onMeleeSwing handler

Replace the existing onMeleeSwing function (keep everything else — requires, WeaponState.Initialize(), getEquippedWeapon, and the Packets.ReqMeleeSwing.OnServerEvent:Connect(onMeleeSwing) line) with:

local TOLERANCE = 0.05 -- seconds of jitter slack so legit hits aren't dropped

local function onMeleeSwing(player: Player)
	local _tool, config = getEquippedWeapon(player)
	if not config or config.Category ~= "Melee" then
		return
	end
	local melee = config :: WeaponTypes.MeleeWeaponConfig
	local combo = melee.Combos.Primary
	if not combo then
		return
	end

	local now = os.clock()
	local state = WeaponState.GetCombo(player, melee.ToolName)
	local stepIndex, accepted = WeaponValidation.resolveComboSwing(state, combo, now, TOLERANCE)
	if not accepted or not stepIndex then
		return -- too fast / out of window: drop
	end

	local character = player.Character
	local rootPart = character and character:FindFirstChild("HumanoidRootPart") :: BasePart?
	if not character or not rootPart then
		return
	end

	WeaponState.SetCombo(player, melee.ToolName, stepIndex, now)

	local step = combo.Steps[stepIndex]
	local resolved = WeaponValidation.resolveStep(melee, step)

	local targets = WeaponValidation.queryMeleeTargets(rootPart.CFrame, resolved.Range, resolved.HitboxSize, { character })
	for _, model in targets do
		local humanoid = model:FindFirstChildOfClass("Humanoid")
		if humanoid then
			local applied = CombatService.ApplyToModel(model, humanoid, resolved.Damage, melee.DamageType, player)
			if applied then
				local hitRoot = model:FindFirstChild("HumanoidRootPart") :: BasePart?
				local pos = if hitRoot then hitRoot.Position else rootPart.Position
				Packets.WeaponImpact:Fire(pos, melee.ToolName)
			end
		end
	end
end
