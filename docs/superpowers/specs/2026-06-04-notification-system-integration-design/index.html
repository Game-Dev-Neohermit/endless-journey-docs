Notification System Integration — Design

Date: 2026-06-04 Status: Approved (design) Topic: Fix and rework the imported NotificationHandler module into the project's conventions.

Background​

NotificationHandler.luau (Notification System by 7eoeb) was imported into src/ReplicatedStorage/SharedModules/. An audit found correctness bugs, two wasteful per-frame Heartbeat loops, and several violations of this project's architecture (raw Sound instances, direct TweenService, no Janitor, module-scope LocalPlayer).

This rework fixes every audit finding and integrates the module with the project's cross-cutting systems: SoundManager, MotionMaster, Janitor, Signals, and config-driven tuning.

Goals​

  • Fix all 16 audit findings (correctness + performance + architecture).
  • Route audio through SoundManager, animation through MotionMaster, cleanup through Janitor.
  • Make notifications Signal-triggered (decoupled) so no controller requires the module.
  • Move all tuning into a NotificationConfig module.
  • Keep the gradient text-sweep effect, but optimize it to a single tween.

Non-Goals (YAGNI)​

  • No new notification types.
  • No theming/skinning system yet (the game has no UI theme; reskin happens later).
  • No server→client notification Packet (can be added later as its own channel if needed).

Architecture & File Layout​

Mirrors the SoundManager pattern: config + Init() bootstrap + Signal-driven consumer.

FileRoleStatus
Configs/NotificationConfig.luauTypes, colors, image IDs, base transparencies, device/scaling settings, durations, MaxConcurrent cap, SFX name per type, optional ExecutedFunctionTimeoutNew
Configs/SoundConfig.luauAdd 5 non-positional SFX entries: NotifSuccess, NotifInfo, NotifWarn, NotifAlert, NotifDefault (asset IDs migrated from the old module)Edit
Signals/init.luauAdd RequestNotification and RequestClearNotifications to the busEdit
SharedModules/NotificationManager/ (renamed from NotificationHandler.luau)Rewritten module: Init() bootstrap, sole signal consumer, Janitor-managed, MotionMaster animations, SoundManager audioRewritten
StarterPlayerScripts/NotificationController.client.luauOne-line bootstrap calling NotificationManager.Init(); mirrors SoundController.client.luauNew

Data flow:

Controller → Signals.RequestNotification:Fire(type, message, duration?, fn?)
           → NotificationManager (only subscriber)
           → build + animate toast (MotionMaster)
           → SoundManager.PlaySFX("Notif"..Type)
           → Janitor cleanup on close/clear

LocalPlayer/PlayerGui are acquired inside Init() (not at require time), so the module is safe to live in SharedModules like SoundManager.

Public API​

Signals.RequestNotification:Fire(
    notificationType,  -- "Success" | "Info" | "Warn" | "Alert" | "Default" (case-insensitive)
    message,           -- string
    duration,          -- number? (nil → device default from NotificationConfig)
    executedFunction   -- (() -> ())? (nil → timed auto-close)
)

Signals.RequestClearNotifications:Fire()  -- clears all active notifications
  • The signal is the only public trigger path; controllers never require the module.
  • NotificationManager exposes Init() plus internal Show/Clear used by the signal handler.
  • Type/string validation and valid-type lookup are centralized in the signal handler.

Audit Findings → Resolutions​

Correctness​

  • #1 Text always min size (math.clamp(round(scaledMin), scaledMin, scaledMax)): compute a real interpolated size between scaled min and max so MaxTextSize takes effect.
  • #2 LayoutOrder = os.time() collisions & #3 math.huge: use a module-level monotonic counter; executed-function notifications get a reserved high band above the counter.
  • #4 Heartbeat crash on name mismatch: guard :match(...) result before :lower().
  • #5 Hanging executedFunction: optional ExecutedFunctionTimeout in config (nil = wait forever, current behavior).

Performance / Algorithms​

  • #6 Per-frame GetDescendants() per notification: single shared Heartbeat (Janitor-managed). Cache each notification's tagged descendants once at creation; dirty-check transparency writes (only write on change).
  • #7 20-keypoint NumberSequence rebuilt every frame (kept-but-optimized): set a static transparent→opaque gradient ramp once, then animate UIGradient.Offset (Vector2) with a single MotionMaster tween. Same sweep look, no per-frame allocation.
  • #8 Gradient Heartbeat leak on early GUI destroy: eliminated — the sweep is now a self-cleaning tween, not a manual connection.
  • #9 tick() deprecated: use os.clock() for monotonic timing.
  • #10 Resize not debounced: route the ViewportSize listener through a one/two-frame debounce (pending flag) to coalesce rapid window-drag fires.
  • #11 Throwaway GetTextSize("") for line height: compute line height from font metrics / single measure, removing a TextService round-trip.
  • #12 No concurrency cap: NotificationConfig.MaxConcurrent; when exceeded, close the oldest non-executed notification early.

Architecture (project conventions)​

  • #13 Raw Sound instances: deleted playSound; use SoundManager.PlaySFX("Notif"..Type). No Sounds folder, no Ended leak.
  • #14 Direct TweenService: all animation via MotionMaster (EaseOutQuart-equivalent for size/fade; Offset tween for the sweep; linear tween for the time-left bar).
  • #15 No Janitor: one Janitor for the manager (shared Heartbeat, viewport/debounce connection, signal connections); one Janitor per notification entry (its tweens + close timer), keyed in a table. Close/clear = entry.cleaner:Destroy().
  • #16 Module-scope LocalPlayer + WaitForChild: moved into Init().

Cleanup​

  • Remove unused TextChatService and ReplicatedStorage imports.
  • Remove the unused container local in animateIn.
  • Remove the double frame:Destroy() (animateOut Completed already destroys).
  • Remove redundant re-lowering in the validation loop.
  • Replace weak type annotations (table, () -> nil) with precise types.
  • Capture/refresh Camera defensively rather than once at module scope.

Respawn Safety​

ScreenGui.ResetOnSpawn = false is preserved. With the Init()-once pattern and a persisted GUI reference, the manager survives respawns without rebuilding. The GUI lives in PlayerGui (not Backpack), so the Backpack-replacement caveat does not apply here.

Testing​

No automated suite (per project). Verification in Studio:

  • Fire each of the 5 types via signal; confirm color/icon/sound/animation.
  • Fire a burst exceeding MaxConcurrent; confirm oldest closes and stack stays bounded.
  • Fire an executedFunction notification; confirm it stays until the function returns (and times out if ExecutedFunctionTimeout set).
  • Resize the window during active notifications; confirm smooth resize with no error spam.
  • RequestClearNotifications; confirm all close and GUI tears down cleanly.
  • Respawn with active notifications; confirm no duplicate GUI / no leaked connections.

Affected Conventions / Docs​

Update the networking/signals map in Documentations/Project-Maintenance-Guide.md with the two new Signals and the new SFX entries.
