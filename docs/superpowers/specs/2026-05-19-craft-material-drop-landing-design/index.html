Craft Material Drop Landing & Pickup Registration

Date: 2026-05-19 Status: Approved

Problem​

When a player presses Backspace to drop a craft material from their backpack or hotbar, Roblox places the Tool's Handle in front of the player at ~2× character height. Because CanCollide = false is set on the Handle, it floats there permanently instead of falling. Additionally, the proximity pickup hover effect (bob + spin) starts via the PickupItem CollectionService tag the moment the item is registered — before it has landed — causing a mid-air hover. There is no consistent path for hover registration: shredder-ejected materials use the tag listener, dropped tools have no landing system at all.

Goals​

  1. Dropped craft material Tools fall and physically land on designated surfaces (train platform floor, workbenches).
  2. Hover + spin animation starts only after the item has settled on a landing surface, with rotation reset to identity first.
  3. A single, consistent code path drives hover registration for all pickup items (both shredder-ejected and player-dropped), replacing the CollectionService tag listener.

Non-Goals​

  • Changing how raw junk Tools behave (they keep CanBeDropped = false).
  • Modifying ShredderServer, MaterialPickupService, HoverEffect, MotionMaster, or JunkToolManager.
  • Supporting collision with player characters or untagged geometry for dropped items.

Architecture​

New server script: DroppedToolService​

src/ServerScriptService/DroppedToolService.server.luau

Responsibilities:

  1. Register PhysicsService collision groups at startup.
  2. Assign DroppableSurface-tagged parts to the correct collision group.
  3. Detect dropped craft material Tools entering workspace.
  4. Run per-item landing detection loops.
  5. Invoke ProximityPickupServer.RegisterItem after landing.

Modified: ProximityPickupServer​

src/ServerStorage/SharedModules/ProximityPickupServer.luau

  • RegisterItem fires the new PickupItemReady packet to all clients immediately after the zone is created.
  • New Players.PlayerAdded handler replays PickupItemReady for all active unclaimed items to late-joining players.

New packet: PickupItemReady​

src/ReplicatedStorage/SharedModules/Packets/init.luau

  • Direction: S→C (RemoteEvent)
  • Payload: handle: BasePart, itemId: string
  • Passing an Instance reference over a RemoteEvent is safe — Roblox queues delivery until the instance is replicated on the client.

Definition (add alongside PickupItemClaimed):

local PickupItemReady = Packet(
    "PickupItemReady",
    Packet.Instance :: BasePart, -- Handle of the pickup item
    Packet.String                -- itemId (GUID)
)

Export it in the return table: PickupItemReady = PickupItemReady.

Modified: ProximityPickupController​

src/StarterPlayer/StarterPlayerScripts/ProximityPickupController.client.luau

  • Removes all CollectionService-based hover wiring (GetTagged, GetInstanceAddedSignal, GetInstanceRemovedSignal, trackModel).
  • Adds a single Packets.PickupItemReady.OnClientEvent handler that calls HoverEffect.Apply directly.
  • Existing PickupItemClaimed handler is unchanged.

Modified: ProximityPickupConfig​

src/ReplicatedStorage/SharedModules/Configs/ProximityPickupConfig.luau

Three new tuning values:

SETTLED_VELOCITY_THRESHOLD = 0.5,  -- studs/s; below this the handle is considered at rest
DROP_POLL_INTERVAL        = 0.1,   -- seconds between GetTouchingParts polling ticks
DROP_LANDING_TIMEOUT      = 60,    -- seconds before abandoning an item that never lands

Collision Group Setup​

Two groups registered by DroppedToolService at server startup:

GroupCollides with DefaultCollides with DroppableSurface
DroppedMaterialNoYes
DroppableSurface(unchanged)Yes
  • DroppedMaterial is assigned to a dropped craft material's Handle the moment it's detected.
  • DroppableSurface is assigned to every part tagged "DroppableSurface" via CollectionService — at startup and via GetInstanceAddedSignal for parts added later (newly placed objects).

Drop Detection​

workspace.DescendantAdded fires for every new descendant. DroppedToolService filters to:

  • instance:IsA("Tool")
  • instance.Parent == workspace (direct child — distinguishes Roblox default drops from ShredderServer's workspace.DroppedMaterials subfolder)
  • instance:GetAttribute("IsCraftMaterial") == true

On match:

  1. Retrieve Handle = tool:FindFirstChild("Handle"). Warn and skip if absent.
  2. PhysicsService:SetPartCollisionGroup(Handle, "DroppedMaterial")
  3. Handle.CanCollide = true, Handle.CanTouch = true, Handle.Anchored = false
  4. Spawn landing detection loop via task.spawn.

Landing Detection Loop​

Polls every DROP_POLL_INTERVAL seconds on a dedicated task.spawn'd thread.

Per tick:

touching = Handle:GetTouchingParts()
onSurface = any part in touching has tag "DroppableSurface"

if onSurface AND Handle.AssemblyLinearVelocity.Magnitude < SETTLED_VELOCITY_THRESHOLD:
    → exit loop → landing sequence

Safety exits:

  • Handle.Parent == nil — tool was destroyed or collected while falling; exit immediately.
  • Elapsed time exceeds DROP_LANDING_TIMEOUT — item failed to reach a tagged surface (e.g. fell off the train); exit without registering.

Landing Sequence (server-side)​

Runs once the loop exits with a confirmed landing:

  1. Handle.Anchored = true
  2. Handle.CFrame = CFrame.new(Handle.Position) — resets rotation to identity so HoverEffect's spin starts from a clean orientation.
  3. Call ProximityPickupServer.RegisterItem(tool, metadata, pickupCallback, true) where:
    • metadata = { ItemType = tool:GetAttribute("ItemType"), ItemTier = tool:GetAttribute("ItemTier") }
    • pickupCallback moves tool.Parent = claimedPlayer.Backpack
    • keepModel = true (tool IS the inventory item)
  4. RegisterItem fires PickupItemReady — hover starts on all clients.

ProximityPickupServer Changes​

Inside RegisterItem​

After activeItems[itemId] = record, add:

PickupItemReady:Fire(model.PrimaryPart, itemId)

(Packet:Fire(...) broadcasts to all clients — same pattern as PickupItemClaimed:Fire(itemId, player).)

This is the only addition. No existing logic changes.

Late-joiner handler​

Players.PlayerAdded:Connect(function(player)
    task.defer(function()
        for itemId, record in pairs(activeItems) do
            if record.State == "Unclaimed" and record.Model.PrimaryPart then
                PickupItemReady:FireClient(player, record.Model.PrimaryPart, itemId)
            end
        end
    end)
end)

task.defer yields to the end of the current resumption cycle, giving the joining player's OnClientEvent connections time to register before the packets arrive.

ProximityPickupController Changes​

Removed​

-- entire trackModel function
-- CollectionService:GetTagged("PickupItem") initial loop
-- CollectionService:GetInstanceAddedSignal("PickupItem") connection
-- CollectionService:GetInstanceRemovedSignal("PickupItem") connection
-- CollectionService import (no longer used)

Added​

Packets.PickupItemReady.OnClientEvent:Connect(function(handle: BasePart, itemId: string)
    if trackedItems[itemId] then return end  -- guard: late-joiner replay + normal fire can both arrive

    local model = handle.Parent :: Model
    trackedItems[itemId] = model

    local floorOffset = handle.Size.Y + HOVER_FLOOR_CLEARANCE
    local ok, hoverHandle = pcall(
        HoverEffect.Apply,
        handle,
        ProximityPickupConfig.HOVER_HEIGHT,
        ProximityPickupConfig.HOVER_DURATION,
        { FloorOffset = floorOffset, SpinDuration = ProximityPickupConfig.SPIN_DURATION }
    )
    if ok then
        hoverHandles[itemId] = hoverHandle
    else
        warn("Failed to apply hover effect to", handle:GetFullName(), ":", hoverHandle)
    end

    model.AncestryChanged:Connect(function(_, parent)
        if parent == nil then
            stopHoverEffect(itemId)
            trackedItems[itemId] = nil
        end
    end)
end)

The duplicate-fire guard (if trackedItems[itemId] then return end) is essential: a player who joins while items are active will receive both a FireAll from registration history (replayed via PlayerAdded) and could theoretically receive duplicates. The guard makes the handler idempotent.

End-to-End Flows​

Player drops a craft material (new flow)​

  1. Player presses Backspace → Roblox moves Tool to workspace (direct child).
  2. DroppedToolService detects it (Tool + IsCraftMaterial + parent is workspace).
  3. Handle → DroppedMaterial collision group; CanCollide = true; falls.
  4. Item only physically interacts with DroppableSurface parts; passes through characters.
  5. Polling loop: detects touch on tagged surface + near-zero velocity.
  6. Server anchors handle, resets rotation to identity.
  7. RegisterItem → zone created → PickupItemReady fired to all clients.
  8. ProximityPickupController receives packet → HoverEffect.Apply → item hovers and spins.
  9. Player walks near zone → PickupItemClaimed → hover stops → float to player → tool to Backpack.

Shredder ejects a material (unchanged externally)​

  1. ShredderServer arc animation completes → Handle.CanCollide = true, Handle.Anchored = false (existing).
  2. task.delay(ARC_DURATION) → RegisterItem called (existing).
  3. RegisterItem now fires PickupItemReady (new addition).
  4. Client receives packet → hover starts.
  5. Pickup flow same as above from step 9.

Player joins while items are in the world​

  1. Players.PlayerAdded fires → task.defer → PickupItemReady:FireClient for each active unclaimed item.
  2. Client's OnClientEvent handler receives them → hover starts for each.

Manual Studio Setup (User Action Required)​

Implementation note: The agent implementing this spec must make no modifications to Studio objects (no MCP object edits, no property changes via script execution in Studio). All steps below are performed manually by the developer in Roblox Studio before or after deploying the code changes.

Complete these steps in Studio in order:

Step 1 — Enable dropping on craft material templates

  1. Open ReplicatedStorage > CraftingMaterials in the Explorer.
  2. For each Tool template inside (e.g. Wood, Metal):
    • Select the Tool.
    • In the Properties panel, set CanBeDropped = true.
  3. Save the place.

Raw junk Tool templates in ReplicatedStorage > JunkTools keep CanBeDropped = false — do not change those.

Step 2 — Tag landing surfaces with DroppableSurface

Open the Tag Editor (Plugins → Tag Editor, or use the built-in CollectionService tag field in Properties).

Tag the following parts with the tag DroppableSurface:

  • All floor/platform parts of the train that players walk on.
  • The top platform surface of each workbench Model.

Rules for future additions:

  • Any new surface you want dropped items to land on: add the DroppableSurface tag to that part.
  • No code changes are needed — DroppedToolService picks up new tagged parts automatically via CollectionService:GetInstanceAddedSignal.

Step 3 — Verify IsCraftMaterial attribute on ejected materials

The DroppedToolService drop-detection filter checks for IsCraftMaterial = true on the Tool. This attribute is already set by both ShredderServer and MaterialPickupService at runtime — no Studio-side attribute setup is needed. This step is just a verification checkpoint: confirm neither of those scripts has been changed to omit that attribute.

Step 4 — Verify CraftingMaterials Handle parts

For each Tool template in ReplicatedStorage > CraftingMaterials:

  • Confirm it has a child BasePart named exactly Handle.
  • Confirm Handle is set as the Tool's PrimaryPart (or that DroppedToolService can set it — the service sets mat.PrimaryPart = handle after cloning, so the template does not strictly require it pre-set, but it is cleaner to have it set).

These are already required by ShredderServer; this is a double-check.
