XP & Level System — Design

Date: 2026-06-11 Status: Approved (design); implementation pending Place scope: Gameplay place (this repo). Lobby place deployment noted in §10.

1. Goal​

Add a persistent XP and Level system to Endless Journey, stored with ProfileStore.

  • Players earn XP from two sources in the gameplay place:
    1. Enemy kills — when an enemy dies.
    2. Train distance — while the train is in its "go" state (running: not braked and not out of fuel/stalled), the party earns 1 XP every 5 seconds.
  • XP is party-wide and shared. Every player in the server receives the full award from either source (no per-killer attribution). One party occupies one server, so "whole party" = "everyone in the server".
  • Both sources feed a single XP value (one XP pool, not two tracks).
  • Level cap is 100, using a polynomial-1.5 cost curve (§3).
  • XP and Level are identical across places (lobby and gameplay) in the same Roblox universe.
  • This first pass ships: server-authoritative data + awards, client replication, and a level-up toast. No XP bar GUI yet.

2. Architecture overview​

Chosen approach: data authority + thin earner wiring.

UnitLocationRuns inResponsibility
XPConfigReplicatedStorage/SharedModules/Configs/XPConfig.luaubothAll tuning constants (curve, rates, cap, store name).
XPCurveReplicatedStorage/SharedModules/XPCurve.luaubothPure curve math: xpToNext(level), derive level/progress from total XP. Precomputes cumulative thresholds at load.
XPManagerServerStorage/SharedModules/XPManager.luauboth placesProfileStore profile lifecycle, XP→level derivation, award API, client replication. Place-agnostic.
XPSystemLoaderServerScriptService/XPSystemLoader.server.luaugameplay onlyCalls XPManager.Initialize(), then wires the two earning sources (train go-state, enemy deaths) to the award API.
XPControllerStarterPlayer/StarterPlayerScripts/XPController.client.luaubothReceives replication, re-fires a client signal, shows the level-up toast.

ProfileStore.luau is relocated from ReplicatedStorage/SharedModules/ to ServerStorage/SharedModules/ProfileStore.luau so its source is never replicated to clients. Only XPManager requires it (server-side).

Rationale for this split over an all-in-one manager: the lobby place must run profile lifecycle + replication for display and clean session handoff, but must not run the train/combat earners. Keeping earners in a gameplay-only loader avoids place-conditional branches inside the data module.

3. Data model & XP curve​

Stored data (profile)​

PROFILE_TEMPLATE = {
    TotalXP = 0, -- lifetime cumulative XP; the single source of truth
}

Level and progress are derived from TotalXP, never stored. This means re-tuning the curve never desyncs saved data.

Curve​

xpToNext(L) = round(XPConfig.CURVE_COEFF * L ^ XPConfig.CURVE_EXP) + XPConfig.CURVE_OFFSET

Defaults: CURVE_COEFF = 5, CURVE_EXP = 1.5, CURVE_OFFSET = 45, MAX_LEVEL = 100.

Representative costs (XP to go from L to L+1):

L→L+1XP
1→250
10→11203
25→26670
50→511,813
75→763,293
99→1004,970

Total XP to reach level 100 ≈ 204,000. Distance XP alone is ~720 XP/hour, so kills meaningfully accelerate progress.

Derivation (in XPCurve)​

At module load, precompute CUMULATIVE[L] = total XP required to be level L (CUMULATIVE[1] = 0, CUMULATIVE[L] = CUMULATIVE[L-1] + xpToNext(L-1)), up to MAX_LEVEL.

XPCurve.levelFromTotal(totalXP) -> level            -- highest L with CUMULATIVE[L] <= totalXP, clamped to MAX_LEVEL
XPCurve.progress(totalXP) -> level, xpIntoLevel, xpForNextLevel
    -- xpIntoLevel    = totalXP - CUMULATIVE[level]
    -- xpForNextLevel = xpToNext(level), or 0 at MAX_LEVEL

At cap: xpForNextLevel = 0, bar reads full. TotalXP keeps accumulating past cap harmlessly (U32 range is effectively unbounded for this game).

4. Persistence (XPManager)​

Follows the current ProfileStore API (verified via official docs):

local PlayerStore = ProfileStore.New(XPConfig.STORE_NAME, PROFILE_TEMPLATE) -- STORE_NAME = "PlayerXP"
local Profiles: { [Player]: Profile } = {}

On PlayerAdded:

  1. profile = PlayerStore:StartSessionAsync(tostring(player.UserId), { Cancel = function() return player.Parent ~= Players end }).
  2. If profile == nil → player:Kick(...) (server shutdown / lock contention; ProfileStore's recommended handling).
  3. profile:AddUserId(player.UserId) (GDPR), profile:Reconcile().
  4. profile.OnSessionEnd:Connect(...) → drop from Profiles, kick player to rejoin.
  5. If player still in game → store in Profiles, then replicate initial state to them (§6); else profile:EndSession().
  6. Also iterate Players:GetPlayers() at init for players who joined before the script ran.

On PlayerRemoving: profile:EndSession() and clear from Profiles.

Key = tostring(UserId), store name = "PlayerXP" — identical in both places so the same DataStore record is shared. ProfileStore session-locking serializes the lobby↔gameplay teleport handoff automatically (the new server waits for the old to release). No MessagingService or manual sync required.

5. Award API (XPManager)​

XPManager.AddPartyXP(amount: number)  -- award to every player in the server with a loaded profile
XPManager.AddXP(player: Player, amount: number)  -- single-player primitive (used internally; available for future sources)

AddPartyXP iterates Players:GetPlayers(); for each with a loaded profile it calls the single-player path:

  1. Read old level via XPCurve.levelFromTotal(profile.Data.TotalXP).
  2. profile.Data.TotalXP += amount.
  3. Compute new level, xpIntoLevel, xpForNextLevel via XPCurve.progress.
  4. If newLevel > oldLevel → fire Packets.XPLevelUp:FireClient(player, newLevel).
  5. Replicate Packets.XPStateSync:FireClient(player, level, xpIntoLevel, xpForNextLevel).

Players without a loaded profile are skipped (guard against the join race). Amounts are integers; amount <= 0 is a no-op.

6. Replication & client (XPController)​

Packets (added to Packets/init.luau)​

-- Server → owning Client: authoritative XP/level snapshot for HUD/derived display.
XPStateSync = Packet("XPStateSync",
    Packet.NumberU8,   -- level (1..100)
    Packet.NumberU32,  -- xpIntoLevel
    Packet.NumberU32   -- xpForNextLevel (0 at cap)
)

-- Server → owning Client: the player just leveled up (drives the toast; future reward hook).
XPLevelUp = Packet("XPLevelUp",
    Packet.NumberU8    -- new level
)

Fired to a single player on profile load and on every XP change. XPStateSync is small and low-frequency (distance ticks at most every 5s), so per-tick fan-out is fine.

Signal (added to Signals/init.luau)​

OnXPChanged = Signal() :: Signal.Signal<number, number, number>  -- (level, xpIntoLevel, xpForNextLevel)

XPController.client.luau (both places)​

  • On XPStateSync → fire Signals.OnXPChanged(level, xpIntoLevel, xpForNextLevel) (reserved for a future HUD bar).
  • On XPLevelUp → Signals.RequestNotification:Fire(XPConfig.LEVELUP_NOTIFICATION_TYPE, "Level Up! You reached level " .. newLevel, XPConfig.LEVELUP_NOTIFICATION_DURATION) so the existing NotificationManager shows the toast. The signal signature is Signal<string, string, number?, (()->())?> and the type string must be one of NotificationConfig.Types ("success" | "info" | "warn" | "alert" | "default").

No XP bar GUI is built in this pass; the HUD can later consume OnXPChanged.

7. Earning sources (XPSystemLoader.server.luau, gameplay only)​

local XPManager = require(ServerStorage.SharedModules.XPManager)
XPManager.Initialize()

Distance​

  • Track trainRunning: boolean, updated by Signals.SetTrainState:Connect(running -> trainRunning = running).
  • A 5-second server timer (task.wait(XPConfig.DISTANCE_TICK_SECONDS) loop, or a Janitor-managed task.delay chain): on each tick, if trainRunning then XPManager.AddPartyXP(XPConfig.DISTANCE_XP_PER_TICK).
  • SetTrainState(true) fires only when the train is not braked and not stalled, and the train starts braked (INITIAL_BRAKED = true), so XP never accrues during the frozen pre-start phase.

Kills​

  • Watch the EnemyNPC CollectionService tag (CollectionService:GetTagged for existing + GetInstanceAddedSignal for new).
  • For each tagged model: resolve its Humanoid, connect Humanoid.Died → XPManager.AddPartyXP(XPConfig.KILL_XP). Died fires once, so each enemy awards once.
  • All connections are owned by a Janitor (project rule — no hand-rolled connection arrays). On the tag's GetInstanceRemovedSignal, clean up that entry's connection.
  • Simplification: any EnemyNPC death counts (including environmental/non-player kills), because shared XP needs no killer attribution. A future tightening could require player-attributed kills via CombatService; out of scope here.

8. Configuration (XPConfig.luau)​

XPConfig.STORE_NAME = "PlayerXP"
XPConfig.MAX_LEVEL = 100

-- Curve
XPConfig.CURVE_COEFF = 5
XPConfig.CURVE_EXP = 1.5
XPConfig.CURVE_OFFSET = 45

-- Earning
XPConfig.DISTANCE_TICK_SECONDS = 5
XPConfig.DISTANCE_XP_PER_TICK = 1
XPConfig.KILL_XP = 10            -- per enemy death (tunable; attribution-agnostic)

-- Level-up toast
XPConfig.LEVELUP_NOTIFICATION_TYPE = "success"  -- must be in NotificationConfig.Types
XPConfig.LEVELUP_NOTIFICATION_DURATION = 4

Per project convention, tuning happens here, not in code.

9. Error handling & edge cases​

  • Profile load failure (StartSessionAsync returns nil): kick the player to rejoin.
  • Player leaves before profile loads: EndSession() immediately; never store the profile.
  • Award race: awarding skips players without a loaded profile.
  • Level cap: at level 100, xpForNextLevel = 0; XPLevelUp fires once on reaching 100; further XP raises no level.
  • No players / empty server: distance tick is a no-op.
  • Enemy death de-dup: Humanoid.Died is single-shot per NPC.
  • Connection cleanup: Janitor-managed; per-NPC connection cleaned on tag removal, the distance loop on shutdown.

10. Cross-place / lobby deployment (out of this repo)​

XP/Level are universe-wide because DataStores are universe-wide. Requirements for the lobby place (separate repo/place, not implemented here):

  • Run XPManager.Initialize() (profile lifecycle + replication) so level displays and the session hands off cleanly — but not XPSystemLoader (no earners in the lobby).
  • Deploy XPConfig, XPCurve, XPManager, ProfileStore, and XPController with the same STORE_NAME and the same key format (tostring(UserId)).
  • Run XPController for display/toast.

This spec implements the gameplay place; the lobby mirror is a follow-up deployment task.
