Train Notifications → NotificationManager (Design)

Date: 2026-06-04 Status: Approved (design) Author: brainstorming session

Summary​

Migrate TrainClient off its hand-rolled toast UI and onto the shared Signals.RequestNotification channel, keeping only the two "you're missing something" cases. This mirrors the Shredder → NotificationManager migration: success and exploit-only failures show nothing; only cases a legitimate player can hit and can't otherwise diagnose get a toast.

Guiding principle​

Notifications exist to tell the player they did something wrong or they are missing something. Confirmation of success is left to existing diffuse feedback (the fuel HUD bar filling), not a toast.

Scope — what survives​

Two notifications, both reachable by a legitimate player and both otherwise silent (the action just does nothing):

IDCaseTypeMessage
ARefuel attempted without an energy item to feedwarn (amber)Hold an energy item to refuel.
BRefuel attempted while the fuel tank is already fullinfo (blue)Fuel tank is full.

Scope — what is removed (no toast)​

CaseBeforeRationale for dropping
Refuel success (Refueled +N)success toastFuel HUD bar filling is its own confirmation.
Refuel TOO_FARfailure toastProximityPrompt gates distance; unreachable for legit players.
Refuel INVALID_ENGINEfailure toastExploit-only; never happens legitimately.
Brake success (Train stopped/resumed)success toastLever state + train motion are the confirmation.
Brake STALLED (braking while out of fuel)failure toastDropped per design decision (C).
Brake TOO_FAR / INVALID_LEVERfailure toastGated / exploit-only.

After this change the brake (lever) path shows no notifications at all, and the refuel path shows only A and B.

Trigger mapping​

In TrainClient.client.luau:

  1. PromptButtonHoldBegan on the engine prompt (currently warn() + TODO at ~L181): when playerHasEnergyTool() is false, fire A. Keep the existing 1-second prompt.Enabled = false debounce — it doubles as anti-spam for the toast.
  2. Refuel Triggered result (currently the success/NO_ENERGY/REFUEL_FAIL branches at ~L189-200):
    • success → nothing.
    • reason == TrainResultCodes.NO_ENERGY → fire A.
    • reason == TrainResultCodes.FUEL_FULL → fire B.
    • any other reason → nothing.
  3. Brake Triggered result (currently success/BRAKE_FAIL at ~L225-230): stop calling the toast entirely.

Both A trigger points (1 and 2's NO_ENERGY) share one message string constant so they stay in sync.

Code removed​

  • The TrainToastGui ScreenGui, toastFrame, toastCorner, toastLabel, SUCCESS_COLOR, FAILURE_COLOR, TOAST_TIME, toastSerial, toastTween, and the entire showToast() function (~L49-135, ~75 lines).
  • The REFUEL_FAIL and BRAKE_FAIL lookup tables.
  • The MotionMaster require (verified: only showToast used it).

Code added​

  • Local constants near the top of the file:
    • REFUEL_NOTIF_DURATION = 3 (mirrors Shredder's NO_JUNK_NOTIF_DURATION = 3).
    • NO_ENERGY_MESSAGE = "Hold an energy item to refuel."
    • FUEL_FULL_MESSAGE = "Fuel tank is full."
  • Signals.RequestNotification:Fire("warn", NO_ENERGY_MESSAGE, REFUEL_NOTIF_DURATION) at the two A trigger points.
  • Signals.RequestNotification:Fire("info", FUEL_FULL_MESSAGE, REFUEL_NOTIF_DURATION) at the B trigger point.

Signals is already required in TrainClient; no new requires are added (one is removed).

Non-goals​

  • No Placement "can't place here" toast — the ghost already turns red via OnBuildValidityChanged; a per-misclick toast would be spammy.
  • No Grabhook or Junk notifications — no "wrong/missing" cases exist there (cooldown is communicated by SFX; there is no inventory-full concept).
  • No changes to NotificationManager, NotificationConfig, Signals, or Packets.
  • No server-side changes.

Verification​

No automated tests (per project). Verify in Studio:

  • Trigger refuel with no energy item held → amber "Hold an energy item to refuel." toast (from both the hold-begin and, if reached, the server NO_ENERGY path); no duplicate spam thanks to the 1s prompt debounce.
  • Refuel a full tank → blue "Fuel tank is full." toast.
  • Successful refuel → no toast; fuel HUD bar rises.
  • Brake/resume, and brake while stalled → no toast.
  • Confirm the old TrainToastGui no longer appears in PlayerGui.
