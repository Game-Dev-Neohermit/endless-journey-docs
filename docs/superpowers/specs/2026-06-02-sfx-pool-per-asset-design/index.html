SFX Pool Per-Asset Design

Date: 2026-06-02 Status: Approved

Problem​

The grabhook fire sound (and any other SFX played through SFX.PlayAt) has a noticeable delay on every fire. Root cause: Pool.luau maintains a single shared ObjectPool<Sound>. When a Sound instance is acquired from the pool it almost always has a stale SoundId from its previous use (e.g. ProximityPickup), so setting it to the new asset ID triggers a Roblox-internal reload. sound:Play() is called while sound.IsLoaded == false, causing silent buffering before audio plays.

Solution​

Replace the single shared Sound pool with per-asset sub-pools keyed by asset ID string. A Sound acquired from a sub-pool already has the correct SoundId set — no SoundId change, no reload, no delay. Pool sizing is configurable per SFX in SoundConfig, with small defaults for niche sounds.

Changes​

1. SoundConfig.luau — pool size fields​

Add two optional fields to the SoundDef type:

PoolInitial: number?,  -- pre-allocated slots; default 1
PoolMax: number?,      -- hard cap; default 5

Only GrabHookFire is fired frequently through the pooled PlaySFXAt path, so it is the only entry that overrides the defaults:

KeyPoolInitialPoolMax
GrabHookFire412
all others1 (default)5 (default)

PoolInitial is kept small so the first fire of a session doesn't synchronously construct a large batch of Sound instances on the hot path (the asset bytes are already warm — SoundManager.Init runs ContentProvider:PreloadAsync in the background). The pool expands on demand up to PoolMax.

Which call paths reach the pool: PlaySFXAt is the only path that pools Sounds. Besides GrabHookFire, it is also used by PlacementPlace, PlaceableMove, and PlaceableStash (low-frequency / currently empty IDs — default 1/5 sizing is fine), and remote GrabHookLoop enters the pool on other clients via the replication receive (SFX.ConnectReplication → playPositional, default sizing). PlaySFX (2D one-shot) and PlayLooped do not pool.

2. Pool.luau — per-asset sub-pools​

Replaced:

soundPool: ObjectPool  -- single shared pool

With:

soundSubPools: { [assetId: string]: ObjectPool }  -- one bucket per asset ID

Pool.Acquire(position, assetId, initial?, max?):

  1. Look up or lazily create the sub-pool for assetId using the provided initial/max (or defaults 1/5).
  2. Retrieve a Sound from that sub-pool.
  3. If sound.SoundId ~= assetId (newly allocated instance), set it now.
  4. Acquire a Part from the shared static pool, position and parent it.
  5. Parent Sound to Part; return (Part, Sound).

Pool.Release(part, sound, pitch?):

  • Return Sound to soundSubPools[sound.SoundId] (the correct bucket by current SoundId).
  • Part and pitch return to their existing shared pools — unchanged.

The Part pool and PitchShiftSoundEffect pool are unmodified — they keep their current sizing (Part pool initial 5 / max 20 / expand 5; pitch pool 0 / max 20 / expand 5).

The shared Sound-pool constants are removed; each Sound sub-pool gets its own sizing from the def (or defaults: PoolInitial 1, PoolMax 5).

3. SFX.luau — play ordering + forward pool sizing​

playPositional signature:

local function playPositional(id, position, volume, pitch, poolInitial?, poolMax?)

Pool.Acquire receives id, poolInitial, poolMax.

Play ordering changes from play → wait-if-not-loaded to wait-if-not-loaded → play:

-- before
sound:Play()
if not sound.IsLoaded then
    sound.Loaded:Wait()
end

-- after
if not sound.IsLoaded then
    sound.Loaded:Wait()
end
sound:Play()

This handles first-play-of-session and pool expansion under contention: the coroutine (already task.spawn'd) yields in the background while the asset loads, then plays immediately once ready. All subsequent plays of the same asset are instant — SoundId is unchanged so IsLoaded stays true.

SFX.PlayAt passes def.PoolInitial and def.PoolMax as trailing args to task.spawn(playPositional, ...).

What is not changing​

  • The Part pool and PitchShiftSoundEffect pool remain shared and unmodified.
  • SFX.Play (2D one-shot, parented to SoundService) is not touched.
  • SFX.PlayLooped is not touched.
  • GrabHook.client.luau call sites are not touched.
  • No changes to replication, Groups, Music, or Ambience.
