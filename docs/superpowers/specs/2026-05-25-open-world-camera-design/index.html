ThirdPersonCamera (default) + ShootingCamera + CameraBoom

Date: 2026-05-25

Context​

The project currently defaults to Roblox's stock camera; pressing Alt toggles into the vendored SmoothShiftLock (mouse-locked, character rotates to camera yaw — classic over-shoulder ShiftLock). The May 2026 camera spec (docs/superpowers/specs/2026-05-15-camera-system-design.md) describes a different ShiftLock flavor where the character rotates to movement direction (open-world style), plus a CameraBoom occlusion + zoom-clamp layer.

To avoid confusion between two distinct ShiftLock flavors, this change adopts neutral names:

Old nameNew nameRole
Open World Third Person Camera (= spec's ShiftLock)ThirdPersonCameraDefault camera. Mouse-locked, AutoRotate off, shoulder offset, character rotates to Humanoid.MoveDirection.
Project's current ShiftLock Camera (= SmoothShiftLock)ShootingCameraProgrammatically-entered alt mode. Mouse-locked, AutoRotate off, shoulder offset, character rotates to camera yaw (aim mode).

This change:

  • Makes ThirdPersonCamera the project's default camera on spawn.
  • Removes player-facing toggling. Alt/L3 no longer switch camera modes.
  • Keeps ShootingCamera (via the vendored SmoothShiftLock engine), entered only programmatically through Signals.RequestShootingCamera. The signal is already wired by two existing call sites (GrabHook.client.luau enables on equip / disables on unequip; PlacementClient.client.luau disables on build mode entry) — both get updated to the new signal name as part of this change. No new tool wiring is added.
  • Adds CameraBoom (raycast occlusion + zoom clamp) shared by both cameras, with per-mode max-zoom values.

Spectator mode from the original spec is out of scope.

Approach​

Two new client controllers, a renamed glue script, and config consolidation:

  1. ThirdPersonCameraController.client.luau — implements the default camera (locked mouse, AutoRotate off, shoulder offset, character rotates to Humanoid.MoveDirection). Active at spawn; suspends itself when ShootingCamera engages.
  2. CameraBoomController.client.luau — raycast occlusion + smooth zoom clamp; switches between per-mode max distances based on which camera is active.
  3. ShootingCameraController.client.luau (rename of CustomShiftLock.client.luau) — glue for the vendored SmoothShiftLock engine; unbinds the engine's Alt/L3 context action so player input no longer toggles it.

Mode-state source of truth is Signals.OnShootingCameraToggled (renamed from OnShiftLockToggled). ShootingCameraController fires it from SmoothShiftLock.MouseLockEvent. ThirdPersonCameraController and CameraBoomController subscribe.

Signals.RequestShootingCamera (renamed from RequestShiftLockState) is the programmatic entry point used by tools.

CameraOffset tweens use MotionMaster, not TweenService (per CLAUDE.md: "Do not use TweenService for client-side animations").

The SmoothShiftLock/ vendored package itself is not modified — only its externally-bound context action is unbound (per CLAUDE.md: vendored packages "edited as packages, not ad-hoc").

src/StarterPlayer/StarterPlayerScripts/ThirdPersonCameraController.client.luau (new)​

Controller behavior:

  • On CharacterAdded (and at script start if character exists): rebind humanoid + HRP references. Pattern matches [[project-backpack-replacement]] — never WaitForChild once.
  • Default state (ThirdPersonCamera active):
    • UserInputService.MouseBehavior = Enum.MouseBehavior.LockCenter
    • Humanoid.AutoRotate = false
    • MotionMaster.Create(humanoid, { CameraOffset = CameraConfig.ThirdPersonOffset }, { Duration = OffsetTweenDuration, Model = "EaseOutSine" }), cancelling any prior tween first.
  • RunService:BindToRenderStep("ThirdPersonCameraUpdate", Camera.Value + 1, …):
    • Skip if mode is suspended, character missing, or Humanoid.Sit == true.
    • Re-assert AutoRotate = false, MouseBehavior = LockCenter, CameraOffset = ThirdPersonOffset (defensive; humanoid can be reset by other systems).
    • Read humanoid.MoveDirection; if magnitude > 0.1, compute targetYaw = math.atan2(-moveDir.X, -moveDir.Z) and hrp.CFrame = hrp.CFrame:Lerp(CFrame.new(hrp.Position) * CFrame.Angles(0, targetYaw, 0), RotationLerpSpeed).
  • Signals.OnShootingCameraToggled listener:
    • true (ShootingCamera engaged): suspend updates, set AutoRotate = true, tween CameraOffset back to Vector3.zero. (ShootingCamera will then set its own offset via Camera.CFrame multiply and reapply AutoRotate = false inside its MouseLock.)
    • false (ShootingCamera disengaged): re-engage ThirdPersonCamera state.

src/StarterPlayer/StarterPlayerScripts/CameraBoomController.client.luau (new)​

Port directly from the original spec (2026-05-15-camera-system-design.md lines 357–479) with mode-aware max distance. Skeleton:

local isShooting = false  -- starts in ThirdPersonCamera

Signals.OnShootingCameraToggled:Connect(function(active: boolean)
    isShooting = active
end)

local function getMaxDistanceForMode(): number
    return isShooting
        and CameraConfig.ShootingCameraMaxZoomDistance
        or  CameraConfig.ThirdPersonCameraMaxZoomDistance
end

RunService:BindToRenderStep("CameraBoom", Enum.RenderPriority.Camera.Value, function(dt)
    if not CameraConfig.BoomEnabled then return end
    -- raycast origin = camera.Focus.Position (fallback HRP) → direction toward camera.CFrame.Position
    -- RaycastParams: Exclude character, RespectCanCollide = true
    -- clamped = max(CameraMinZoomDistance, hitDistance - BoomBuffer)
    -- target = min(getMaxDistanceForMode(), clamped) when hit, else getMaxDistanceForMode()
    -- currentDistance lerps toward target by dt * BoomSmoothingSpeed
    player.CameraMinZoomDistance = CameraConfig.CameraMinZoomDistance
    player.CameraMaxZoomDistance = currentDistance
end)

Roblox API note: RaycastParams.RespectCanCollide is the current documented API (verified via Context7 against /roblox/creator-docs). Default is false, so it must be explicitly set to true for the boom to ignore non-colliding decoration parts.

Coexistence Safety​

  • New controllers bind RenderStep at distinct names ("CameraBoom" at Camera.Value, "ThirdPersonCameraUpdate" at Camera.Value + 1).
  • When ThirdPersonCamera is active and ShootingCamera is idle, SmoothShiftLock's internal RenderStepped still runs but its spring target is Vector3.zero (init.luau line 133), so no additional camera offset stacks on top of Humanoid.CameraOffset.
  • When ShootingCamera engages, ThirdPersonCameraController releases ownership (AutoRotate → true, CameraOffset → zero) before yielding the frame, then SmoothShiftLock's MouseLock re-disables AutoRotate and applies its own camera-CFrame offset.

Tuning​

All tunable values live in CameraConfig.luau. Common adjustments:

  • Camera too close/far → CameraMinZoomDistance / ThirdPersonCameraMaxZoomDistance / ShootingCameraMaxZoomDistance.
  • Boom snaps too sharply / too softly → BoomSmoothingSpeed (8–12 reasonable range).
  • Character rotates too slowly toward movement → RotationLerpSpeed (0.3–0.5).
  • Shoulder offset feels off → ThirdPersonOffset (default) or ShootingOffset (aim mode).

Verification​

There is no automated test suite — verification happens in Roblox Studio.

  1. rojo build -o "Game Instance.rbxlx" succeeds with no Luau errors.
  2. Studio playtest, ThirdPersonCamera (default):
    • Spawn in: mouse locked to center, character rotates to movement direction when moving WASD.
    • Walk a circle around a pillar with the camera framed so the pillar is between camera and character — camera pulls in smoothly instead of clipping.
    • Scroll wheel: zoom never goes below 6 studs or above 9 studs.
    • Press Alt — nothing happens. Camera mode does not change.
  3. Studio playtest, programmatic ShootingCamera:
    • In Studio command bar: require(game.ReplicatedStorage.SharedModules.Signals).RequestShootingCamera:Fire(true).
    • Reticle appears, character now rotates to face camera direction instead of movement direction, Humanoid.CameraOffset shifts to (1.75, 1, 0), CameraBoom still clamps occlusion. Temporarily set ShootingCameraMaxZoomDistance = 15 and confirm max-zoom range increases only in this mode.
    • …RequestShootingCamera:Fire(false) → returns cleanly to ThirdPersonCamera; AutoRotate behavior and shoulder offset swap back without a visible camera jump.
  4. Roblox MCP (per [[feedback_roblox_mcp_usage.md]], game-tree inspection only): use mcp__Roblox_Studio__inspect_instance to confirm ThirdPersonCameraController, ShootingCameraController, and CameraBoomController appear under StarterPlayer/StarterPlayerScripts.
  5. Skip Selene per [[feedback_skip_selene]].
  6. Per CLAUDE.md: update Documentations/Project-Maintenance-Guide.md to reflect the renamed config (CameraConfig), renamed signals (OnShootingCameraToggled, RequestShootingCamera), and the three controllers' fan-out.
