Replicated Server Projectiles + C4/Grenade Redesign

Date: 2026-06-07 Branch: feat/weapon-system Status: Design approved, pending spec review

Problem​

The Weapon System v1 projectile model is not truly replicated. The server runs an invisible FastCast2 simulation purely for damage/AOE, while each client independently renders its own cosmetic (the shooter in its handler; everyone else off ProjectileSpawned / GrenadeThrown packets). The only genuinely server-replicated instance today is the C4 resting prop.

Two concrete defects motivate the change:

  1. Grenade vanishes on first contact, then detonates ~3s later with nothing visible on the ground.
  2. C4 uses a raycast-and-stick placement that is inconsistent with the grenade/rocket throw feel, and its cosmetic lives in ServerStorage/WeaponProps while the others live in ReplicatedStorage/WeaponAssets.

The user also wants the in-flight projectile itself to be replicated — one server-spawned instance that Roblox replicates to all clients — rather than N independent per-client cosmetic simulations.

Decisions (locked)​

DecisionChoice
Scope of replicationAll projectiles — rocket, grenade, C4
MoverHybrid: physics for throwables, server-FastCast for rocket

Goals​

  • One server-owned, replicated instance per projectile that flies → rests → detonates, visible identically to every client.
  • Grenade bounces a little, rests visibly on the ground, then detonates on its fuse.
  • C4 becomes a thrown explosive that rests immediately on contact (no bounce), supports MaxActive, and detonates all active charges at once on G.
  • Delete the per-client cosmetic path (ProjectileVisuals) and its packets.
  • Unify rocket / grenade / C4 onto one projectile path and one asset folder.

Non-Goals​

  • No client-side prediction/reconciliation of projectile flight (muzzle/throw FX stay instant; the projectile instance itself appears after the round-trip).
  • No change to hitscan guns, melee, ammo/reload, or the damage authority model (server-side AOE / raycast remains the source of truth).
  • No new VFX beyond what already exists (ExplosionAt blast, impact sparks).

Architecture​

ServerProjectile (new server module)​

Location: src/ServerStorage/SharedModules/ServerProjectile.luau (server-only, required by WeaponServer).

Owns the lifecycle of one spawned, replicated instance:

  • Clones a template from ReplicatedStorage/WeaponAssets (resolved lazily; the folder is Studio-authored and may not exist yet — no blocking top-level WaitForChild, no-op safely until present, matching the existing ProjectileVisuals / C4Server patterns).
  • Parents the instance under a single workspace/ServerProjectiles folder so it replicates to all clients automatically.
  • Keeps projectiles from shoving players without a collision group. In this codebase characters and the world/terrain share the "Default" collision group (there is no separate "Players" group — see DroppedToolService), so a group cannot separate "hits the ground" from "hits a player". Instead each physics projectile part is set Massless = true: it still falls and bounces under gravity, but imparts ~zero impulse on a heavy, network-owned character. To stop the projectile self-colliding with the thrower at spawn, the physics mover spawns it a SPAWN_OFFSET (~2.5 studs) forward of the muzzle along the throw direction.

Two movers behind that one lifecycle:

Physics mover (throwables).

  • Unanchored part, CanCollide = true, Massless = true, part:SetNetworkOwnership(nil) so the server stays the network owner. This keeps the server's position reads authoritative and current, and prevents an exploiter from seizing ownership to teleport the charge — the anti-exploit equivalent of today's server-side cast.
  • Launched with AssemblyLinearVelocity = direction * speed. Gravity, bounce, and settling come from the engine; Roblox interpolates the motion smoothly to every client.
  • The same instance becomes the resting prop — it is not destroyed until detonation.

FastCast mover (rocket).

  • Anchored part stepped along the existing authoritative rocketServerCaster: LengthChanged moves the part's CFrame; Hit applies AOE and destroys it.
  • Reliable high-speed hit (no tunneling). Accepted tradeoff: anchored CFrame replication is not interpolated, so the rocket looks slightly stepped to remote clients — acceptable for a fast, short-lived projectile.

Throwable behavior​

Both throwables launch on an arc via the physics mover and differ only by two config discriminators:

  • Grenade — Rest = "Bounce", Detonation = "Fuse": elasticity lets it bounce and settle; task.delay(FuseTime) reads the part's current position, calls CombatService.ApplyAOE + Packets.ExplosionAt, then destroys the part.
  • C4 — Rest = "Stick", Detonation = "Manual": on the first world Touched, the part is frozen dead (anchored / velocity zeroed) so it rests immediately with no bounce. Each active charge is tracked per player; ReqDetonate (bound to G) detonates all of that player's charges at once and destroys them. MaxActive is enforced at throw time; ArmDelay and PlaceRange are removed; a throw CooldownTime is added.

Hit detection / damage authority (unchanged in spirit)​

All AOE remains server-side and now reads the real replicated instance's position:

  • Rocket → FastCast Hit → ApplyAOE + ExplosionAt + destroy.
  • Grenade → fuse task.delay → ApplyAOE at part position + ExplosionAt + destroy.
  • C4 → ReqDetonate → for each tracked part: ApplyAOE at its position + ExplosionAt + destroy.

Origin/direction anti-exploit validation (finite, near character) on the fire/throw requests is preserved exactly as today.

Config & Type Changes​

WeaponTypes.luau:

  • ThrowableWeaponConfig gains:
    • Detonation: "Fuse" | "Manual"
    • Rest: "Bounce" | "Stick"
    • MaxActive: number? (manual-detonation throwables)
  • Remove PlacedWeaponConfig and the "Placed" member of WeaponCategory (C4 was the only Placed weapon). Update the WeaponConfig union accordingly.

WeaponConfig.luau:

  • C4 entry: Category = "Throwable", Detonation = "Manual", Rest = "Stick", keep MaxActive, add CooldownTime; drop ArmDelay and PlaceRange. Replace PropName with CosmeticTemplate = "C4" (resolved from WeaponAssets).
  • Grenade entry: add Detonation = "Fuse", Rest = "Bounce".

Networking Changes​

Packets/init.luau + docs/reference/networking-map.md:

  • Remove: ProjectileSpawned, GrenadeThrown (no client cosmetic simulation), C4Placed (placement sound replaced by the replicated throw sound).
  • Replace ReqThrowGrenade + ReqPlaceC4 with one ReqThrowProjectile(origin: Vector3, direction: Vector3) — the server infers grenade vs C4 from the requester's equipped Tool.
  • Generalize ReqDetonateC4 → ReqDetonate (no payload; only Manual throwables respond).
  • Unchanged: ReqFireWeapon, WeaponFired, WeaponImpact, WeaponAmmoSync, ExplosionAt.

Client Changes​

  • Delete ProjectileVisuals.luau — no client-side projectile casting remains. (Confirmed sole consumers are ThrowableHandler, WeaponEffectsController, GunHandler, all updated here.)
  • Delete PlacedHandler.luau — C4 no longer raycast-places.
  • ThrowableHandler drives both grenade and C4: gate on cooldown, play the throw sound (replicated) + instant throw anim/recoil (no projectile prediction), send ReqThrowProjectile. Gains OnDetonate (G → ReqDetonate) used by Manual throwables.
  • WeaponController routes C4 to ThrowableHandler and wires the detonate input to handler.OnDetonate when present.
  • GunHandler rocket branch drops the local ProjectileVisuals.fireRocket cosmetic; keeps muzzle FX / recoil + ReqFireWeapon.
  • WeaponEffectsController drops the ProjectileSpawned, GrenadeThrown, and C4Placed handlers (keeps WeaponFired, WeaponImpact, ExplosionAt).

Server Changes​

  • New ServerProjectile module (above).
  • WeaponServer:
    • Rocket branch spawns the replicated anchored part via ServerProjectile and moves it on rocketServerCaster.LengthChanged instead of firing ProjectileSpawned; destroys it on Hit.
    • onThrowGrenade → onThrowProjectile, handling both throwables: physics spawn via ServerProjectile, then Fuse (grenade) or Stick + track (C4).
    • Detonate-all (ReqDetonate) reads tracked C4 instances and detonates them.
  • Delete C4Server.server.luau — placement is gone; throw + detonate fold into WeaponServer.
  • WeaponState: reuse the existing AddPlaced / TakeAllPlaced / GetPlacedCount for tracking active C4 instances (conceptually "active C4"); drop armedAt (no ArmDelay).

Assets (Studio, done by user)​

  • Move the C4 model from ServerStorage/WeaponProps → ReplicatedStorage/WeaponAssets (alongside Rocket, Grenade). The server clones from WeaponAssets for all three projectiles.
  • Retire the WeaponProps folder.

Docs​

Update docs/reference/networking-map.md (packets added/removed) and the weapon system / throwable playbook pages in the same commit as the code change, per the project's docs-with-code rule.

Risks & Mitigations​

  • Rocket choppiness (anchored replication not interpolated): accepted; can revisit with a physics/CCD rocket later if it looks bad in Studio.
  • Throwable physics divergence between clients: Roblox replicates the server-owned part's motion, so all clients see the same instance — divergence is not possible (unlike the old per-client simulation). Server net ownership is the key invariant.
  • Massless projectile feel: a massless part still bounces correctly but, if it ever feels too floaty, switch to CustomPhysicalProperties with a low density rather than fully massless. Verify in Studio.
  • Network ownership API: BasePart:SetNetworkOwnership / SetNetworkOwner name + signature should be confirmed against current Roblox API via Context7 before implementing (training data is stale per project rule).
  • Spawn latency for the shooter: muzzle flash, throw anim, recoil, and sound fire instantly client-side, so the ~RTT delay before the projectile appears is barely perceptible (and hidden by the throw wind-up).
