Camera Consolidation — Design

Date: 2026-06-01 Branch: feat/camera-consolidation Status: Approved (design)

Problem​

The project has two near-duplicate client camera controllers solving the same problem with one differing parameter and one differing polish detail:

  • ThirdPersonCameraController.client.luau — the always-on default camera. Offsets via humanoid.CameraOffset, faces movement direction, snaps the offset in and tweens it out (MotionMaster).
  • ShootingCameraController.client.luau — an aim camera built on the vendored SmoothShiftLock module. Offsets via Camera.CFrame post-multiply, faces camera yaw, springs the offset both directions, adds a reticle.

SmoothShiftLock carries ~80 lines of vestigial machinery (DevEnableMouseLock gating, GameSettings listeners, a PlayerModule BoundKeys hijack, a ContextAction binding, an Available/ShouldEnable/IsEnabled state machine) that the project actively fights: ShootingCameraController force-sets IsAvailable = true, unbinds the Alt/L3 action, and monkey-patches _updateMouseLockEnabledState to keep stripping that binding. This is a maintenance smell and a fragility source.

The two controllers differ functionally in exactly two ways:

  1. Character facing — movement direction vs. camera yaw.
  2. Offset transition polish — snap-in/tween-out vs. spring both ways (plus first-person collapse).

Goal​

Replace both controllers with a single CameraController.client.luau that exposes the same external signal API, ports the two good ideas from SmoothShiftLock (spring transition, first-person collapse), and retires the vendored module and all of its monkey-patching.

Decisions​

  • Free-look facing: face movement direction (preserve current ThirdPersonCameraController behavior). Aim mode faces the camera/reticle.
  • Offsets: keep distinct offsets per mode (aim shoulder offset vs. lighter third-person offset), spring-transitioned between them.
  • Scope: full consolidation — delete the SmoothShiftLock/ module and the monkey-patching entirely.
  • Spring: use MotionMaster.Spring (project's exact-ODE spring driver), not the vendored Spring class.
  • Filename: rename to CameraController.client.luau (no longer third-person-specific).

Architecture​

Files​

  • New: src/StarterPlayer/StarterPlayerScripts/CameraController.client.luau — evolves the existing ThirdPersonCameraController.client.luau into a mode-aware controller.
  • Delete: ThirdPersonCameraController.client.luau (superseded by the rename), ShootingCameraController.client.luau, and the entire src/ReplicatedStorage/SharedModules/SmoothShiftLock/ tree (init.luau, Constants.luau, Dependencies/Maid, Dependencies/Signal, Dependencies/Spring).
  • Keep untouched: CameraBoomController.client.luau (separate occlusion/zoom-clamp layer; continues to listen on OnShootingCameraToggled).
  • Edit: Configs/CameraConfig.luau — add spring tuning constants ported from SmoothShiftLock/Constants.luau.

Signal API (unchanged — zero blast radius outside the controller)​

  • RequestShootingCamera:Fire(boolean?) — external intent to enter/exit aim mode. Fired by GrabHook.client.luau and PlacementClient.client.luau. Unchanged.
  • OnShootingCameraToggled:Fire(boolean) — broadcast when aim mode toggles. Consumed by CameraBoomController. Unchanged.
  • RequestMouseIcon:Fire(boolean) — GUI mouse-cursor request. Unchanged.

Keeping these names means GrabHook, PlacementClient, and CameraBoomController need no edits.

State model​

Two orthogonal booleans (they compose; not a single enum):

  • aimMode — driven by RequestShootingCamera. When true: reticle shown, shoulder offset target, character faces camera yaw, MouseBehavior = LockCenter, cursor hidden.
  • freeLookMode — the existing LeftAlt toggle (current isDefaultCameraMode). When true: free mouse, AutoRotate = true, no custom facing. Only meaningful while not in aim mode.

Precedence: aim wins. Entering aim suspends free-look handling (preserving the current isSuspended semantics); exiting aim restores the prior free-look state.

Offset spring​

A MotionMaster.Spring(humanoid, "CameraOffset", {...}) SpringDriver drives humanoid.CameraOffset directly (it self-connects to the visual step and applies the property each frame), replacing both the instant-set in the current engage() and SmoothShiftLock's Camera.CFrame post-multiply. The controller retargets it via :SetTarget(offset) on mode changes; it does not read/apply the offset in its own render loop.

  • Spring target (via :SetTarget):
    • CameraConfig.ShootingOffset (1.75, 1, 0) when aimMode
    • CameraConfig.ThirdPersonOffset (0.5, 0.3, 0) whenever not in aim mode (both the locked and free-mouse sub-modes — matches the current ThirdPersonCameraController, which keeps ThirdPersonOffset in both). No zero-offset state in normal play; exiting aim eases shoulder → third-person.
  • Driver lifecycle: MotionMaster.Spring binds to a specific humanoid; recreate it on CharacterAdded and :Destroy() it on CharacterRemoving.
  • Both transition directions now ease via the spring (fixes the current snap-in/tween-out asymmetry). The OffsetTweenDuration release tween is removed.
  • Single symmetric spring. SpringDriver has one frequency, so the vendored in-speed/out-speed split is collapsed to a single Omega + Zeta (YAGNI — same ease rate both directions). The driver is recreated per character (it binds to a specific humanoid).

First-person collapse — dropped (YAGNI). SmoothShiftLock collapsed the offset when the camera came within 1 stud of focus. CameraConfig.CameraMinZoomDistance is 6, so under normal play the camera never gets that close and the branch never fires. Not ported.

humanoid.CameraOffset and Camera.CFrame * CFrame.new(offset) operate in the same camera-local space, so driving CameraOffset with the spring reproduces the shoulder framing using the idiomatic mechanism.

Character facing​

Two facing helpers, selected by mode; both skip rotation while humanoid.Sit:

  • Aim: face camera yaw — local _, y = Camera.CFrame:ToOrientation(), target CFrame.new(hrp.Position) * CFrame.Angles(0, y, 0), lerped with 1 - exp(-rate*dt) smoothing (ported from SmoothShiftLock, using the project's existing smoothing form).
  • Free-look (non-default): face movement direction — existing math.atan2(-moveDir.X, -moveDir.Z) logic, unchanged, gated on moveDir.Magnitude > 0.1.
  • Default (free mouse): no custom rotation; AutoRotate = true handles it.

Lifecycle & cleanup​

  • Single RunService:BindToRenderStep("CameraUpdate", Enum.RenderPriority.Camera.Value + 1, ...) drives: offset-spring update, first-person check, mode-appropriate facing, and the defensive MouseBehavior/AutoRotate/cursor re-assert.
  • Character rebind via CharacterAdded/CharacterRemoving (existing pattern); humanoid/hrp cleared on removing.
  • Reticle ScreenGui + ImageLabel + UIAspectRatioConstraint creation moves in from ShootingCameraController; visibility toggled by aimMode.
  • LeftAlt ToggleCameraMode ContextAction binding retained (toggles free-look), sinking input and no-op while in aim mode.
  • Retired with the module: Maids, the Available/ShouldEnable/IsEnabled state machine, the PlayerModule BoundKeys hijack, the Alt/L3 ContextAction binding, and the _updateMouseLockEnabledState monkey-patch.

CameraConfig changes​

Add (single symmetric spring; Speed→Omega, Damper→Zeta from SmoothShiftLock/Constants.luau):

  • OffsetSpringOmega = 22 (natural frequency; midpoint of the vendored 20/25 in/out speeds)
  • OffsetSpringZeta = 0.75 (damping ratio; was TRANSITION_SPRING_DAMPER)

Remove (dead fields, confirmed unreferenced by any code):

  • OffsetTweenDuration — release tween is replaced by the spring.
  • TurnResponsiveness = 24 — never read by any code. Carried forward from the old ShiftLockConfig on the speculation "consumed by SmoothShiftLock internals if referenced" (see 2026-05-25-open-world-camera-design.md); it isn't — SmoothShiftLock uses its own CHARACTER_ROTATION_SPEED. Dead since that refactor.

Note: ShootingOffset is currently orphaned (nothing reads CameraConfig.ShootingOffset; the live shoulder value is the hardcoded LOCKED_CAMERA_OFFSET in SmoothShiftLock/Constants.luau, synced only by a comment). The consolidation wires it up — the controller's aim target reads CameraConfig.ShootingOffset, and the duplicate constant is deleted with the module. Keep ShootingOffset, ThirdPersonOffset, ReticleImage, ReticleScale, RotationLerpSpeed, and all CameraBoom fields.

Out of scope​

  • No changes to CameraBoomController occlusion logic.
  • No changes to the RequestShootingCamera callers (GrabHook, PlacementClient).
  • No new camera modes beyond aim / free-look-third-person.

Verification​

No automated tests (project verifies in Studio). Manual checks after implementation:

  1. Default spawn → third-person offset, character faces movement direction.
  2. LeftAlt → free mouse / AutoRotate; LeftAlt again → locked third-person.
  3. Equip GrabHook / aim → reticle appears, shoulder offset eases in, character faces camera yaw, cursor hidden.
  4. Release aim → offset eases back, reticle hides, prior free-look state restored.
  5. Enter build mode (PlacementClient) → aim disengages cleanly.
  6. CameraBoom still clamps zoom against walls in both modes.
