Proximity Pickup Responsiveness Improvement

Date: 2026-05-15
Status: Design phase
Related: 2026-05-14-proximity-pickup-design.md

Overview​

The current proximity pickup system uses a Heartbeat-based Lerp loop for client animation, which introduces unpredictable timing due to frame-rate-dependent delta times. This creates a visible gap between when an item disappears from the world and when it appears in the player's inventory, making the game feel unresponsive or laggy.

This spec replaces the unpredictable Heartbeat animation with MotionMaster for deterministic, frame-independent timing, and reduces animation duration from 0.9s to 0.25s for snappier feedback. The result is seamless, instant-feeling item pickup that matches the responsiveness of Minecraft.

Problem Statement​

Current behavior:

  1. Client animates item with Heartbeat loop using model.PrimaryPart.CFrame:Lerp(..., math.min(dt * 5, 1))
  2. The Lerp rate (dt * 5) is frame-rate-dependent—high FPS = slower lerp, low FPS = faster lerp, or even complete instant jumps if dt is large
  3. Server separately calls task.delay(FLOAT_DURATION) to grant inventory
  4. Due to timing variance, there's a perceptible delay between visual disappearance and inventory arrival
  5. Animation duration is 0.9s, contributing to the "slow" feel

User impact: Players perceive network lag or poor code optimization when items take time to appear in inventory after visually floating away.

Solution: Deterministic Animation with MotionMaster​

Key Changes​

1. Replace Heartbeat Lerp with MotionMaster

Use MotionMaster.Play() instead of the manual Heartbeat loop. MotionMaster guarantees animation completion in exactly the specified duration, independent of frame rate.

2. Reduce Duration: 0.9s → 0.25s

Tighter timeline = faster visual feedback = feels responsive. 0.25s is the midpoint of the user's 0.2–0.3s target range.

3. Use Linear Easing

Smooth constant-speed motion (not springy or accelerating). Matches user's "smooth constant speed" requirement.

Timing Guarantee​

With this change:

  • Client animation begins at t=0, completes at t=0.25s
  • Server task.delay(0.25) fires at t=0.25s
  • Both fire at the same instant → inventory grant is perceived as immediate
  • No gap between disappearing and inventory arrival

Technical Details​

Client Changes: ProximityPickupController.client.luau​

Current code (lines 41–76):

Packets.PickupItemClaimed.OnClientEvent:Connect(function(itemId: string, claimer: Player)
    local model = trackedItems[itemId]
    if not model then return end
    trackedItems[itemId] = nil

    if claimer == LocalPlayer then
        local heartbeatConn: RBXScriptConnection
        heartbeatConn = RunService.Heartbeat:Connect(function(dt: number)
            if not model or not model.PrimaryPart or not model:IsDescendantOf(workspace) then
                heartbeatConn:Disconnect()
                return
            end
            local character = LocalPlayer.Character
            local hrp = character and character:FindFirstChild("HumanoidRootPart") :: BasePart?
            if not hrp then return end
            model.PrimaryPart.CFrame = model.PrimaryPart.CFrame:Lerp(
                hrp.CFrame * CFrame.new(0, 1, -1.5),
                math.min(dt * 5, 1)
            )
        end)

        task.delay(ProximityPickupConfig.FLOAT_DURATION, function()
            heartbeatConn:Disconnect()
        end)
    else
        model:Destroy()
    end
end)

Replace with:

Packets.PickupItemClaimed.OnClientEvent:Connect(function(itemId: string, claimer: Player)
    local model = trackedItems[itemId]
    if not model then return end
    trackedItems[itemId] = nil

    if claimer == LocalPlayer then
        local character = LocalPlayer.Character
        local hrp = character and character:FindFirstChild("HumanoidRootPart") :: BasePart?
        if hrp and model.PrimaryPart then
            MotionMaster.Play(model.PrimaryPart, {
                CFrame = hrp.CFrame * CFrame.new(0, 1, -1.5)
            }, {
                Duration = ProximityPickupConfig.FLOAT_DURATION,
                Model = "Linear",
            })
        end
    else
        model:Destroy()
    end
end)

Why:

  • Removes Heartbeat loop entirely (simpler, no connection management)
  • MotionMaster handles frame-rate-independent animation
  • Animation guaranteed to complete in exactly FLOAT_DURATION seconds
  • Linear easing = smooth constant speed

Config Changes: ProximityPickupConfig.luau​

Current:

FLOAT_DURATION = 0.9,

Change to:

FLOAT_DURATION = 0.25,

Server: ProximityPickupServer.luau​

No changes needed. The server's task.delay(ProximityPickupConfig.FLOAT_DURATION) already fires when the client animation completes. Reducing the config value from 0.9 → 0.25 automatically tightens server-side timing.

Multiplayer Behavior​

No changes to multiplayer safety. All existing protections remain:

  • Multiple players can pick up different items simultaneously (no queueing)
  • Items float to only the claiming player
  • State machine prevents double-claim
  • Sound queue remains unchanged

Testing Checklist​

  1. Single player: Pick up one item, verify instant appearance in Backpack with no delay
  2. Single player (burst): Pick up several items in quick succession, verify all float smoothly and appear in inventory without overlap
  3. Multiplayer: Two players pick up different items simultaneously, both float and inventory-grant without interference
  4. Edge case: Pick up item while character is moving; item should track toward current hand position (MotionMaster will update to new CFrame as the character moves, since it animates toward hrp.CFrame which is evaluated at play time)
  5. Audio: Pickup sound plays once per item, respecting the existing SOUND_INTERVAL queue (no changes to sound logic)

Out of Scope​

  • Per-item pickup speeds (would require metadata override; add later if needed)
  • Custom easing per item type (linear-only for this pass)
  • Animation curve tweaking (0.25s is fixed; can tune in config later if needed)

Rollback Plan​

If issues arise:

  1. Revert ProximityPickupConfig.FLOAT_DURATION to 0.9
  2. Revert ProximityPickupController.client.luau Heartbeat loop restoration
  3. No database or state changes; fully reversible
