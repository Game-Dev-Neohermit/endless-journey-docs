Weapon System — Design Spec

Date: 2026-06-06 Status: Approved design, pending implementation plan Scope: v1 = full weapon system (melee + guns + rocket + grenade + C4 + ammo/reload + PvE damage contract)

1. Purpose & Scope​

Add a combat weapon system to Endless Journey following the project's client-predicts / server-authoritative pattern with a shared validator.

In scope for v1:

  • Melee weapons — single swing, 1 combo (no chains).
  • Guns — pistol, SMG, AR, SR. All hitscan (instant server raycast).
  • Rocket launcher — FastCast2 projectile with travel time + AOE.
  • Grenade — thrown FastCast2 spherecast arc (bounces, fused) + AOE.
  • C4 — placed prop, remote detonate + AOE.
  • Ammo/reload for guns — magazine + reserve + timed reload, server-authoritative.
  • PvE damage — players damage tagged NPC Humanoids (and players, via existing HealthManager).

Explicitly out of scope (the user builds these):

  • All HUD/GUI. This spec defines a HUD Integration Contract (§11) but builds no UI.
  • Scopes / aim-down-sights. Weapons have no zoom/ADS state.
  • Enemy AI / NPC spawning. The spec defines the damageable contract only; enemy models and behavior are supplied separately.
  • Automated tests (project has none; verification is manual in Studio — see §13).

Decisions locked during brainstorming:

  • Targets: PvE — players damage NPC Humanoids; HealthManager stays player-only and is wrapped by a damage router.
  • Delivery: Roblox Tools equipped from the Backpack (like GrabHook).
  • Ammo: full magazine + reserve + reload.
  • Fire modes: all guns hitscan; only the rocket launcher is a FastCast2 projectile.
  • Architecture: Approach B — per-category handlers over a shared base + a data-driven WeaponConfig registry + a shared validator.

2. Existing Code This Builds On​

  • HealthManager — already defines AttackType = "Melee" | "Bullet" | "AOE", AOEVariant = "Gas" | "Explosion", and ApplyDamage(target, amount, attackType, source, aoeVariant). This is the damage sink for players. It is keyed by Player and does not handle NPC Humanoids.
  • Packets — all new client↔server traffic registers here. Weapon identity is inferred server-side from the equipped Tool (pattern: RequestDrop), keeping fire packets minimal.
  • FastCast2 — projectile engine (Eti/EgoMoose fork by Mawin CK). Serial mode FastCast2.new(), newBehavior(), RaycastFire/BlockcastFire/SpherecastFire, events Hit/LengthChanged/CastFire/ CastTerminating/CanPierce/Pierced, and ObjectCache pooling for cosmetic bullets.
  • Shared-validator precedent: PlacementSystem, SprintValidation, ShredderMath.
  • Anti-exploit precedent: PlacementServer (distance/raycast/cooldown thresholds treated as sensitive).
  • Cross-cutting: Janitor (every lifecycle scope), SoundManager (all audio), MotionMaster (all client animation), Signals (in-process event bus), GenericPoolInstance (instance pooling for effects).

3. Architecture (Approach B)​

Shared (ReplicatedStorage/SharedModules)
├── Configs/WeaponConfig.luau     -- registry: every weapon keyed by name + stats
├── WeaponValidation.luau         -- shared math both sides run (fire-rate, ammo, hitbox, ballistics, AOE falloff)
├── WeaponTypes.luau              -- shared exported types (Category, FireMode, configs, fire payloads)
├── Packets/init.luau             -- new weapon packets (additions)
└── Configs/SoundConfig.luau      -- new weapon SFX entries (additions)

Client (StarterPlayer/StarterPlayerScripts)
├── WeaponController.client.luau  -- bootstrap: watches equipped Tool, reads config, input, predicts, dispatches
└── WeaponHandlers/               -- ModuleScripts required by the controller
    ├── MeleeHandler.luau
    ├── GunHandler.luau           -- hitscan + rocket (FastCast2 client caster)
    ├── ThrowableHandler.luau     -- grenade (FastCast2 client caster)
    └── PlacedHandler.luau        -- C4

Server
├── ServerScriptService/WeaponServer.server.luau   -- receives packets, validates per category, applies damage
├── ServerStorage/SharedModules/CombatService.luau -- damage router: Player → HealthManager, NPC → Humanoid
└── ServerStorage/SharedModules/WeaponState.luau   -- per-player authoritative ammo + cooldown state

Dispatch: WeaponController and WeaponServer own input/lifecycle and dispatch to a handler chosen by WeaponConfig[name].Category. FastCast2 is referenced only inside the gun (rocket) and throwable (grenade) handlers. Each handler is independently understandable: given a config entry and a fire intent, it produces visuals (client) or a validated damage event (server).

Caster ownership: one serial FastCast2 caster per projectile weapon type (one rocket caster, one grenade caster), created once and reused for every shot — never one caster per shot (per FastCast2's own guidance). Client casters use a cosmetic template + ObjectCache; server casters use no cosmetic part (validation/AOE only).

5. WeaponConfig Schema​

Configs/WeaponConfig.luau returns { [weaponName: string]: WeaponConfigEntry }. Types live in WeaponTypes.luau. Tuning lives here, never in code (project convention).

Common fields (all categories):

  • Category: "Melee" | "Gun" | "Throwable" | "Placed"
  • DisplayName: string
  • ToolName: string — the Tool instance name this config binds to
  • Damage: number — base direct-hit damage
  • DamageType: "Melee" | "Bullet" | "AOE"
  • HeadshotMultiplier: number? — applied when the hit part is named Head (default 1, i.e. off)

Melee:

  • SwingCooldown: number — seconds between swings (fire-rate gate)
  • Range: number — reach in studs
  • HitboxSize: Vector3 — OverlapParams box extents in front of the character
  • SwingAnimId: string?, SwingSound: string (SoundConfig key)

Gun (hitscan: pistol/SMG/AR/SR):

  • FireMode: "Hitscan"
  • RPM: number — rounds per minute → server min-interval = 60/RPM
  • Automatic: boolean — hold-to-fire vs semi
  • MagazineSize: number, ReserveMax: number, ReloadTime: number
  • Spread: number — max cone half-angle in degrees (applied to aim direction)
  • MaxDistance: number — hard cap on hit range (anti-exploit + ray length)
  • FireSound, ReloadSound, DrySound (SoundConfig keys)

Gun (projectile: rocket launcher): all hitscan-gun fields except FireMode = "Projectile", plus:

  • ProjectileSpeed: number — studs/sec
  • Gravity: Vector3 — FastCast2 Acceleration (e.g. low or zero for a flat rocket)
  • AOERadius: number, AOEDamage: number — center damage; falls off to 0 at radius
  • CosmeticTemplate: string — name of the rocket model to clone into ObjectCache

Throwable (grenade):

  • ThrowSpeed: number, Gravity: Vector3
  • SpherecastRadius: number — FastCast2 SpherecastFire radius
  • Restitution: number — bounce energy retained per impact (0–1)
  • FuseTime: number — seconds from throw to detonation
  • AOERadius: number, AOEDamage: number
  • CarryCount: number — max carried
  • CosmeticTemplate: string, throw/bounce/explode SoundConfig keys

Placed (C4):

  • PlaceRange: number — max stud distance from character to place
  • MaxActive: number — max simultaneously placed per player
  • ArmDelay: number — seconds after place before it can detonate
  • AOERadius: number, AOEDamage: number
  • place/detonate SoundConfig keys

6. WeaponValidation (shared math)​

WeaponValidation.luau holds pure functions run on both client (predict) and server (authoritative) so the two sides agree:

  • canFire(weaponName, lastFireTime, now) -> boolean — fire-rate gate from RPM/SwingCooldown.
  • applySpread(direction, spreadDegrees, seed) -> Vector3 — deterministic cone spread. The client sends its post-spread direction; the server re-derives/validates the cone bound (the direction must lie within Spread of the reported aim).
  • meleeHitbox(rootCFrame, range, hitboxSize) -> OverlapParams region — the box query both sides use; server runs it from the server-known character CFrame.
  • aoeFalloff(center, hitPos, radius, maxDamage) -> number — linear falloff to 0 at radius.
  • isWithinRange(origin, hitPos, maxDistance) -> boolean
  • ammoAfterShot / ammoAfterReload — pure transitions over { mag, reserve }.

No instance creation, no networking — math only (mirrors ShredderMath/SprintValidation).

7. Authority Flows​

All client→server fire packets carry only what the server cannot already know (origin, aim direction). The weapon is inferred from the player's currently equipped Tool. The server never trusts a client-claimed hit; it re-raycasts or re-simulates.

Melee

  1. Client: input → canFire gate → play swing (MotionMaster/Animator) → predicted hit FX.
  2. ReqMeleeSwing(aimDir) → server.
  3. Server: validate fire-rate (WeaponState), run meleeHitbox from server character CFrame, cap by Range, resolve targets via CombatService, apply Melee damage.
  4. Broadcast WeaponImpact for hit sparks on other clients (swing anim replicates via Animator).

Hitscan gun

  1. Client: canFire + local ammo predict → muzzle flash + tracer to client workspace:Raycast point.
  2. ReqFireWeapon(origin, dir) → server.
  3. Server: validate fire-rate + ammo (WeaponState) + origin within tolerance of the muzzle/ character + Spread bound → server workspace:Raycast (length MaxDistance, filter shooter) → CombatService damage (Bullet, ×HeadshotMultiplier if Head).
  4. Broadcast WeaponFired(shooter, weaponName, origin, hitPos, isHit) → others render tracer/impact.
  5. WeaponAmmoSync to the owner.

Rocket (projectile)

  1. Client: spawn FastCast2 cosmetic rocket via the rocket caster (ObjectCache); LengthChanged moves the part, CastTerminating plays the explosion FX locally.
  2. ReqFireWeapon(origin, dir) → server.
  3. Server: validate fire-rate + ammo + origin → run its own rocket caster (no cosmetic) with Acceleration = Gravity; on Hit, apply AOE via aoeFalloff to all targets in AOERadius (AOE/Explosion).
  4. Broadcast ProjectileSpawned(shooter, origin, dir, speed) so other clients render their own cosmetic rocket; ExplosionAt(pos, radius, weaponName) for the blast FX/sound.

Grenade (throwable)

  1. Client: ReqThrowGrenade(origin, dir) plus a local FastCast2 spherecast arc (bounces via Restitution) for immediate feedback.
  2. Server: validate CarryCount + throw origin; simulate the same spherecast arc; after FuseTime, apply AOE at the grenade's current position.
  3. Broadcast GrenadeThrown(shooter, origin, dir, speed, fuse) → clients render the arc; ExplosionAt at detonation.

C4 (placed)

  1. Client: place preview → ReqPlaceC4(pos, normal).
  2. Server: validate PlaceRange + MaxActive; spawn the armed prop (server-owned), start ArmDelay.
  3. ReqDetonateC4() → server detonates all of that player's armed C4, applying AOE per charge.
  4. Broadcast ExplosionAt per charge.

Trajectory preview (client). While a throwable is equipped, TrajectoryPreview (a WeaponHandlers module) renders a live green neon arc from the camera aim, raycast-truncated to real geometry, ending in a landing marker. It uses the same SPAWN_OFFSET and upward aim bias as the real throw and workspace.Gravity, so the preview matches the projectile's free flight. It is purely client-local — no packets or signals.

8. Ammo & Reload​

WeaponState.luau (server) is the source of truth: per player, per weapon → { mag, reserve }, plus lastFireTime and reloadEndsAt.

  • Fire: server checks mag > 0 and fire-rate; decrements mag; rejects (and sends DrySound cue / no-op) at 0.
  • Reload: ReqReloadWeapon() → server validates not-already-reloading and reserve > 0, sets reloadEndsAt = now + ReloadTime; on completion moves min(MagazineSize - mag, reserve) from reserve to mag. Mid-reload fire is rejected until complete.
  • Client prediction: the client decrements its local mag immediately for HUD responsiveness; the server reconciles via WeaponAmmoSync (authoritative mag/reserve). On mismatch the server value wins.

9. NPC Damage Contract (PvE dependency)​

CombatService.luau (server) is the single damage router:

CombatService.ApplyHit(hitPart, amount, attackType, sourcePlayer, aoeVariant?)
  → resolve hitPart to nearest ancestor Model containing a Humanoid
  → if that Model is a Player's character:  HealthManager.ApplyDamage(player, amount, attackType, sourcePlayer, aoeVariant)
  → elseif Model has CollectionService tag "NPC" and a Humanoid:  damage the Humanoid directly
  → else: ignore (no damage)
CombatService.ApplyAOE(center, radius, maxDamage, attackType, sourcePlayer, aoeVariant?)
  → OverlapParams sphere → for each Humanoid root in range → ApplyHit with aoeFalloff amount

Contract for enemies (supplied separately): an NPC is a Model containing a Humanoid, tagged with CollectionService tag "NPC". That single tag both gates direct Humanoid damage here and places the NPC's parts in the Character collision group (see NpcCollisionService), so thrown charges pass through it. No tag → no damage and no pass-through. NPC death, AI, and spawning are out of scope; v1 damages the Humanoid directly (a dedicated NpcHealth manager can replace the direct path later without changing handlers).

Note: HealthManager mirrors its record → Humanoid.Health but does not read Humanoid → record (see its Audit H3 note). Routing player damage through HealthManager.ApplyDamage (not raw Humanoid writes) keeps the HUD-tracked value correct.

10. New Packets​

Register in Packets/init.luau and document in the networking-map reference (§14).

Client → Server (weapon inferred from equipped Tool):

  • ReqFireWeapon(origin: Vector3, dir: Vector3) — hitscan + rocket.
  • ReqMeleeSwing(aimDir: Vector3)
  • ReqReloadWeapon() — Response: (accepted: boolean, reloadTime: number)
  • ReqThrowGrenade(origin: Vector3, dir: Vector3)
  • ReqPlaceC4(pos: Vector3, normal: Vector3) — Response: (success: boolean, reason: u8)
  • ReqDetonateC4()

Server → all clients (visuals):

  • WeaponFired(shooter: Player, weaponName: string, origin: Vector3, hitPos: Vector3, isHit: boolean)
  • ProjectileSpawned(shooter: Player, origin: Vector3, dir: Vector3, speed: number, weaponName: string)
  • GrenadeThrown(shooter: Player, origin: Vector3, dir: Vector3, speed: number, fuse: number)
  • ExplosionAt(pos: Vector3, radius: number, weaponName: string)
  • WeaponImpact(pos: Vector3, normal: Vector3, weaponName: string)

Server → owning client (state):

  • WeaponAmmoSync(weaponName: string, mag: number, reserve: number)

High-frequency positional packets (if profiling shows need) may move to makeUnreliable following the ghost-update precedent; v1 keeps them reliable.

11. HUD Integration Contract (user builds the HUD)​

This system builds no UI. The user's HUD consumes the following, all already produced by the system above:

  • Ammo: subscribe to the WeaponAmmoSync packet (weaponName, mag, reserve) for the authoritative count, and to a client-side Signals event WeaponAmmoChanged(weaponName, mag, reserve) fired on local prediction for zero-latency updates. The HUD should render whichever is most recent, trusting WeaponAmmoSync on mismatch.
  • Equipped weapon: client Signals events WeaponEquipped(weaponName, category) and WeaponUnequipped(weaponName), fired by WeaponController on Tool equip/unequip. Config (display name, category, mag size) is read from WeaponConfig[weaponName].
  • Reload state: client Signals event WeaponReloadStarted(weaponName, reloadTime) and WeaponReloadComplete(weaponName) so the HUD can show a reload timer/animation.
  • Throwable/C4 counts: WeaponAmmoSync is reused for grenades (mag = carried, reserve = 0) and C4 (mag = remaining, reserve = active-placed), or a dedicated signal if the user prefers — to be finalized in the implementation plan.
  • Crosshair/hitmarker: client Signals event WeaponLocalHit(targetPart) fired when the client's predicted ray hits an NPC; the HUD may show a hitmarker. (Server confirmation is authoritative for damage but not required for the marker.)

New Signals entries to register: WeaponEquipped, WeaponUnequipped, WeaponAmmoChanged, WeaponReloadStarted, WeaponReloadComplete, WeaponLocalHit.

12. Effects, Audio, Cleanup​

  • Visuals: tracers, muzzle flash, impacts, and explosion FX animate via MotionMaster (no TweenService). Reusable effect instances pool through GenericPoolInstance. Cosmetic projectiles (rocket, grenade) pool through FastCast2 ObjectCache.
  • Audio: every sound goes through SoundManager (PlaySFXAt for positional fire/impact/ explosion, PlaySFX for local reload/dry). New asset ids/volumes/pitch live in SoundConfig; the server relay's replication allowlist derives from SoundConfig. No ad-hoc Sound instances.
  • Cleanup: every lifecycle scope owns a Janitor — the equipped Tool (input connections, casters), each in-flight projectile, each placed C4. Keyed collections (active C4 per player, in-flight grenades) store one Janitor per entry (entry.cleaner: Janitor.Janitor). No hand-rolled connection arrays.

13. Anti-Exploit (sensitive thresholds)​

Treated like PlacementServer thresholds. All damage is applied server-side only; client hit claims are never trusted.

  • Fire-rate: server enforces 60/RPM (or SwingCooldown) min interval per weapon; early requests dropped.
  • Ammo: server-authoritative mag/reserve; fire at 0 rejected; reload timing server-stamped.
  • Origin: claimed origin must be within a tolerance of the player's muzzle/character; else reject.
  • Range: hitscan ray length and hit acceptance capped at MaxDistance.
  • Spread: reported dir must lie within Spread of the player's aim; else clamp/reject.
  • Line of sight: implicit — the server does its own raycast/cast, so occluded "hits" never register.
  • Grenade/C4: throw origin and PlaceRange distance caps; CarryCount/MaxActive enforced server-side; ArmDelay enforced before detonation.

15. Verification (manual, in Studio)​

No automated suite. Verify in Studio:

  • Melee: hit and miss on a tagged NPC dummy; range cap; cooldown gate.
  • Each gun: fire-rate cadence, magazine depletion, reload (incl. mid-reload fire rejected), reserve drain, hitscan damage, headshot multiplier.
  • Rocket: travel, impact, AOE falloff at center vs edge of radius.
  • Grenade: arc, bounce, fuse timing, AOE.
  • C4: place within range, max-active cap, arm delay, detonate-all.
  • Exploit checks: spoofed origin rejected, over-rate fire dropped, out-of-range hit rejected, fire with empty mag rejected.

16. Open Questions for the Implementation Plan​

  • Exact grenade/C4 HUD count representation (reuse WeaponAmmoSync vs dedicated signal) — §11.
  • Whether the server should also replicate the rocket's cosmetic via FastCast2 parallel VMs if many players fire rockets at once (deferred; serial is v1).
  • Whether melee should support a light lunge/forward-step (currently pure in-place swing).
  • Damage falloff over distance for guns (v1 = flat damage; falloff is a config-only future add).
