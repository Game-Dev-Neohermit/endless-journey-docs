NPC Projectile Pass-Through & Tag Consolidation — Design

Date: 2026-06-09 Status: Approved design, pending implementation plan Scope: Make thrown weapons (and their trajectory preview) pass through NPCs the same way they pass through players, by putting NPC parts in the Character collision group. Consolidate the Damageable tag into a single NPC tag.

Problem​

Thrown charges (Grenade, C4) and the client trajectory-preview arc collide with NPCs instead of passing through them. The cause is a collision-group gap:

  • CollisionGroups turns off WeaponProjectile ↔ Character only. WeaponProjectile ↔ Default stays collidable.
  • CharacterCollisionService assigns the Character group only to Players' characters — it iterates Players:GetPlayers() and listens to Players.PlayerAdded.

NPCs (Humanoid models, e.g. the hand-placed Workspace.Dummy) are never assigned, so their parts stay in Default. WeaponProjectile collides with Default, so both the server projectile and the client WeaponProjectile-group raycast stop on NPCs.

The design intent is the opposite: projectiles pass through all characters (players and NPCs), and detonation AOE — a spatial Humanoid query, not physical collision — applies the damage.

Decisions (from brainstorming)​

QuestionDecision
How are NPCs detected for group assignment?CollectionService "NPC" tag. A server service assigns the Character group to parts of any "NPC"-tagged model. Explicit, opt-in, future-proof.
New collision group for NPCs?No. Reuse the existing Character group — it already has the correct matrix (WeaponProjectile passes through, DroppedMaterial passes through, collides with world/DroppableSurface). No matrix change.
Keep the Damageable tag?Retire it. Damageable and NPC are 1:1 today (both mean "a non-player Humanoid model"), and Damageable has a single consumer. Consolidate to one NPC tag that drives both collision-group assignment and damage routing.
Code structureSeparate sibling service (NpcCollisionService.server.luau), self-contained, mirroring CharacterCollisionService's pattern. ~8 lines of shared-shape logic duplicated; no refactor of the working player service.
Client (TrajectoryPreview) change?None. Collision groups and their collidable matrix replicate to clients; once NPC parts are in Character, the client WeaponProjectile raycast passes through them automatically.

Caveat accepted​

A single NPC tag cannot express a passive/invulnerable NPC (projectiles pass through, but it can't be damaged). No such NPC exists today; if needed later, reintroduce a separate damage flag at that point. YAGNI — collapse now.

Architecture​

1. New: NpcCollisionService.server.luau​

A server service (in ServerScriptService, sibling to CharacterCollisionService) that places every BasePart of every "NPC"-tagged model into the Character collision group.

  • Requires CollisionGroups (for the Character constant) and Janitor.
  • assign(instance): if instance:IsA("BasePart"), set instance.CollisionGroup = CollisionGroups.Character.
  • watchModel(model): assign every existing descendant, then own a per-model Janitor holding a model.DescendantAdded:Connect(assign) so streamed-in limbs/accessories are caught. Tear the Janitor down when the model loses the tag or is destroyed.
  • Wiring (mirrors CharacterCollisionService but keyed on the tag, not Players):
    • for _, model in CollectionService:GetTagged("NPC") → watchModel.
    • CollectionService:GetInstanceAddedSignal("NPC"):Connect(watchModel) for runtime-spawned/tagged NPCs.
    • CollectionService:GetInstanceRemovedSignal("NPC") → tear down that model's Janitor (untag cleanup).
  • Guard: only watch Instance:IsA("Model") matches (the tag is applied to the model, not individual parts).

2. Modify: CombatService.luau​

  • Rename the tag constant: DAMAGEABLE_TAG = "Damageable" → NPC_TAG = "NPC".
  • The hit-resolution check at the single damage site keys off CollectionService:HasTag(model, NPC_TAG).
  • Update the @class doc comment: the "Damageable NPC contract" becomes the "NPC tag contract" — a Model containing a Humanoid, tagged "NPC", takes direct Humanoid damage; player characters still route through HealthManager.

3. Retire Damageable (manual Studio step)​

In Studio, re-tag Workspace.Dummy (and any other Damageable-tagged model) from Damageable → NPC. After migration, the Damageable tag is unused. This is a developer action, not a code change.

Edge Cases & Cleanup​

  • Streamed-in limbs: handled by per-model DescendantAdded, same as the player service.
  • Untagging at runtime: GetInstanceRemovedSignal tears down the model's Janitor. The parts keep the Character group (harmless — the model is no longer an NPC by tag, but physics behavior is benign); we do not attempt to revert the group.
  • Model destroyed: the per-model Janitor is also torn down on model.Destroying as a backstop.
  • Idempotent group registration: unchanged — CollisionGroups already registers Character once.
  • Player who is also tagged: players are never tagged NPC; no double-handling.

Non-Goals​

  • No new collision group, no change to the collidability matrix.
  • No client/TrajectoryPreview change.
  • No NPC spawning/AI system (out of scope; the tag contract is the integration point for a future spawner).
  • No passive/invulnerable-NPC support (see caveat).

Verification​

No automated suite (per project convention). Verified in Studio after syncing with rojo serve:

  1. Tag Workspace.Dummy as NPC (remove Damageable). Equip a Grenade and aim through the Dummy — the trajectory arc passes through the Dummy (does not stop on it).
  2. Throw the Grenade through/at the Dummy — the projectile passes through the Dummy's body and detonates on world geometry behind/under it.
  3. Confirm the Dummy still takes damage from the detonation AOE (damage routing now via the NPC tag).
  4. Repeat with C4.
  5. Confirm players still collide with each other and the world (no regression from the unrelated Character group).
