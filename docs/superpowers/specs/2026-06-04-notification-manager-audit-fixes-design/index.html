NotificationManager Audit Fixes — Design

Date: 2026-06-04 Status: Approved (design) Topic: Fix all findings from the caveman-review audit of the NotificationManager integration (commits a119899…41b9232).

Background​

A code review of the new NotificationManager found one blocking bug, two behavioral risks, four nits, and one open question. The headline bug makes every notification leak and never animate. This patch resolves all findings in two files with no protocol/signal/packet changes.

Audit Findings → Resolutions​

🔴 Blocking — :Play() returns nil, entrance adds crash show​

MotionMaster.TweenObject:Play() has no return (MotionMaster.luau:782-804), so it returns nil. The five entrance animations in show use cleaner:Add(MotionMaster.Create(...):Play(), "Destroy"), which becomes cleaner:Add(nil, "Destroy") — Janitor then indexes a nil object (Janitor init.luau:283) and throws. The first add (gradient sweep) aborts show before the size tween, the audio call, and the close scheduling: the frame is parented at size (0,0), never animates in, never auto-closes, and the entry leaks in entries forever.

Resolution: Add a contained local helper (do not modify the shared MotionMaster library):

-- Create → track in janitor → play. Optional index lets a new tween on the
-- same property cancel/replace the previous one at that index.
local function track(cleaner: Janitor.Janitor, tween, index: string?)
    cleaner:Add(tween, "Destroy", index)
    tween:Play()
    return tween
end

All five entrance tweens become track(cleaner, MotionMaster.Create(...)). closeEntry already does create→add→play correctly and is left as-is (optionally routed through track for consistency).

🔵/🟡 Unifying fix — shared "sizeTween" index for all frame.Size tweens​

Three places animate frame.Size: the intro (in show), resizeAll, and closeEntry. Janitor:Add(object, method, index) calls Remove(self, index) first (init.luau:263-264), destroying the prior object at that index. Giving every frame.Size tween the shared per-entry index "sizeTween" means a newer size tween automatically cancels the older one.

This resolves in one stroke:

  • 🔵 nit: resizeAll's fire-and-forget MotionMaster.Play (now tracked via track(..., "sizeTween")).
  • race: intro size tween vs. close tween (close replaces intro).
  • race: resize size tween vs. close tween.

resizeAll switches from MotionMaster.Play(frame, ...) to track(entry.cleaner, MotionMaster.Create(frame, ...), "sizeTween"). closeEntry's close tween also uses index "sizeTween".

🟡 Risk — stale camera connection​

getScaled, calcSize, and updateEntryTransparency already read Workspace.CurrentCamera live each call, so only the Init-time ViewportSize connection is stale if CurrentCamera is replaced (respawn / camera swaps).

Resolution: In Init, replace the one-shot connection with:

local function bindCamera()
    local cam = Workspace.CurrentCamera
    if not cam then
        return
    end
    -- Index "cameraViewport": rebinding disconnects the previous camera's listener.
    managerJanitor:Add(
        cam:GetPropertyChangedSignal("ViewportSize"):Connect(requestResize),
        "Disconnect",
        "cameraViewport"
    )
end

managerJanitor:Add(
    Workspace:GetPropertyChangedSignal("CurrentCamera"):Connect(function()
        bindCamera()
        requestResize()
    end),
    "Disconnect"
)
bindCamera()

🟡 Risk — Heartbeat Y-fade fights the intro fade-in​

The shared Heartbeat writes ImageTransparency / TextTransparency to the Y-fade value t every frame, contending with the intro 1 → 0 transparency tweens (visible as a frame-1 flicker; only partially masked by the dirty-check).

Resolution: Add entering: boolean to the Entry type, set true at creation. updateEntryTransparency returns early while entering is true — the toast sits at the bottom (t ≈ 0) during its ~AnimDuration intro, so skipping the Y-fade there is invisible. The intro frame-Size tween's OnComplete sets entering = false, handing transparency control to the Y-fade. (The frame-Size tween is chosen as the intro completion signal because it always exists, including for executed notifications.)

🔵 Nits​

  • Typed any janitors: retype Entry.cleaner and managerJanitor as Janitor.Janitor (the established project convention — see ProximityPickupController, ShredderClient, TrainClient).
  • Double getScaled(): ensureContainer recomputes getScaled() only for the layout padding, but show already computed settings. Change signature to ensureContainer(settings) and pass it through (sole caller is show).
  • Dead config: remove ScrollBarThickness from both Device.Mobile and Device.Desktop in NotificationConfig — the rewrite dropped the ScrollingFrame; the field is unreferenced.

❓ Resolved — lineHeight extra line​

bounds.Y from GetTextSize already includes the full wrapped text height. The extra + lineHeight (= textSize) was a leftover from the old GetTextSize("") line-height hack and adds a phantom line.

Resolution: Drop the extra line. Height becomes:

local totalTextHeight = bounds.Y
return {
    Width = fixedWidth,
    Height = math.ceil(math.max(totalTextHeight + settings.Padding, settings.ImageSize + settings.Padding)),
    TextSize = textSize,
}

Breathing room comes from settings.Padding. This visibly shortens toasts by ~one line and is a Studio-verify item; if the taller look is preferred, reintroduce a fractional factor (e.g. bounds.Y + textSize * 0.3) rather than a full line.

Files Affected​

No changes to Signals, Packets, SoundConfig, the bootstrap controller, or the maintenance guide (behavior and public API are unchanged).

Non-Goals (YAGNI)​

  • No change to the MotionMaster library (Play() return value stays as-is; fix is contained).
  • No new notification types, theming, or server→client packet.
  • No change to the gradient-sweep look, colors, durations, or MaxConcurrent.

Testing​

No automated suite (per project). Studio verification:

  • Fire each of the 5 types; confirm the entrance animation now plays (size + icon/text fade
    • gradient sweep), sound plays, time bar drains, auto-close after duration.
  • Burst past MaxConcurrent; confirm oldest non-executed closes, stack stays bounded, no errors.
  • Resize the window mid-toast; confirm smooth resize, no error spam, no size-tween fighting.
  • Fire an executedFunction toast; confirm it stays until the function returns.
  • RequestClearNotifications; confirm all close cleanly with no leaked entries/connections.
  • Respawn with active toasts; confirm resize still works (camera rebind) and no duplicate GUI.
  • Confirm toast height looks right after dropping the phantom line (lineHeight decision).
