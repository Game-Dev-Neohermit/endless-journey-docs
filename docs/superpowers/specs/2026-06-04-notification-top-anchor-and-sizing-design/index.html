NotificationManager — Top-Anchor Position + Reliable Text Sizing — Design

Date: 2026-06-04 Status: Approved (design) Topic: Fix two reported NotificationManager problems: (1) toasts stack up from the bottom and overlap the hotbar; (2) long messages get clipped (e.g. "You have no junk to shred." shows as "You have no junk").

Background​

The toast stack is anchored to the bottom of the screen and grows upward, colliding with the hotbar. Separately, a width-accounting bug clips long messages: calcSize measures text wrapping in a box wider than the label is actually rendered (the frame's UIPadding is not subtracted), so text wraps to more lines than the computed height allows and ClipsDescendants cuts off the overflow. A dynamic font-growth path (short messages scale up to 34px) makes short messages wrap unexpectedly, worsening the clip.

Decisions taken during brainstorming:

  • Long text: wrap onto multiple lines and grow the toast taller (width stays capped).
  • Font: one fixed readable size (no dynamic growth).
  • Stacking: newest on top, anchored below the Roblox top bar; remove the position-based fade.

Goals​

  • Anchor the stack to the top, below the Roblox top bar, growing downward; newest on top.
  • Long messages wrap and the toast grows taller; nothing is ever clipped.
  • Use a single fixed, readable font size per device.
  • Remove the now-meaningless position-based Y-fade and its per-frame machinery.

Non-Goals (YAGNI)​

  • No change to the public API (Signals.RequestNotification / RequestClearNotifications).
  • No change to colors, icons, sounds, durations, MaxConcurrent, the time-bar, the gradient text sweep, or the intro grow/fade-in animation.
  • No new notification types or theming.

Part 1 — Position & Stacking​

ensureContainer (init.luau)​

  • screenGui.IgnoreGuiInset = false — the stack respects the top-bar inset so it sits below the Roblox topbar / playerlist instead of under them.
  • Container:
    • AnchorPoint = Vector2.new(0.5, 0) (top-center)
    • Position = UDim2.fromScale(0.5, NotificationConfig.TopOffsetScale) (small gap below the inset)
    • Size = UDim2.new(1, 0, 0, 0), AutomaticSize = Enum.AutomaticSize.Y (unchanged)
  • UIListLayout.VerticalAlignment = Enum.VerticalAlignment.Top.

Newest on top (buildFrame)​

The monotonic layoutCounter currently increments so the newest toast has the highest LayoutOrder (sorts last → bottom). Invert it so the newest sorts first (top):

  • Timed toasts: frame.LayoutOrder = -layoutCounter.
  • Executed toasts (none in this project today, but preserve the separation): keep them in a distinct band that still sorts newest-first within the band, e.g. frame.LayoutOrder = -(1_000_000_000 + layoutCounter) so executed toasts sit above timed ones. (Functionally equivalent grouping to today, mirrored for top-anchoring.)

The grow-in size animation is unchanged; a new toast appears at the top and pushes existing toasts down.

Remove the position-based Y-fade​

Delete the scroll-fade machinery — it only made sense for a bottom stack and would render fresh top toasts as half-faded:

  • Remove updateEntryTransparency and the shared RunService.Heartbeat connection in Init.
  • Remove the entering field + its set/clear, the tagged array (and the table.insert(tagged, …) calls), and the lastT field from Entry.
  • Remove FadeStartY / FadeEndY from NotificationConfig.
  • The intro fade-in tweens (icon ImageTransparency, text TextTransparency) and the gradient sweep stay — they are independent of the Heartbeat. The frame keeps its static BackgroundTransparency = BaseTransparency[type]. Toasts hold normal opacity until they shrink-close on timeout / eviction.

Note: with the intro size tween's OnComplete no longer needed to clear entering, the "sizeTween" index and track helper remain (still used for intro/resize/close size tweens); only the entering-clearing callback is removed.

Part 2 — Text Sizing​

Fixed font size​

  • Replace Device.<>.MinTextSize / MaxTextSize with a single Device.<>.TextSize (Desktop ≈ 22, Mobile ≈ 16). The effective size is TextSize * FontScale (existing FontScale clamp stays).
  • getScaled returns TextSize (scaled) instead of MinTextSize/MaxTextSize.

Exact text-area width (measured == rendered)​

calcSize(settings, message, isExecuted) computes the text content width by subtracting every horizontal contributor, matching what the label actually gets:

frameWidth   = min(screenWidth * WidthPercentage, MaxWidth)
horizPadding = settings.Padding * 2                 -- frame UIPadding (left + right)
gap          = settings.Padding * 0.6               -- UIListLayout.Padding between items
reserved     = settings.ImageSize + gap             -- icon + its gap
if not isExecuted then
    reserved += settings.CanvasWidth + gap          -- time-bar + its gap
end
textWidth    = math.max(frameWidth - horizPadding - reserved, 1)
  • Measure once at the fixed size: bounds = GetTextSize(message, textSize, Font, Vector2(textWidth, math.huge)).
  • Height = math.ceil(math.max(bounds.Y, settings.ImageSize) + settings.Padding) (vertical padding = Padding*0.5 top + bottom = Padding). Grows taller for multi-line text.
  • Return { Width = frameWidth, Height = Height, TextSize = textSize, TextWidth = textWidth }.

Label + layout (show / buildFrame)​

  • The text label gets an explicit pixel width: Size = UDim2.fromOffset(sizeInfo.TextWidth, <fill height>). Use Size = UDim2.new(0, sizeInfo.TextWidth, 1, 0) (fixed width, fill height) so it never relies on Scale = 1 (the source of the mismatch). TextWrapped = true stays; TextYAlignment = Center.
  • buildFrame: set UIListLayout.Wraps = false so the icon and label never wrap onto separate rows — only the text wraps internally.
  • ClipsDescendants = true stays (hides content during the grow-in); with the height now exact, it no longer clips final text.

Resize​

resizeAll recomputes via the same calcSize(settings, message, isExecuted) and re-applies the label width and frame size. It must pass isExecuted (read from the entry) so the reserved-width math matches. The time-bar/icon/padding updates stay.

Config Changes (NotificationConfig)​

FieldChange
Device.Mobile.TextSize / Device.Desktop.TextSizeNew. Fixed font size (Mobile ≈ 16, Desktop ≈ 22).
Device.*.MinTextSize, Device.*.MaxTextSizeRemove.
FadeStartY, FadeEndYRemove.
TopOffsetScaleNew. Stack's vertical gap below the top inset, fraction of viewport height (≈ 0.03).

Entry type loses tagged, lastT, entering, and baseTransparency. The frame's static background transparency is already set directly in buildFrame (frame.BackgroundTransparency = NotificationConfig.BaseTransparency[notifType]), so the per-entry baseTransparency copy — read only by the removed fade — is dropped. MaxConcurrent, AnimDuration, AnimEasing, GradientSweepDuration, BaseScreenMin, Colors, ImageIds, BaseTransparency, SfxNames, Types, Font are unchanged.

Testing (Studio — no automated suite)​

  • No-junk info toast → full text "You have no junk to shred.", appears at the top, clear of the hotbar.
  • A deliberately long message → wraps to multiple lines, toast grows taller, no clipping.
  • Burst of 6 (exceeds MaxConcurrent) → newest on top, older pushed down, oldest evicted, stack stays below the top bar and bounded.
  • Resize the window mid-stack → toasts stay correctly positioned and sized.
  • Confirm the intro grow + icon/text fade-in + gradient sweep still play; toasts no longer fade by screen position.

Affected Conventions / Docs​

No new Signals/Packets. If the maintenance guide describes the notification visuals, update the position (top-anchored) and note the fixed font size; otherwise no doc change required.
