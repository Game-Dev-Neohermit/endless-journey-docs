Placeable Stash / Move — Design

Date: 2026-05-26 Status: Approved, ready for implementation plan

1. Goal​

Allow a player to remove a placed item from the world and return it to their inventory through buttons embedded in the placeable's own GUI. Two flavors:

  • Stash — destroy the placed model and put the corresponding Tool back in the player's Backpack.
  • Move — same as Stash, plus auto-equip the new Tool so the player immediately re-enters build mode.

The buttons (MoveButton, StashButton) are invisible ImageButtons that the author of each placeable's GUI places anywhere inside the GUI. Stash/Move are accessible only by opening that GUI (existing per-placeable ProximityPrompt flow — out of scope for this spec).

Any player near enough to open the GUI can stash or move any placed item — no per-instance ownership tracking.

3. Tool template contract (PlaceableTools/)​

Each Tool must satisfy:

  • Name matches a Model name in PlaceableItems/ exactly. Lookup is by name.
  • Attribute PlaceableName equal to the same string. Redundant with Name but kept for consistency with how PlacementServer already reads tool intent.
  • Standard Tool layout: a Handle BasePart. Other attributes/animations are cloned verbatim each time a Tool is spawned.

If no matching Tool exists in PlaceableTools/ when a player clicks Stash or Move, the server silently fails the request. The placed Model remains untouched — players never lose an item to a missing template.

4. Networking​

Three new packets in ReplicatedStorage/SharedModules/Packets/init.luau:

-- Client → Server, with response
ReqStashPlaceable = Packet("ReqStashPlaceable",
    Packet.Instance        -- target Model in workspace.PlacedObjects
):Response(Packet.Boolean8)

ReqMovePlaceable = Packet("ReqMovePlaceable",
    Packet.Instance
):Response(Packet.Boolean8)

-- Server → All Clients, fire-and-forget broadcast for visual + audio cue
BroadcastPlaceablePoof = Packet("BroadcastPlaceablePoof",
    Packet.CFrameF32U16,   -- where the model was (pivot)
    Packet.String,         -- placeableName (to clone visual template)
    Packet.Boolean8        -- isMove (true = Move sound, false = Stash sound)
)

The placed Model reference travels across the wire as an Instance; server resolves it directly for validation.

5. Server validation (PlaceableActionsServer)​

Validation runs in this order for both ReqStashPlaceable and ReqMovePlaceable. Any failure → return false, no destruction, no Tool granted, no broadcast.

  1. Cooldown — per-player, PlacementConfig.PlaceableActions.Cooldown seconds since last successful stash/move by this player.
  2. Type — typeof(target) == "Instance" and target:IsA("Model").
  3. Ancestry — target.Parent == workspace.PlacedObjects (rejects forged targets pointing at arbitrary models).
  4. Attribute — target:GetAttribute("PlaceableName") is a non-empty string.
  5. Template exists — ReplicatedStorage.PlaceableTools:FindFirstChild(name) exists and :IsA("Tool").
  6. Atomic claim — re-check target.Parent == workspace.PlacedObjects, then target.Parent = nil immediately. If target.Parent is already nil here, another player's request won the race; return false.

After validation passes, in order:

  1. Clone the Tool template, parent to player.Backpack.
  2. Move only: if player.Character exists and has a Humanoid, call Humanoid:EquipTool(newTool). Roblox auto-unequips any currently-held tool back into the Backpack — nothing is lost. If no Humanoid, warn and skip the equip step (Tool stays in Backpack); still treat as success.
  3. BroadcastPlaceablePoof:Fire(targetCFrame, placeableName, isMove) to all clients.
  4. target:Destroy().
  5. Record cooldown timestamp.
  6. Return true.

No distance check. Anyone who can open the GUI can act. (Per design choice — the existing ProximityPrompt already enforces locality at the GUI-open step.)

6. Client helper (PlaceableActions module)​

Location: src/ReplicatedStorage/SharedModules/PlaceableActions.luau.

API​

type Binding = { Unbind: (Binding) -> () }

function PlaceableActions.bind(model: Model, gui: GuiObject | LayerCollector): Binding

bind behavior​

  • Recursively search gui for an ImageButton descendant named MoveButton and one named StashButton. Each is optional; missing one logs a warn but doesn't error.
  • Connect MoveButton.Activated → ReqMovePlaceable:Fire(model).
  • Connect StashButton.Activated → ReqStashPlaceable:Fire(model).
  • While a request is in flight for this binding, both buttons are gated locally so the player can't double-invoke. Server-side cooldown remains the authoritative defense.
  • The binding tracks two distinct states:
    • Buttons disabled — set when the model is destroyed (AncestryChanged fires with parent=nil) OR when the caller invokes Unbind(). Disconnects the button Activated signals so dead buttons can't be re-clicked.
    • Explicitly unbound — set ONLY by the caller invoking Unbind(). This is what suppresses the success signal. The model being destroyed must NOT suppress the signal, because the server always destroys the model before returning success — gating on model destruction would mean the signal never fires on the happy path.
  • Returned Binding:Unbind() is idempotent. It disconnects the AncestryChanged watcher, disconnects any remaining button connections, and marks the binding as explicitly unbound.

On :Fire response:

  • success == true and not explicitly unbound → fire Signals.OnPlaceableStashed:Fire(model) or Signals.OnPlaceableMoved:Fire(model).
  • success == false → silent (failures here are exploit / race / config errors, not normal gameplay).
  • Explicitly unbound during the in-flight request → silent regardless of success. The caller's Unbind() cancels interest in the result.

Poof handler (inside same module, IS_CLIENT-guarded auto-init)​

Subscribes to BroadcastPlaceablePoof.OnClientEvent. For each broadcast:

  1. Clone ReplicatedStorage/PlaceableItems/<name> Model. Strip scripts, ProximityPrompts, CollectionService tags, set every BasePart CanCollide=false, Anchored=true, CanQuery=false, CanTouch=false.
  2. Pivot the clone to the broadcast CFrame, parent to a transient workspace.PlaceablePoofs Folder (created lazily on first poof).
  3. Run a MotionMaster.Sequence({ Parallel = true, ... }) of per-BasePart tweens:
    • Size → Vector3.new(0.05, 0.05, 0.05) (Roblox refuses true zero on some parts)
    • Transparency → 1
    • Duration PlacementConfig.PlaceableActions.PoofDuration, model EaseInQuad.
  4. Play PlacementConfig.Sounds.Stash or Sounds.Move at the position via the existing playSoundAtPosition pattern (reuse from PlacementClient or duplicate the helper inside this module).
  5. On sequence complete, destroy the clone.

7. Signals​

Two new signals in ReplicatedStorage/SharedModules/Signals/init.luau:

OnPlaceableStashed = Signal() :: Signal.Signal<Model>,
OnPlaceableMoved   = Signal() :: Signal.Signal<Model>,

Both fire on the requesting client only, after a success=true response. Other clients are not signaled — they receive the BroadcastPlaceablePoof instead. (If a future feature needs cross-client awareness, add a separate broadcast packet rather than overloading these signals.)

8. Config additions (PlacementConfig.luau)​

-- Inside the existing Sounds table:
Sounds = {
    Place  = "...",          -- existing
    Rotate = "...",          -- existing
    Stash  = "",             -- new — empty string skips playback (existing convention)
    Move   = "",             -- new
}

-- New top-level table:
PlaceableActions = {
    Cooldown     = 0.4,      -- seconds, per-player, between stash/move requests
    PoofDuration = 0.25,     -- seconds, scale-down + sound timing
}

9. Existing-code edit (PlacementServer.server.luau)​

One line added in the PlaceItem handler, immediately after placed:PivotTo(ghostCFrame):

placed:SetAttribute("PlaceableName", itemName)

This is the attribute the stash/move validator reads to identify which Tool template to spawn. No other behavior changes.

10. Edge cases​

CaseHandling
Two players click Stash on same model same frameAtomic claim (step 6) ensures one wins; loser silently gets success=false.
Player clicks Stash on a model already mid-destroyAncestry check (step 3) fails → false.
Move requested but player just died (no Character)Falls back to Stash behavior — Tool lands in Backpack without auto-equip. success=true.
Move requested but no Humanoid on Characterwarn, skip equip step, Tool in Backpack. success=true.
Backpack capped (project later adds limit)Out of scope — engine default Backpack has no cap; not handled by this feature.
Placeable template renamed / missing in PlaceableTools/Validation step 5 fails → false. Model stays placed; no items lost.
bind() called twice on same model without unbinding the firstBoth bindings remain active independently. Caller's responsibility to Unbind on GUI close.
Server cooldown rejects mid-burst clicksLocal in-flight gate already prevents double-clicks; cooldown catches scripted spam. Silent drop.
Broadcast poof arrives for a placeable whose template was just removedFindFirstChild returns nil → skip the visual silently; sound still plays.

11. Documentation deliverable (Project-Maintenance-Guide.md)​

Add a "Placeable Actions (Stash / Move)" section containing:

  • Networking-map entries for ReqStashPlaceable, ReqMovePlaceable, BroadcastPlaceablePoof.
  • Signals-map entries for OnPlaceableStashed, OnPlaceableMoved.
  • How to enable Stash/Move on a new placeable — step by step:
    1. Confirm the placeable already has a Model in ReplicatedStorage/PlaceableItems/<Name>.
    2. Add a Tool to ReplicatedStorage/PlaceableTools/<Name> with the attribute PlaceableName = "<Name>". The Tool must have a Handle BasePart.
    3. In the placeable's GUI (the one opened by its existing ProximityPrompt), add two ImageButtons named exactly MoveButton and StashButton. They can sit at any depth inside the GUI. To make them invisible but clickable: ImageTransparency = 1, BackgroundTransparency = 1.
    4. In the controller script that opens that GUI, when showing it for a specific placed model: 
      local PlaceableActions = require(ReplicatedStorage.SharedModules.PlaceableActions)
      local binding = PlaceableActions.bind(placedModel, guiRoot)

      -- Later, when the GUI closes:
      binding:Unbind()
    5. (Optional) Set PlacementConfig.Sounds.Stash and .Move to asset IDs for audio feedback. Empty string is silent.
  • Caveats callout: without a matching Tool in PlaceableTools/, Stash/Move silently fail for that placeable. Always pair a new placeable Model with a new Tool template in the same PR.

12. Out of scope​

  • The per-placeable ProximityPrompt and its GUI-opening logic (assumed pre-existing per the user's setup).
  • Inventory persistence / DataStore — Tool grant is purely runtime.
  • Per-instance state preservation (e.g. a Workbench mid-shredding when stashed): the stash discards everything; the new Tool spawns from the clean template. If state preservation is needed later, add an attribute-snapshot step before destroy.
  • UI animation for the buttons themselves (hover / press feedback) — author of the GUI handles that.
  • Anti-grief rules beyond the cooldown (e.g. "can't stash someone else's Workbench mid-craft"). Game design decision deferred.
