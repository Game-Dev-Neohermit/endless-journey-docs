Placement Sound Delay Fix — Design Spec

Date: 2026-05-26 Status: Approved

Problem​

The placement sound (PlacementConfig.Sounds.Place) plays with variable latency — sometimes instant, sometimes 0.x seconds, occasionally 1–2 seconds. The delay is inconsistent.

Root cause: playSoundAtPosition in PlacementClient.client.luau creates a new Sound instance on every placement, sets SoundId, and immediately calls :Play(). Roblox's audio engine must asynchronously load the asset before playback can start. When the asset is not in the engine's cache, this load takes an unpredictable amount of time.

Scope​

Single-file change: src/StarterPlayer/StarterPlayerScripts/PlacementClient.client.luau

No changes to: PlacementConfig, PlacementSystem, server scripts, Packets, or any other module.

Design​

Pre-created 3D audio emitter​

At module initialization (after the existing module-level state block), set up a persistent audio emitter if PlacementConfig.Sounds.Place is non-empty:

  1. Create an invisible, anchored Part in workspace:
    • Anchored = true, CanCollide = false, CanQuery = false, CanTouch = false
    • Transparency = 1, Size = Vector3.one
  2. Create a Sound as its child with SoundId = PlacementConfig.Sounds.Place.
  3. task.spawn a call to ContentProvider:PreloadAsync({sound}) to buffer the asset in the background without blocking client startup.

The Part and Sound are module-level locals, reused for the lifetime of the client session.

If PlacementConfig.Sounds.Place is "", skip creation entirely — the call site guards on nil.

Replacement call site in tryPlace​

Remove playSoundAtPosition entirely. Replace the call at the existing placement site with:

if placeSoundPart and placement.TargetGhostCFrame then
    placeSoundPart.Position = placement.TargetGhostCFrame.Position
    placeSound:Play()
end

No new instances created. No cleanup needed — the Part is persistent.

playSound2D (rotate sound)​

Unchanged. Rotate SoundId is currently "" (no-op). The same pre-create pattern can be applied when a rotate sound is added.

What is removed​

  • The playSoundAtPosition function (replaced inline).
  • The per-placement Instance.new("Part") and Instance.new("Sound") allocations.
  • The sound.Ended:Once(destroy) cleanup callback.
  • The task.delay(10, ...) safety destroy.

Trade-offs accepted​

  • The persistent Part occupies one workspace slot for the session (negligible).
  • Two simultaneous placement sounds from the same client cannot overlap (not a real scenario — placement is one-at-a-time per client).
