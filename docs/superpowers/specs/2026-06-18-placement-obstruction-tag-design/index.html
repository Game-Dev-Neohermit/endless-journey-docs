Placement Obstruction Tag — Design

Date: 2026-06-18 Status: Approved (Approach B — fully tag-based)

Problem​

The build placement system lets a player place an item (e.g. Workbench) directly inside an already-existing world fixture such as the Train Shield Generator or the Tech Tree Bench. The overlap check never detects these fixtures.

Root cause​

PlacementSystem.BuildObstructionFilter builds the GetPartBoundsInBox include filter from exactly three sources:

  1. PlacedObjects folder (items placed through the placement system)
  2. Player characters
  3. Enemy-tagged instances

The shield generator and tech-tree bench are ...Placeholder models parented loose directly under Workspace — they were never routed through the placement system, so they appear in none of the three buckets. The overlap query literally never tests them, so a ghost drops straight through.

Their CollisionBox parts are CanQuery = true, so the moment a CollisionBox is included in the filter, GetPartBoundsInBox detects it. The fix is purely about what goes into the filter, not about the detection mechanism.

Note: placed-vs-placed collision already works (via the folder). Only static world fixtures are affected.

Approach — Fully tag-based (Approach B)​

A single CollectionService tag, PlacementObstruction, becomes the sole source of truth for "this volume blocks build placement." The filter no longer depends on folder membership or hierarchy.

Why B over a hybrid (keep folder + add tag for fixtures)​

GetPartBoundsInBox cost scales with the number of filtered parts in the query region, and it runs every Heartbeat while a ghost is active. Including placed items as whole models forces the broadphase to test every visual mesh (the Workbench alone is 23 MeshParts). Tagging only the CollisionBox means the query tests one box per obstruction instead of its full mesh hierarchy — cheaper than the system is today, and uniform across fixtures and placed items.

Tagging granularity: CollisionBox part, never the model​

TechTreeBenchPlaceholder contains a TrajectoryPoints sub-model whose parts are scattered across the map. Tagging the whole model would turn every trajectory point into a placement blocker. Tags are therefore applied to the single CollisionBox part of each obstruction.

Changes​

1. PlacementSystem.luau​

  • Add module constant OBSTRUCTION_TAG = "PlacementObstruction".
  • BuildObstructionFilter: replace the self.PlacedObjectsFolder entry with CollectionService:GetTagged(OBSTRUCTION_TAG). Keep GhostModelsFolder, player characters, Enemy-tagged instances, and the extra argument.

2. PlacementServer.server.luau​

  • In finalizeModel, when a part is the CollisionBox, add the PlacementObstruction tag to it (so placed items participate via the tag instead of the folder).
  • Fallback: if a placeable has no CollisionBox part, tag the model's PrimaryPart (or the model itself) so it still blocks placement.
  • The PlacedObjects folder remains as the organizational parent for placed items; it is simply no longer the collision source of truth. Tags set on the server replicate to clients automatically, so the client preview filter sees them.

3. Docs​

  • Update docs/systems/placement.md and the model-structure contract: any static world model that build placement must respect needs its CollisionBox tagged PlacementObstruction.

Edge cases​

  • Ghost self-collision: the active ghost is never tagged (lives in GhostModels / ServerStorage) and is additionally excluded via GhostOwnParts.
  • Revert path: RequestPlacementRevert reuses BuildObstructionFilter, so it inherits the fix with no extra change.
  • Client visibility: fixture tags live in the .rbxlx and replicate; placed-item tags are set server-side and replicate. Both are visible to the client filter.

Out of scope​

  • Changing how placed items are organized (they stay in PlacedObjects).
  • Any rework of the raycast / surface-resolution path.

Manual actions required (post-implementation, in Studio)​

These are design-time .rbxlx edits that the code change does not perform. They must be done by hand in Studio after the code is synced, or the fix will not take effect for the existing fixtures:

  • Tag Workspace.TrainShieldGeneratorPlaceholder.CollisionBox with the CollectionService tag PlacementObstruction (Tag Editor or CollectionService:AddTag).
  • Tag Workspace.TechTreeBenchPlaceholder.CollisionBox with PlacementObstruction.
  • Any other static world model that build placement should respect: ensure it has a CollisionBox part and tag that part PlacementObstruction.
  • Verify in Studio (playtest): attempt to place a Workbench overlapping the shield generator and the tech-tree bench — the ghost should turn invalid and placement should be rejected. Also confirm placed-vs-placed collision still works.
