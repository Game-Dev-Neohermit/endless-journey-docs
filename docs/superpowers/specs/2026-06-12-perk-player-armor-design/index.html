Perk System — Player Armor (Spec 3 of 5)

Date: 2026-06-12 Status: Approved for planning Game: Endless Journey (Roblox / Rojo / Luau) Series: Spec 3 of 5 — depends on Spec 1 (Perk Framework). Prerequisite: Spec 1 implemented (the Armor perk is declared in PerkConfig and publishes PerkBuffs/<UserId>.ArmorReduction, but no consumer reads it yet).

Summary​

Implement the Player Armor personal perk as flat percentage incoming-damage reduction, applied at the single server-side damage chokepoint HealthManager.applyDamageInternal. There is no separate armor item or resource in the game, so "armor efficiency" is modeled directly as damage mitigation: at level 10 (PerLevel = 0.025) the player takes 25 % less damage from every source.

This is a surgical, single-function change — comparable to Spec 2's hooks — kept as its own spec because it's the only defensive mitigation and touches the sensitive damage path.

Decisions (locked)​

TopicDecision
Armor modelFlat % damage reduction, not an armor pool/resource (none exists). damage = damage * (1 − ArmorReduction)
ChokepointHealthManager.applyDamageInternal — the one place all player damage (Melee, Bullet, AOE, environment) is subtracted from health
Sources coveredAll incoming damage, including environment/hazard and NPC attacks (it's incoming mitigation, independent of attacker)
Safety capHard-clamp total reduction to 0.75 so future stacking sources can never reach immunity
Live updatesReads the attribute per damage event (no caching); mid-combat allocate/respec applies on the next hit

Architecture​

One edited file. Reads the Spec 1 buff folder; no new modules, packets, GUI, or persistence.

ServerStorage/SharedModules/HealthManager.luau
  -- applyDamageInternal: reduce `amount` by ArmorReduction before subtracting from health

Component & responsibility​

applyDamageInternal(player, info) currently finalizes amount and runs record.Health = math.max(0, record.Health - amount). Insert the mitigation just before that:

-- Player Armor perk: flat % incoming-damage reduction (Spec 3).
local buffs = ReplicatedStorage.PerkBuffs:FindFirstChild(tostring(player.UserId))
local reduction = buffs and (buffs:GetAttribute("ArmorReduction") :: number?) or 0
reduction = math.clamp(reduction, 0, 0.75)         -- safety cap
amount = amount * (1 - reduction)

record.Health = math.max(0, record.Health - amount)

Because this is the single sink for all damage routed through HealthManager, every attack category is covered without per-call-site edits. The attacker is irrelevant — this is the defender's mitigation, so it composes naturally with the attacker's Spec 2 DamageBonus (attacker scales up, defender scales down, both server-authoritative).

Data flow​

Any damage → HealthManager.ApplyDamage → applyDamageInternal reads PerkBuffs/<UserId>.ArmorReduction, clamps, multiplies amount → health subtracted → synced. Allocating/respeccing Armor changes the attribute (Spec 1 dispatcher); the next damage event reflects it.

Edge cases & anti-exploit​

  • Server-side read of a server-written attribute — unforgeable by clients.
  • No negative/over-100 % reduction: math.clamp(reduction, 0, 0.75) guards against config typos or future additive sources stacking to immunity.
  • Order vs other modifiers: armor is applied to the final post-attacker-bonus amount, so attacker DamageBonus and defender ArmorReduction multiply independently (base * (1 + DamageBonus) * (1 − ArmorReduction)).
  • Death still fires: mitigation only scales amount; the existing record.Health / Humanoid mirror and death handling are unchanged.
  • No record / dead player: existing guards (record == nil, record.Health <= 0) run first; armor never resurrects or no-ops incorrectly.
  • Rounding: health is tracked as a float and mirrored to the Humanoid as today; no integer rounding is introduced (avoids a 1-damage attack being fully negated by rounding).

Future extension (out of scope, noted)​

If a real armor item/resource (equippable plates, durability) is added later, "Armor efficiency" can be re-pointed to scale that item's effectiveness instead of being flat global reduction. The buff key (ArmorReduction) and the chokepoint stay the same; only the meaning of the number changes. No perk-framework change required.

Out of scope (this spec)​

  • An armor pool/resource/equipment system.
  • Per-damage-type resistances (all types share one reduction).
  • Any new perks, packets, GUI, or persistence (all in Spec 1).
