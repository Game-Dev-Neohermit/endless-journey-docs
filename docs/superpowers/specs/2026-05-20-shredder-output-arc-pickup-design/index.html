Shredder Output Arc → Proximity Pickup Fix

Date: 2026-05-20
Branch: overhaul-proximity-item
Status: Approved

Problem​

After a workbench shredder ejects a material item and its arc animation completes, the item gains CanCollide = true and briefly becomes Anchored = false. This means:

  • A player standing at the landing spot is physically blocked by the item.
  • There is a brief unanchored physics window before ProximityPickupServer.RegisterItem re-anchors the part.

Root cause: Two concurrent paths both fire after each arc — tw:OnComplete (which sets CanCollide = true / Anchored = false) and task.delay(ARC_DURATION, ...) (which calls RegisterItem). They race, and CanCollide is never reset afterward.

Desired Item Lifecycle​

Spawned at SpawnPoint
  CanCollide = false, Anchored = true
        ↓
  Arc animation (MotionMaster.SplineMove, server-side)
  All clients see arc via Roblox part replication
        ↓
  Lands at randomised position
  CanCollide = false, Anchored = true  ← STAYS this way
        ↓
  ProximityPickupServer.RegisterItem called immediately in OnComplete
  → PickupItemReady fires → client HoverEffect + spin starts
  → Pickup zone goes live
  → Auto-collect timer running in parallel
        ↓
  Player walks into zone (or auto-collect fires)
  → executeClaimAsync: CanCollide = false on all parts (no-op, already false)
  → PrimaryPart.Anchored = false (for float animation)
  → Callback: mat.Parent = player.Backpack

What Changes​

File: src/ServerScriptService/ShredderServer.server.luau
Function: ejectMaterials

Remove​

  • The tw:OnComplete lines that set handle.CanCollide = true and handle.Anchored = false.
  • The entire separate task.delay(ShredderConfig.ARC_DURATION, function() ... end) block.

Add​

Inside tw:OnComplete (after tw:Destroy()):

  1. Explicitly assert handle.CanCollide = false and handle.Anchored = true (defensive, in case something changed the state mid-arc).
  2. Early-return if handle.Parent is nil (model cleaned up mid-arc).
  3. Call ProximityPickupServer.RegisterItem(mat, metadata, pickupCallback, true).
  4. Call CollectionService:AddTag(mat, "CraftMaterial").
  5. Connect mat.AncestryChanged for the re-register-on-drop path (moved here from the deleted task.delay block; logic identical).

Unchanged​

  • droppedMaterials table insert (still happens at spawn, before the arc).
  • Auto-collect loop.
  • ProximityPickupServer.Claim path in auto-collect.
  • DroppedToolService — only watches direct workspace children, not DroppedMaterials folder.
  • ProximityPickupController — PickupItemReady arrival triggers HoverEffect and spin; no change.
  • ProximityPickupServer.executeClaimAsync — already sets CanCollide = false on all parts; now a no-op for this path, but harmless.
