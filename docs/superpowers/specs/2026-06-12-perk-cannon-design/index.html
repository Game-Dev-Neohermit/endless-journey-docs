Perk System — Cannon + Cannon Damage Perk (Spec 5 of 5)

Date: 2026-06-12 (cannon-gameplay brainstorm resolved 2026-06-14) Status: Approved for planning — cannon gameplay brainstorm complete; assumptions resolved below Game: Endless Journey (Roblox / Rojo / Luau) Series: Spec 5 of 5 — depends on Spec 1 (Perk Framework); reuses the Weapon stack (FastCast2, ServerProjectile, CombatService) and the Placement stack (PlacementSystem, PlaceableItems, PlacedObjects). Prerequisite: Spec 1 implemented — the CannonDamage perk is declared in PerkConfig and the dispatcher auto-publishes PartyPerkBuffs.CannonDamageBonus (party max); this spec adds the cannon that consumes it.

Scope note (read first)​

The Cannon Damage perk is a one-line multiplier on a cannon's damage. The cannon itself is a substantial new combat feature; its gameplay forks were flagged for a dedicated brainstorm in the original draft. That brainstorm is now complete and its outcomes are folded into this spec (see "Resolved decisions"). The perk hook is stable regardless: finalDamage = base * (1 + CannonDamageBonus).

Summary​

A grid-placeable, manned cannon that a player mounts to fire explosive arc shells at enemies, dealing area damage. It reuses the existing weapon infrastructure (FastCast2 projectile simulation, CombatService.ApplyAOE) and the existing placement infrastructure (PlacementSystem → workspace/PlacedObjects) rather than inventing new systems. Firing is gated by a cooldown + an overheat gauge. The Cannon Damage party perk multiplies its shell damage by the resolved CannonDamageBonus.

Architecture​

Reuses the weapon stack (server-authoritative shell, like the rocket path in WeaponServer) and the placement stack (the cannon is a placeable).

ReplicatedStorage/SharedModules/Configs/CannonConfig.luau      -- NEW: damage, AOERadius,
  -- fireCooldown, shellSpeed, gravity, maxAimDistance; heat params (HeatPerShot, HeatDecayPerSec,
  -- MaxHeat, OverheatLockTime); CANNON_TAG, part names (Muzzle/MountPrompt/Seat), placeable name,
  -- ENEMY_SHIP_TAG, FX/sound keys

ServerScriptService/CannonServer.server.luau                   -- NEW: discovers placed cannons by
  -- tag in PlacedObjects (GetInstanceAddedSignal, one Janitor per cannon); mount/dismount auth;
  -- validates fire (occupant, cooldown, overheat, finite/unit direction); re-simulates shell via a
  -- FastCast2 caster with Acceleration = gravity; applies AOE scaled by CannonDamageBonus; tracks
  -- per-cannon heat as model attributes

StarterPlayer/StarterPlayerScripts/CannonController.client.luau -- NEW: mount UX, seat/anchor gunner,
  -- aim camera, trajectory preview (reuse WeaponHandlers/TrajectoryPreview), fire input, barrel
  -- snap, muzzle flash/impact FX (WeaponEffectsController patterns + SoundManager), dismount

StarterPlayer/StarterPlayerScripts/CannonGuiController.client.luau -- NEW: gunner heat bar HUD,
  -- overheat lockout state + FX; reads Heat/Overheated attributes off the placed cannon

ReplicatedStorage/PlaceableItems/Cannon (Studio-authored Model)  -- NEW: VisualMesh, CollisionBox,
  -- Muzzle, MountPromptPart, Seat (authored in Studio; reported, not script-created)

Packets/init.luau   -- + ReqMountCannon, ReqFireCannon, CannonFired (impact reuses ExplosionAt)
Signals/init.luau   -- (optional) OnCannonMounted / OnCannonDismounted (HUD/camera bridge)

Damage application reuses CombatService.ApplyAOE(center, radius, damage, "AOE", source, ignore) — the same path grenades/rockets/C4 already use — so faction rules and player/NPC routing are inherited for free for EnemyNPC Humanoid rigs.

Config (new)​

CannonConfig.CANNON_TAG = "Cannon"          -- CollectionService tag on the placeable Model
CannonConfig.PROMPT_PART_NAME = "MountPromptPart"
CannonConfig.MUZZLE_PART_NAME = "Muzzle"
CannonConfig.SEAT_PART_NAME = "Seat"
CannonConfig.PLACEABLE_NAME = "Cannon"      -- matches the PlaceableItems entry
CannonConfig.ENEMY_SHIP_TAG = "EnemyShip"   -- forward seam (no ship HP this spec)

CannonConfig.Damage = 120                   -- base shell damage (perk multiplies this)
CannonConfig.AOERadius = 14
CannonConfig.FireCooldown = 2.0             -- seconds between shots (burst rate cap)
CannonConfig.ShellSpeed = 180              -- studs/sec
CannonConfig.Gravity = Vector3.new(0, -workspace.Gravity, 0)  -- arc (FastCast2 Acceleration)
CannonConfig.MaxAimDistance = 1000

-- Overheat
CannonConfig.HeatPerShot = 0.25            -- fraction of MaxHeat added per shot
CannonConfig.MaxHeat = 1.0
CannonConfig.HeatDecayPerSec = 0.20        -- cools while not firing
CannonConfig.OverheatLockTime = 3.0        -- seconds locked once MaxHeat is reached

-- FX/sound keys resolved via SoundManager (no ad-hoc Sound instances)

Components & responsibilities​

  • CannonServer (server authority).
    • Discovery: on startup + CollectionService:GetInstanceAddedSignal(CANNON_TAG), registers each placed cannon Model in PlacedObjects; one Janitor per cannon, cleaned on removal.
    • Mount: ReqMountCannon(cannonModel) → validate proximity to the cannon + not already occupied → record occupant. ReqMountCannon(nil)/dismount/death/disconnect clears it.
    • Fire: ReqFireCannon(origin, direction) → validate requester is the occupant, cooldown elapsed, not overheated, direction finite & unit → spawn an authoritative arc shell via a FastCast2 caster (Acceleration = Gravity) from the cannon's own muzzle CFrame → on impact damage = CannonConfig.Damage * (1 + partyBonus) where partyBonus = ReplicatedStorage.PartyPerkBuffs:GetAttribute("CannonDamageBonus") or 0 → CombatService.ApplyAOE(impact, AOERadius, damage, "AOE", occupant, {}) (tag-aware seam for EnemyShip left as a stub) → broadcast CannonFired + ExplosionAt.
    • Heat: per-cannon heat accumulates HeatPerShot per shot and decays HeatDecayPerSec; reaching MaxHeat sets a lock for OverheatLockTime. Heat (0–1) and Overheated (bool) are written as attributes on the cannon Model (replicate automatically; no extra packet).
    • Per-cannon cooldown/heat stored server-side; client aim is never trusted for damage.
  • CannonController (client). ProximityPrompt to mount; on mount, seat/anchor the gunner, switch to an aim camera, and show a trajectory preview (reuse WeaponHandlers/TrajectoryPreview); fire input sends ReqFireCannon(muzzle, aimDir); renders muzzle flash/impact via WeaponEffectsController patterns and SoundManager; snaps the barrel to the shot direction. Dismount restores normal camera. No authoritative state.
  • CannonGuiController (client). Heat bar HUD for the gunner (precedent: TrainShieldGuiController); reads Heat/Overheated attributes via GetAttributeChangedSignal; shows the lockout state + hiss SFX + steam/red-glow FX at overheat.
  • Cannon Damage perk. Consumed entirely at the server damage line above — the Spec 1 dispatcher already publishes PartyPerkBuffs.CannonDamageBonus. Read per shot (live; respec/leave changes apply to the next shell).

Network protocol (new Packets)​

-- Client → Server: mount (cannon model) or dismount (nil).
ReqMountCannon = Packet("ReqMountCannon", Packet.Any :: Instance?):Response(Packet.Boolean8)

-- Client → Server: fire from the manned cannon. Server validates occupancy/cooldown/overheat/origin
-- and runs its own authoritative shell; client aim direction is advisory (sanity-checked).
ReqFireCannon = Packet("ReqFireCannon",
    Packet.Vector3F32,  -- muzzle origin (advisory; server fires from its own muzzle CFrame)
    Packet.Vector3F32   -- aim direction (unit)
):Response(
    Packet.Boolean8,    -- accepted
    Packet.NumberF32     -- cooldown remaining (0 if accepted)
)

-- Server → all Clients: a shell was fired; render shell + muzzle FX and snap the barrel for non-gunners.
CannonFired = Packet("CannonFired",
    Packet.Instance :: Player,  -- gunner
    Packet.Vector3F32,          -- muzzle origin
    Packet.Vector3F32           -- initial velocity (for client shell visual + barrel snap direction)
)
-- Impact reuses the existing ExplosionAt packet. Heat uses model attributes, not a packet.

Data flow​

Place cannon (PlacementSystem → PlacedObjects, tagged Cannon) → CannonServer registers it → mount prompt → ReqMountCannon → server marks occupant → client seats gunner, enters aim mode + trajectory preview → fire → ReqFireCannon(muzzle, dir) → server validates (occupant, cooldown, overheat, direction) → spawns authoritative arc shell from its own muzzle → on impact computes Damage × (1 + CannonDamageBonus) → CombatService.ApplyAOE → updates heat attributes → broadcast CannonFired + ExplosionAt → all clients render; gunner HUD reflects heat. Mid-run perk allocate/respec changes CannonDamageBonus; the next shell reads the new value.

Edge cases & anti-exploit​

  • Server-authoritative fire: occupancy, cooldown, overheat-lock, and shell origin are re-validated server-side; the server fires from its own muzzle CFrame, so the client cannot fire a cannon it doesn't occupy, faster than the cooldown, while overheated, or from a forged position (same posture as WeaponServer).
  • Single occupant per cannon: a second mount request while occupied is rejected; occupant is cleared on dismount, death, or disconnect (Janitor-owned connections, never hand-rolled).
  • Heat is server-owned: the gunner HUD only reads the server-written Heat/Overheated attributes; the client cannot clear its own overheat.
  • Damage read is server-side of the server-written CannonDamageBonus — unforgeable.
  • Party bonus on leave: Spec 1 dispatcher lowers the resolved bonus when the top holder leaves; the next shell reflects it (no cached multiplier).
  • Faction rules inherited: AOE routes through CombatService, so EnemyNPC rigs must be set in a hostile faction for player→NPC damage to apply, exactly like existing NPCs.
  • Missing parts / destroyed cannon: server rejects the fire gracefully if the cannon, muzzle, or seat is missing; client degrades (no preview) rather than erroring; the per-cannon Janitor tears down mount/heat state if the cannon is stashed or destroyed mid-use.

Out of scope (this spec)​

  • The EnemyShip HP/destructible system and enemy waves (a separate combat/enemy spec) — only the tag-aware AOE seam is laid here.
  • Auto-turret targeting AI, ammo/energy economy, multiple cannon types — these extend CannonConfig/CannonServer without touching the perk hook.
  • Any new perk plumbing or persistence (Spec 1). Placeable cost/persistence is whatever the existing placeable flow already provides.
